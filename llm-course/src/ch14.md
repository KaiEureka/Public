本章没有实验（课程环境无法访问 Common Crawl），文中的 WARC 记录只是格式示意。法律部分是概览，不构成法律意见，而且这方面的规则仍在快速变化。

### 14.1 为什么说数据是护城河

模型架构已经高度趋同，而且基本都是公开的（第 7 章）。各家模型之间的差距，很大一部分来自**数据**和**后训练**。Llama 3 的论文也把它相对 Llama 2 的提升，主要归功于数据在质量、多样性和规模上的改进。

**需要多少数据？**

| 模型 | 预训练数据量 |
|---|---|
| Llama 3 | 15T token |
| DeepSeek-V3 | 14.8T token |
| Qwen3 | 约 36T token |

英文平均约 4 个字节对应 1 个 token。按这个比例，15T token 相当于约 60 TB 的**干净**文本，而原始数据要比这多出好几十倍。

### 14.2 数据来源地图

| 类别 | 主要来源 | 特点 |
|---|---|---|
| **网页** | Common Crawl，以及自建爬虫 | 占总 token 数的大头；质量参差不齐，需要大量过滤 |
| **代码** | GitHub、Software Heritage、The Stack | 能提升推理能力；需要处理许可证和重复的仓库 |
| **数学** | 从网页中筛出的数学内容、arXiv | 在网上占比很低，但对能力提升至关重要 |
| **学术论文** | arXiv（LaTeX 源码）、PubMed Central 开放获取部分、peS2o | 质量高；PDF 中的文字很难准确提取 |
| **书籍** | Project Gutenberg 等公版书、购买或获得授权的书籍 | 长篇、连贯；版权风险最高 |
| **百科** | Wikipedia、Wikidata | 小而精 |
| **问答与论坛** | StackExchange、Reddit | 有对话和问答结构 |
| **多语言** | Common Crawl 中的非英文部分、各国语料 | 英文以外的语言，高质量数据相对稀缺 |
| **其他** | 专利、法院判决、政府文件、语音转写 | 长尾，但有独特价值 |
| **授权合作** | 新闻出版机构、Reddit、图片和视频素材库 | 要付费，但能拿到独家或高质量的数据 |
| **合成数据** | 由模型生成 | 第 17 章 |

后训练使用的数据（指令、偏好、强化学习环境）是另一套体系，从第 24 章开始讲。

**一个公开的配比**：Llama 3 的预训练数据中，通用知识约占 50%，数学和推理约 25%，代码约 17%，多语言约 8%（{{fig-ch14-mix}}）。

### 14.3 Common Crawl

#### 它是什么

Common Crawl 是一个非营利组织，从 2008 年起定期抓取整个互联网，并把数据**免费**放在 AWS 的公开数据集上。它累计已经抓取了超过 2,500 亿个网页，每次抓取（称为一个**快照**）有数十亿个网页。

#### 三种文件格式

| 格式 | 内容 | 用途 |
|---|---|---|
| **WARC** | 原始的 HTTP 响应，包括完整的 HTML | 自己提取正文时用这个 |
| WAT | 元数据（JSON 格式），包括 HTTP 头和页面中的链接 | 分析网页之间的链接关系 |
| WET | Common Crawl 自己提取好的纯文本 | 拿来就能用，但提取得很粗糙 |

<figure id="fig-ch14-formats" data-svg="ch14_formats.svg">
<figcaption>Common Crawl 的三种文件与正文提取</figcaption>
</figure>

一条 WARC 记录大致是这样的（格式示意）：

```
WARC/1.0
WARC-Type: response
WARC-Date: 2024-08-03T12:34:56Z
WARC-Target-URI: https://example.com/some-article
Content-Length: 48213

HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8

<!DOCTYPE html><html><head><title>…</title>
… 导航栏、广告、Cookie 提示、正文、相关推荐、评论区、页脚 …
```

FineWeb 的实验发现，**从 WARC 中用更好的工具自己提取正文，比直接使用 WET 文件效果更好**（他们用的是 trafilatura，见{{fig-ch14-formats}}）。正文提取是第 15 章流水线的第一步。

Common Crawl 还提供了**索引**，包括按网址检索的 CDX 索引，以及按列存储的 Parquet 索引，可以按网址、域名、语言、文件类型筛选，只下载需要的那部分记录。

#### 局限

- **覆盖有偏差**：它沿着链接去抓取，遵守网站的 robots.txt，对每个网站只抓有限的深度，超过 1 MiB 的页面会被截断。
- **噪声很多**：模板化的页面结构、垃圾内容、为搜索引擎优化而堆砌的页面、大量重复、成人内容，以及越来越多的机器生成文本。
- **真正能用的比例很低**：以 DCLM 为例，原始数据池约 240T token，经过过滤之后得到的 baseline 数据集约 4T token，**只保留了不到 2%**。

#### 基于 Common Crawl 的公开数据集

| 数据集 | 年份 | 规模 | 特点 |
|---|---|---|---|
| C4 | 2019 | 约 156B token | 只用一个快照，靠启发式规则过滤（T5 使用） |
| The Pile | 2020 | 825 GB | 22 个来源混合，网页只是其中一部分 |
| RefinedWeb | 2023 | 5T token | **证明了只用网页数据，只要过滤和去重做得好，效果就能比肩精心挑选的混合数据** |
| RedPajama-V2 | 2023 | 30T token | 附带各种质量信号，由使用者自己决定怎样过滤 |
| Dolma | 2024 | 3T token | OLMo 使用 |
| **FineWeb** | 2024 | 15T token | 来自 96 个快照，每个处理步骤都做了消融实验 |
| FineWeb-Edu | 2024 | 1.3T token | 用"教育价值"分类器筛选（第 16 章） |
| DCLM-Baseline | 2024 | 约 4T token | 用质量分类器筛选，并提供了一套标准的数据对比框架 |
| Nemotron-CC | 2024 | 6.3T token | 结合多个分类器，并用合成数据改写 |

### 14.4 代码

- **来源**：GitHub 上的公开仓库，以及 Issues、PR、提交记录、Jupyter Notebook、Kaggle 等。
- **The Stack v1**（2022）只收录宽松许可证下的代码，共 6.4 TB，涵盖 358 种编程语言，代码作者可以申请退出。**The Stack v2**（2024）以 Software Heritage 的存档为基础，涵盖 619 种语言，训练集约 900B token。
- **为什么代码很重要**：除了让模型会写代码，还有研究（Aryabumi 等，2024）发现，**代码数据能提升模型在非代码任务上的推理能力**。
- **代码特有的处理步骤**：识别许可证；去重（大量 fork 出来的仓库几乎完全相同）；去掉自动生成的文件和压缩过的代码；清除代码里的密钥和个人信息；按仓库组织，把同一个仓库的文件按依赖关系拼接起来，让模型能学到跨文件的上下文，DeepSeek-Coder 就是这样做的。

### 14.5 数学和科学

- **数学网页在网上很少**，而且网页上的公式通常是用 MathJax 渲染的，普通的正文提取工具会把公式弄丢。**OpenWebMath**（14.7B token）专门开发了能保留 LaTeX 公式的提取方法。
- **DeepSeekMath 的做法**：以 OpenWebMath 作为种子，训练一个 **fastText** 分类器（一种非常快的线性文本分类器），用它从 Common Crawl 中召回数学网页；然后用召回的结果继续训练分类器，再召回，反复迭代，最终得到 **120B token 的数学语料**。这是 DeepSeek 数学能力很强的关键原因之一。
- **论文**：用 arXiv 的 LaTeX 源码比用 PDF 好得多。此外还有 PubMed Central 的开放获取论文。
- **PDF 是一个巨大但尚未被充分利用的数据来源**，瓶颈在于怎样准确地提取内容。现在有一批专门的工具，如 Nougat、GROBID、olmOCR、MinerU 等，它们用 OCR 和版面分析模型来还原文字、公式和表格。

### 14.6 书籍

- **公版书**：Project Gutenberg 收录了约 7.5 万本；Internet Archive 和各国图书馆也有大量公版扫描件。哈佛大学在 2025 年发布了 Institutional Books 数据集，约百万册公版书，两千多亿 token。
- **Books3 风波**：Books3 是一个约 19.6 万本书的数据集，来自盗版网站，曾被收录进 The Pile，后来引发了一系列诉讼。
- **Anthropic 的案子（2025）**：法院认为，用**合法购买**的书训练模型属于合理使用，但获取和保存盗版书不属于。随后 Anthropic 以 15 亿美元和解。这个案子之后，"购买实体书并扫描"成了一条合规的路径。

### 14.7 对话、论坛和问答

- **StackExchange**：定期公开数据转储，采用 CC BY-SA 许可证，要求署名。
- **Reddit**：2023 年收紧了 API，之后与 Google（据报道每年约 6,000 万美元）和 OpenAI 签了数据授权协议。
- 这类数据的价值在于自然的问答和对话结构，以及大量的多轮讨论。

### 14.8 多语言

- Common Crawl 中，英文大约占四成多，其他语言依次减少。
- 对很多语言来说，高质量的数据本来就很少。FineWeb-2（2024）覆盖了 1,000 多种语言。
- **中文**：Common Crawl 中中文所占的比例和质量都有限。国内团队通常会把自建爬虫、书籍、百科、论坛、学术文献等多种来源结合起来使用。
- 回顾第 5 章：分词器的训练数据必须与多语言的数据配比一致。

### 14.9 自建爬虫

#### 架构

一个大规模爬虫的工作循环是（{{fig-ch14-crawler}}）：

1. 种子网址进入**待抓取队列**，队列按网站的质量、语言、更新频率等设置优先级；
2. 调度器按**礼貌规则**取出网址：对同一个网站限制并发数和访问频率，并查询 DNS 缓存和 **robots.txt 缓存**（记录每个网站允许和禁止抓取的范围）；
3. 大量异步下载器抓取页面，原始响应存成 WARC；
4. 解析页面中的新链接，经过网址规范化和去重后放回队列，同时对页面内容做哈希去重。

<figure id="fig-ch14-crawler" data-svg="ch14_crawler.svg">
<figcaption>大规模爬虫的架构</figcaption>
</figure>

此外还要处理几件事：**陷阱识别**，避免陷入无限翻页的日历、动态生成的无穷网址等；**JavaScript 渲染**，有些页面要执行 JavaScript 才能看到内容，需要用无头浏览器来渲染，成本很高，只对必要的页面这样做；**重新抓取策略**，已经抓过的页面隔多久再抓一次。

开源的爬虫有 Apache Nutch、Heritrix（Internet Archive 使用）等。抓取数十亿个网页，需要成千上万个并发下载器，存储量达到 PB 级别。

#### 必须遵守的规则

- **robots.txt**：2022 年已成为正式标准（RFC 9309）。网站用它声明哪些爬虫可以抓取哪些内容。
- **表明身份**：爬虫要使用可识别的 User-Agent（用来标识访问者身份的字符串），并提供联系方式。常见的 AI 相关爬虫标识有 GPTBot（OpenAI）、ClaudeBot（Anthropic）、CCBot（Common Crawl）、Meta-ExternalAgent 等。Google-Extended 不是爬虫，而是一个专门的标识：网站可以通过它声明不允许自己的内容被用于训练 Gemini。
- **控制访问频率**：不能把别人的网站压垮。
- **不要做的事**：绕过付费墙或登录限制，无视 robots.txt，专门抓取个人信息。这些既有法律风险，也违背行业规范。

#### 趋势

Data Provenance Initiative 的研究《Consent in Crisis》（2024）发现，2023 到 2024 年短短一年里，禁止 AI 爬虫抓取的网站迅速增加：C4 中约 5% 的 token，以及来自最关键那批网站的约 25% 的 token，都变成了受限内容。**可以自由获取的高质量网页正在减少。**

### 14.10 法律与合规

以下是概览，各司法辖区不同，而且仍在变化：

| 地区或议题 | 现状 |
|---|---|
| **美国** | 争议的核心是"合理使用"（fair use）。重要案件包括：纽约时报诉 OpenAI 和微软（仍在审理）；Anthropic 案（合法购买的书籍属于合理使用，盗版不属于，最终以 15 亿美元和解）；Kadrey 诉 Meta（2025 年判 Meta 胜诉，但法官提出了"市场稀释"这一可能的侵权理由）；Thomson Reuters 诉 Ross（2025 年，一款与原告直接竞争的非生成式产品被判不构成合理使用） |
| **欧盟** | 《数字单一市场版权指令》允许"文本与数据挖掘"，但版权方可以用机器可读的方式声明保留权利、选择退出。《AI 法案》从 2025 年 8 月起，要求通用模型的提供者公布训练数据的摘要，并制定尊重版权方退出声明的版权政策 |
| **日本** | 著作权法第 30 条之 4 对数据分析用途给予了较宽的例外 |
| **中国** | 《生成式人工智能服务管理暂行办法》（2023）要求使用具有合法来源的数据和基础模型，不得侵害知识产权；涉及个人信息的，需要取得个人同意，或者符合法律规定的其他情形 |
| **隐私** | GDPR 等法规适用于网页中出现的个人信息，所以要清除个人信息（第 15 章） |
| **许可证** | 代码的开源许可证（比如 GPL 的义务是否延伸到训练出的模型，仍有争议）；CC BY-SA 要求署名；数据集本身也有许可证，比如 FineWeb 用的是 ODC-By |

**常见的合规做法**：记录每份数据的来源；给数据打上许可证标签；遵守退出声明；请法务审核；编写数据卡片，公开说明数据的组成。

### 14.11 数据团队

| 角色 | 职责 |
|---|---|
| 爬虫工程师 | 自建爬虫，维护数据的抓取和更新 |
| 数据流水线工程师 | 在分布式 CPU 集群上处理数据，常用工具有 Spark、Ray 和 HuggingFace 的 DataTrove |
| 数据科学家或研究员 | 训练质量分类器，确定数据配比，做数据消融实验 |
| 法务与政策 | 授权谈判，合规审核 |
| 标注运营 | 主要服务于后训练数据 |

**基础设施**：对象存储，配合 Parquet 或 JSONL 文件格式，并做好数据的版本管理；成千上万个 CPU 核心用于数据处理（数据处理主要靠 CPU，不靠 GPU）；分词流水线，把清洗好的文本转成二进制的 token 文件（第 5 章）。

**数据消融实验**：比较不同的数据处理方案时，用小模型去训练。比如 FineWeb 用 1.8B 参数的模型、训练约 28B token；DCLM 提供了一套标准化的对比框架。第 15、16 章会反复用到这种方法。

::: keypoints
1. 架构已经趋同，数据是各家模型差距的主要来源。前沿模型的预训练数据在 15T 到 36T token 之间。
2. 网页数据（Common Crawl）是数据量的大头。要从 WARC 中自己提取正文，最终只有不到 2% 能留下来。基于 Common Crawl 的公开数据集，已经从 C4 演进到 FineWeb 和 DCLM。
3. 代码、数学、论文和书籍是能力提升的关键，各有特殊的处理方法：代码要处理许可证和 fork；数学要保留公式，并用分类器从网页中召回；论文要攻克 PDF 提取。
4. 自建爬虫要遵守 robots.txt、表明身份、控制访问频率。越来越多的网站禁止 AI 爬虫，可以自由获取的数据在减少。
5. 版权和合规规则因地区而异，而且还在变化。要做好来源记录、许可证标签和退出声明的处理，并请法务审核。
:::

2. **思考**：FineWeb 为什么要从 WARC 文件中自己提取正文，而不是直接用 WET？
3. **思考**：为什么代码数据可能提升模型在非代码任务上的推理能力？提出两个假设。
4. **动手**：写一份 robots.txt，禁止 GPTBot 和 ClaudeBot 抓取，允许其他所有爬虫访问。
5. **设计**：为数据团队设计一个"数据目录"，记录每份数据的信息。列出至少 8 个字段，比如来源、许可证、抓取日期……
6. **思考**：随着越来越多的网站禁止 AI 爬虫，未来抓取到的数据分布会发生怎样的偏移？会给模型带来什么偏差？
:::
