## 附录 D　部分习题参考答案 {#appD .chapter}

计算题给出数值和关键步骤；推导题给出要点；设计题和开放题没有唯一答案，只列出要点，供对照。第 39 章的 20 道闭卷题，答案都在题后括号注明的章节里，这里不再重复。

### 第 0 章

**1.** $6\times7\times10^9\times2\times10^{12} = 8.4\times10^{22}$ FLOP。$8.4\times10^{22}\div(1024\times4\times10^{14})\approx2.05\times10^5$ 秒，约 2.4 天。Llama 2 7B：$8.4\times10^{22}\div(1.843\times10^5\times3600\ \text{秒})\approx127$ TFLOP/s，MFU $\approx127/312\approx41\%$。

**2.** 每个矩阵乘法 $Y = XW$，反向要算 $dX = dY\,W^\top$ 和 $dW = X^\top dY$ 两个同样大小的乘法，所以是前向的 2 倍。做激活重计算时：前向 1 份 + 重算 1 份 + 反向 2 份 = 4 份，约 $8ND$，比 $6ND$ 多 33%。

**3.** $70\times10^9\times16$ 字节 $= 1.12$ TB；$1120/80 = 14$ 张。

**4.** 每张卡读 $140/8 = 17.5$ GB，$17.5\ \text{GB}\div3.35\ \text{TB/s}\approx5.2$ ms，约 190 token/s。

**5.** (a) 预训练研究与 Infra（值班人员处理，研究负责人决定是否回退）；(b) 数据团队与评测团队（去污染）；(c) 推理团队；(d) 数据团队与预训练研究（用消融实验决定）；(e) 基础设施团队；(f) 后训练团队与评测与安全团队。

### 第 1 章

**1.** $\ln128{,}256\approx11.76$。初始 loss 为 25 说明模型一开始就对错误答案很自信，最可能是输出层（logits）的初始尺度太大。第 3 章实验 3 中，输出层标准差为 1 时初始 loss 达到 40.975。

**2.** $\ell = -z_y + \log\sum_j e^{z_j}$，所以 $\partial\ell/\partial z_i = -[i = y] + e^{z_i}/\sum_j e^{z_j}$，即 $\operatorname{softmax}(z) - \operatorname{onehot}(y)$。

**3.** A：$2.0/4 = 0.5$ nats/字节，即 $0.5/\ln2\approx0.72$ 比特/字节；B：$0.9/\ln2\approx1.30$ 比特/字节。A 更强。

**4.** 每个十六进制数字有 16 种等可能的取值，熵为 4 比特，即 $\ln16\approx2.77$ nats/字符。$H(p)$ 是数据本身的随机性，也就是不可约损失，再强的模型也降不下去。

**5.** 上下文太稀疏：验证集中约 10% 的位置的 5 字符上下文在训练集里从未出现，只能靠平滑去猜。数据增加 100 倍后，每种上下文出现的次数变多，最优的 $n$ 会变大，但只会大一点点，因为上下文的种类随 $n$ 指数增长。

**6.** 基座模型只学过续写文档，而网上"一连串问题"的文档（试卷、问卷、练习册）很常见，所以续写出更多问题的概率很高。要让它回答问题，需要后训练（第 24 章）。

**7.** $P(X_2 = \text{睡}) = 0.5 + 0.2 = 0.7$；$P(X_1 = \text{狗}\mid X_2 = \text{睡}) = 0.2/0.7\approx0.286$。任何方向的条件概率都由同一个联合分布决定。模型只学从左往右，是因为这样分解后，每个因子都可以用"预测下一个 token"来训练，生成时也正好按这个顺序逐个采样。

**8.** 1.6 节把整份语料当作一个长字符串，没有"文档"和 ⟨eos⟩。可以这样形式化：随机试验是"在训练文本中均匀随机地取一个位置 $t$，看这个位置的字符和下一个字符"；样本空间是位置的集合，或者说相邻字符对 $(x_t, x_{t+1})$ 的集合；$p$ 是由此得到的相邻字符对的分布，bigram 要学的是其中的条件分布 $p(x_{t+1}\mid x_t)$。更严格地，可以把语料看作一个平稳随机过程的一次实现，bigram 估计的是它的一步转移概率。

### 第 2 章

**1.** 设 $u = ab + c = 1$，$L = u^2 = 1$，$\partial L/\partial u = 2u = 2$。所以 $\partial L/\partial a = 2b = 4$，$\partial L/\partial b = 2a = 2$，$\partial L/\partial c = 2$。

**2.** $b_1$ 被加到 batch 中每一个样本上，每个样本都是一条从 $b_1$ 到 loss 的路径；多条路径的梯度相加，所以 $db_1 = \sum_{\text{batch}} da$。

**3.** 本章的 $b_1$ 初始为 0。$W_1 = 0$ 时隐藏层输出 $h = \tanh(0) = 0$，所以 $dW_2 = h^\top d\text{logits} = 0$；$W_2 = 0$ 时 $dh = d\text{logits}\,W_2^\top = 0$，于是 $W_1$、$b_1$ 和 embedding 都收不到梯度。只有 $b_2$ 在学习，模型退化成 unigram，loss 停在约 3.35（第 1 章的 unigram 为 3.347）。

**4.** $E$：1,040；$W_1$ 与 $b_1$：$(32\times16)\times512 + 512 = 262{,}656$；$W_2$ 与 $b_2$：33,345。合计 297,041。增长全部来自 $W_1$，它的输入维度 $16K$ 随 $K$ 变大。

**5.** 去掉 tanh 后，两个线性层的复合仍然是线性的：每个位置的字符各自给下一个字符的 logits 加一份分数，彼此之间没有相互作用（对数线性模型）。它可以用到比 bigram 更远的字符，但无法表示"th 后面常跟 e"这类组合规律，很难达到 5-gram 计数（1.770）的水平，更比不上带 tanh 的 MLP。

**6.** 反向模式一次能得到一个输出对所有输入的偏导数；前向模式一次只能得到所有输出对一个输入的偏导数。训练时输出只有 1 个（loss），参数有几百万个，所以用反向模式。10 个输出、100 万个输入时，反向模式只需算 10 遍，前向模式要算 100 万遍，反向更划算。

### 第 3 章

**1.** $\sqrt{2/4096}\approx0.0221$，与 GPT-2 的 0.02 几乎一样。

**2.** 3.358 与 unigram 的 3.347 几乎相等。std = 1 时 85% 的隐藏单元饱和，梯度在层间被放大约 3,000 万倍，网络无法利用输入，只通过偏置学到了每个字符的出现频率。

**3.** 第 1 步：$m_1 = (1-\beta_1)g$，$v_1 = (1-\beta_2)g^2$；偏差修正后 $\hat m = g$，$\hat v = g^2$，更新量 $\eta\,g/(\lvert g\rvert + \epsilon)\approx\eta\operatorname{sign}(g)$。$g = 10^{-12}$ 时，更新量约为 $\eta\cdot10^{-12}/10^{-8} = 10^{-4}\eta$，几乎不动。这是合理的：这么小的梯度基本是噪声，$\epsilon$ 防止把它放大成满步长的更新。

**4.** $2^{21}/(32\times2048) = 32$ 次。

**5.** Pre-norm：$h_{l+1} = h_l + f_l(\operatorname{norm}(h_l))$，所以 $\partial h_{l+1}/\partial h_l = I + J_l$，$\partial h_L/\partial h_0 = \prod_l(I + J_l) = I + \sum_l J_l + \cdots$，展开式中总有 $I$，梯度有一条不经过任何层的直通路径。Post-norm：$h_{l+1} = \operatorname{norm}(h_l + f_l(h_l))$，每一层都要再乘上归一化的雅可比矩阵，直通路径被打断，没有这个保证。

**6.** L2 正则的梯度 $\lambda w$ 和普通梯度一起被 Adam 除以 $\sqrt{\hat v}$；梯度大的参数 $\sqrt{\hat v}$ 大，衰减项被除得更小，所以衰减得更少。AdamW 把衰减从梯度中拿出来，直接做 $w\leftarrow w - \eta\lambda w$，所有参数按同样的比例衰减。

### 第 4 章

**1.** 读写各约 67 MB，共 134 MB，$\div3.35$ TB/s $\approx40\ \mu$s。矩阵乘法 $2\times8192\times4096\times4096\approx2.75\times10^{11}$ FLOP，$\div989$ TFLOP/s $\approx278\ \mu$s。前者约为后者的 14%。

**2.** 算术强度 $= 2B\cdot8192^2/[2(2\cdot8192B + 8192^2)] = 8192B/(2B + 8192)$；令它等于 295，得 $B\approx318$。

**3.** 单条序列约 190 token/s。batch 为 64 时仍然受限于读取权重，每步的时间几乎不变，总吞吐量约 $64\times190\approx1.2$ 万 token/s。

**4.** 每步 $6\times7\times10^9\times4\times10^6 = 1.68\times10^{17}$ FLOP，$\div12$ 秒 $= 1.4\times10^{16}$ FLOP/s；峰值 $64\times989\times10^{12}\approx6.33\times10^{16}$ FLOP/s，MFU 约 22%，偏低。

**5.** 一次只处理一个 token 时，每读一个权重只做 2 次运算，算术强度约为 1，远低于平衡点 295，GPU 几乎一直在等数据。

**6.** 受限于算力的工作（大 batch 的矩阵乘法、训练、prefill）提速最多，接近 3.2 倍；受限于带宽的工作（小 batch 的 decode、逐元素运算）提速最少，约 1.7 倍。

### 第 5 章

**1.** 初始相邻对的频数：ug 20、pu 17、un 16、hu 15……第 1 次合并 u + g → ug；之后 un（16）最多，第 2 次合并 u + n → un；之后 h + ug（15）最多，第 3 次合并 → hug。最终各词切成：hug、p ug、p un、b un、hug s。

**2.** $2\times128{,}256\times8192\approx2.10\times10^9$，约占 70B 的 3%。小模型的主体参数少，词表部分占比大（8B 时为 13%），所以对词表大小更敏感。

**3.** uint16 最大能表示 65,535。GPT-2 的词表 50,257 存得下，Llama 3 的 128,256 存不下，要用 32 位整数。

**4.** 例如单词与后面的标点或空格粘在一起的组合（`the,`、`the.`），以及跨越单词边界的片段（如 `d the`）。同一个词因为前后的字符不同，会占用多个名额。

**5.** 每个汉字约 2.97 个 token 对 1.16 个 token，费用约为 2.6 倍；同样的上下文窗口只能装下约 40% 的中文内容。

**6.** 模型看到的是 token（如 `straw`、`berry`），不是字母，必须记住每个 token 的拼写才能数字母。改进：在训练数据中加入拼写类任务；让模型先把单词逐个字母拼出来再数（思维链），或者调用代码工具。

### 第 6 章

**1.** 分数 $q\cdot k_j/\sqrt2$ 依次为 0、0.707、0.707，softmax 权重为 0.198、0.401、0.401；输出 $= 0.198\times[10, 0] + 0.401\times[0, 10] + 0.401\times[5, 5]\approx[3.98, 6.02]$。

**2.** $q\cdot k = \sum_i q_ik_i$；每一项的均值为 0，方差为 $E[q_i^2]E[k_i^2] = 1$，各项相互独立，所以总方差为 $d_h$。

**3.** 训练 loss 会非常低，因为每个位置都能直接看到答案（下一个 token）。但生成时后面的 token 还不存在，模型从没学过只看前文做预测，输出会是乱码。

**4.** 第一层不变：注意力只是对前文做加权平均，权重只由内容决定，与顺序无关。更深的层可以：因果掩码让第 $i$ 个位置只看到前 $i$ 个 token，打乱之后其他位置看到的集合变了，它们的输出也会变，最后一个位置在后面的层里读取这些表示，就可能间接感知到顺序。

**5.** $12Ld^2 = 12\times24\times1024^2\approx302$M；词嵌入 $50{,}257\times1024\approx51.5$M；位置嵌入 $1024\times1024\approx1.0$M。合计约 355M，与公布的数字一致。

**6.** $4Td > 24d^2\iff T > 6d$。$d = 4096$、$T = 8192$ 时，占比 $= T/(T + 6d) = 8192/(8192 + 24{,}576) = 25\%$。

### 第 7 章

**1.** 每层：$W_q$ 和 $W_o$ 各 $8192^2\approx67.1$M；$W_k$ 和 $W_v$ 各 $8192\times1024\approx8.4$M；MLP $3\times8192\times28{,}672\approx704.6$M；合计约 855.6M，乘以 80 层约 68.45B。嵌入加输出层 $2\times128{,}256\times8192\approx2.10$B。总计约 70.55B。

**2.** GQA：$2\times80\times8\times128\times2$ 字节 $= 320$ KB/token。MHA（64 个 KV 头）是它的 8 倍，2,560 KB（约 2.5 MB）。

**3.** $\big(R(m\theta)q\big)^\top R(n\theta)k = q^\top R(m\theta)^\top R(n\theta)k = q^\top R\big((n-m)\theta\big)k$，因为二维旋转矩阵满足 $R(a)^\top = R(-a)$，$R(a)R(b) = R(a+b)$。

**4.** 位置信息只需要进入注意力分数 $q\cdot k$。$v$ 是被取走的内容，旋转它会让输出随绝对位置变化，破坏"只依赖相对位置"的性质。

**5.** GELU 版有两个矩阵，$2\times d\times4d = 8d^2$；SwiGLU 有三个，$3\times d\times h = 8d^2$，所以 $h = \frac83 d$。$d = 4096$ 时为 10,923，取 256 的倍数为 11,008。

**6.** 训练时计算量主要在大的矩阵乘法上，K、V 投影只占很小一部分，减少 KV 头几乎不省算力。推理时 decode 受限于读取 KV cache，KV 头减少 8 倍，cache 就小 8 倍，可以放下更大的 batch 和更长的上下文。GQA 保留了几组不同的 K/V，表达能力比所有头共用一组的 MQA 强。

### 第 8 章

**1.** 每个专家 $3\times4096\times14{,}336\approx176.2$M；每层 8 个专家 1.409B，加上注意力 41.9M 和路由器约 3.3 万，约 1.451B；32 层约 46.44B，加上嵌入和输出层 $2\times32{,}000\times4096\approx0.262$B，总参数约 46.70B。激活参数：每层 2 个专家 352.3M 加注意力 41.9M，约 394.3M，32 层约 12.62B，再加 0.262B，约 12.88B。与官方的 46.7B 和 12.9B 吻合。

**2.** 完全均匀时 $f_i = P_i = 1/E$，$E\sum_i(1/E)(1/E) = 1$；全部分给专家 1 时 $f_1 = P_1 = 1$，其余为 0，结果为 $E$。

**3.** $\binom{64}{8} = 4{,}426{,}165{,}368\approx44$ 亿。

**4.** 偏置只负责让负载均衡，不应该改变专家输出的权重。如果加进门控权重，就等于为了均衡去扭曲模型的输出，又回到了辅助损失干扰主目标的老问题；而且偏置会随负载频繁调整，模型的输出也会跟着抖动。

**5.** batch = 1 时，每个 token 只读取被选中的几个专家，读取的权重少；batch 很大时，所有 token 合起来几乎会选中每一个专家，每一步都要读取全部专家。所以 MoE 要在大规模部署中用专家并行把专家分散到很多卡上，才能既有大 batch，又不被显存带宽卡住。

**6.** 算力受限时，MoE 每个 token 的计算只取决于激活参数，同样的算力能换来更强的模型。显存受限时，MoE 的全部参数都要放进显存，同样的显存能放下的激活参数反而更少。

### 第 9 章

**1.** $T/(T + 6d) = 32{,}768/(32{,}768 + 49{,}152) = 40\%$。

**2.** 每个 token $61\times576\times2 = 70{,}272$ 字节，128K token 约 9.2 GB。MHA：每个 token $2\times128\times128\times61\times2$ 字节，约 4.0 MB，128K token 约 524 GB。

**3.** 理论上每层能再往前看 $W$ 个位置，$32\times4096 = 131{,}072$。但信息每经过一层都要被压缩、与其他信息混合，远处的信息衰减得很快，实际有效的距离短得多。

**4.** 第 $i$ 对维度（$i = 0, \dots, 63$）的波长为 $2\pi\cdot10000^{2i/128}$。令它大于 4096，得 $i > 45.0$，即第 46 到 63 对，共 18 对；第 45 对的波长约 4,080，与训练长度相当，算作临界，所以约 19 对。这些维度在训练中连一个完整的周期都没转完，模型只见过它们的一部分角度；外推到更长的位置时，会出现从未见过的角度。

**5.** 不加 RoPE 时，$q^\top k = (W_{UQ}c_q)^\top(W_{UK}c_{kv}) = (W_{UK}^\top W_{UQ}c_q)^\top c_{kv}$，可以把 $W_{UK}$ 并入 query 一侧，直接与缓存的潜在向量 $c_{kv}$ 做点积。加入 RoPE 后变成 $c_q^\top W_{UQ}^\top R_{n-m}W_{UK}c_{kv}$，中间夹着随相对位置变化的旋转矩阵，无法预先合并成一个固定的矩阵。所以 DeepSeek 采用解耦 RoPE：另加一小段专门携带位置信息的维度。

**6.** 线性注意力把全部历史压缩进一个固定大小的状态。1,000 个 token 之前的一串随机字符没有规律可以压缩，会被后来的内容覆盖，无法逐字恢复。标准注意力保留了每个位置的 K 和 V，可以精确地找到那个位置。

### 第 10 章

**1.** 在 $C = 6ND$ 的约束下，把 $D = C/(6N)$ 代入，对 $N$ 求导，得到 $\alpha A/N^\alpha = \beta B/D^\beta$。解得 $N_{\text{opt}} = G\,(C/6)^{\beta/(\alpha+\beta)}$，$D_{\text{opt}} = G^{-1}(C/6)^{\alpha/(\alpha+\beta)}$，其中 $G = (\alpha A/\beta B)^{1/(\alpha+\beta)}$。

**2.** $6\times20N^2 = 10^{24}$，$N\approx9.1\times10^{10}$（91B），$D\approx1.83$T。

**3.** $C\approx3.15\times10^{23}$ FLOP；$N = \sqrt{C/120}\approx51$B，$D\approx1.02$T。

**4.** 多花的训练算力约 $5.9\times10^{23}$ FLOP，每生成一个 token 省 $5.2\times10^{10}$ FLOP，盈亏点约 11.4T token。请求量翻 10 倍，推理在总成本中的比重更大，最优的模型应该更小、训练的 token 更多。

**5.** 如果用同一个长调度训练所有模型，再用中途的检查点代表"数据较少"的结果，这些检查点的学习率还没衰减下来，loss 偏高。于是数据的作用被低估，结论偏向"模型应该更大"。

**6.** 在多个规模上（比如 $10^{19}$ 到 $10^{22}$ FLOP）分别训练新架构和基线，各自拟合 scaling 曲线，看两条曲线是否相交、在哪里相交，再到更大的规模上验证。指数更小意味着优势会随规模缩小，到某个计算量之后可能被反超。

### 第 11 章

**1.** 随机加总的变化随宽度按 $\sqrt n$ 增长，同向加总按 $n$ 增长。参数更新与输入是相关的（同向），所以单步输出变化扩大 $4096/256 = 16$ 倍。

**2.** $10^{-2}\times256/4096 = 6.25\times10^{-4}$；输出乘子是宽度 256 时的 $1/16$。

**3.** $B_{\text{opt}} = 0.292\times(3\times10^{23})^{0.327}\approx1.4\times10^7$ token；$\eta_{\text{opt}} = 0.312\times(3\times10^{23})^{-0.125}\approx3.6\times10^{-4}$。

**4.** 设 $x = S/S_{\min}$，$E = BS$，$B_{\text{crit}} = E_{\min}/S_{\min}$。代入 $B = B_{\text{crit}}$，得 $E/E_{\min} = x$，条件变为 $(x-1)^2 = 1$，所以 $x = 2$：$S = 2S_{\min}$，$E = 2E_{\min}$。

**5.** loss 越低，梯度中共同的"信号"越小，样本之间的差异（噪声）相对越大，需要更大的 batch 才能把噪声平均掉，所以梯度噪声尺度随训练变大。

**6.** 学习率大时，参数在河谷两侧的峭壁之间来回振荡，同时沿谷底前进；衰减阶段步长变小，参数落到谷底，loss 骤降。这时模型对数据的拟合最精细，最近看到的数据影响最大，所以在衰减阶段换上高质量数据特别有效。

### 第 12 章

**1.** 1,000 步和 20 步。$\beta_2$ 大时，$v$ 记住的是很久以前的梯度大小；某个参数长时间梯度很小、突然来了一个大梯度时，$v$ 反应不过来，更新量 $m/\sqrt v$ 会非常大，造成尖峰。$\beta_2 = 0.95$ 能很快跟上梯度大小的变化。

### 第 22 章

**1.** 归纳：设处理完前 $j$ 块后，$m_j$ 是已见元素的最大值，$\ell_j = \sum e^{x_i - m_j}$，$o_j = \sum e^{x_i - m_j}v_i$（求和都只针对已见的元素）。加入新的一块时，用 $e^{m_j - m_{j+1}}$ 把旧的 $\ell$ 和 $o$ 重新缩放到新的最大值，再加上新块的贡献，上面的形式仍然成立。全部处理完后，$o/\ell = \sum_i e^{x_i - m}v_i/\sum_i e^{x_i - m} = \operatorname{softmax}(x)V$。

```python
def rmsnorm_kernel(x_ptr, g_ptr, out_ptr, n_cols, eps, BLOCK: tl.constexpr):
    row = tl.program_id(0)
    offs = tl.arange(0, BLOCK)
    mask = offs < n_cols
    x = tl.load(x_ptr + row * n_cols + offs, mask=mask, other=0.0).to(tl.float32)
    g = tl.load(g_ptr + offs, mask=mask, other=0.0).to(tl.float32)
    rms = tl.sqrt(tl.sum(x * x, axis=0) / n_cols + eps)   # one read of the row
    tl.store(out_ptr + row * n_cols + offs, g * x / rms, mask=mask)
```

**6.** 可能的原因：① 数据加载跟不上：查看时间线上每步开始时 CPU 在做什么，或者换成假数据对比；② 每步开始时的通信没有和计算重叠（比如 FSDP 的第一次 all-gather 没有预取）：查看时间线上的 NCCL 内核；③ CPU 端启动内核的开销太大（Python 开销、大量小内核）：用 CUDA Graphs 或 torch.compile 对比，检查 GPU 内核之间的间隙。

### 第 23 章

**1.** 对 $\tau$ 求导：$-c/\tau^2 + \lambda/2 = 0$，$\tau^* = \sqrt{2c/\lambda}$。代回得最优的损失占比为 $\sqrt{2c\lambda} + \lambda R$。

**2.** $\lambda = 2$ 次/小时 $= 1/1800$ 次/秒，$\tau^* = \sqrt{2\times5\times1800}\approx134$ 秒（约 2.2 分钟）；损失 $\sqrt{2\times5/1800} + 300/1800\approx0.075 + 0.167\approx24\%$，大头是重启。大规模训练需要更快的重启（热备节点、存在内存中的检查点）、更少的故障（健康检查、主动剔除），以及弹性训练。

**3.** 模型参数、优化器状态（$m$、$v$、步数）、学习率调度器的状态、每个 rank 的随机数生成器状态、数据读取的位置、训练步数和配置等。漏掉数据读取的位置，恢复后会重复训练已经见过的数据，或者跳过一部分数据，改变数据的分布和配比，而且很难被发现。

**4.** 要点：数据并行的各个副本在同步之后，参数应该逐比特相同。可以每隔几百到上千步，让各副本计算参数的哈希并比较，代价是把参数读一遍（毫秒到秒级）。发现不一致时，找出与多数不同的副本，隔离对应的机器，用金丝雀计算复查，再从上一个一致的检查点恢复。

**5.** 卡死时没有报错，所有 rank 都在等待，看不出是谁、在哪一步出了问题，成千上万个 rank 的日志也很难对齐。通信记录器为每个 rank 记录最近的集合通信调用（操作类型、序号、数据量、状态），卡死时把它们汇总比较，就能找出哪个 rank 没有进入某次调用，或者调用的顺序不一致。

**6.** 要点：① 自动告警，通知值班人员；② 判断是否是孤立的尖峰（几十步内自行恢复的可以继续观察）；③ 检查同一时刻的系统指标（坏卡、网络错误）和数据（这一批是否异常）；④ 不恢复或反复出现：回退到尖峰之前的检查点，跳过这段数据，必要时临时调低学习率；⑤ 值班人员可以决定回退和跳过数据，连续多次出现、或者需要修改超参数时，叫醒研究负责人；⑥ 每一次处理都要记录。

### 第 25 章

**1.** $\partial\mathcal{L}/\partial r_w = -\sigma(r_l - r_w)$。模型已经能很好地区分两个回答时，$r_w - r_l$ 很大，$\sigma(r_l - r_w)\approx0$，几乎没有梯度。

**2.** Bradley-Terry 只依赖 $r_w - r_l$，同一个提示下的两个回答加上同一个 $c(x)$，差值不变。最优策略 $\pi_{\text{ref}}e^{(r + c(x))/\beta} = \pi_{\text{ref}}e^{r/\beta}\cdot e^{c(x)/\beta}$，多出来的因子与 $y$ 无关，归一化时被消掉。

**3.** $\mathbb{E}_\pi[r] - \beta\,\mathrm{KL}(\pi\Vert\pi_{\text{ref}}) = -\beta\,\mathrm{KL}\big(\pi\,\Vert\,\pi_{\text{ref}}e^{r/\beta}/Z\big) + \beta\log Z$，KL 为 0 时取最大，所以 $\pi^* = \pi_{\text{ref}}e^{r/\beta}/Z$。$\beta\to0$ 时集中到奖励最高的回答上；$\beta\to\infty$ 时退回 $\pi_{\text{ref}}$。

**4.** $\mathbb{E}_{y\sim\pi}[b\,\nabla\log\pi(y)] = b\sum_y\pi(y)\nabla\log\pi(y) = b\sum_y\nabla\pi(y) = b\,\nabla\sum_y\pi(y) = b\,\nabla1 = 0$。

**5.** $A = +1$，$\rho = 1.5$：$\min(1.5, 1.2) = 1.2$，取的是被裁剪的项，对 $\theta$ 的梯度为 0。$A = -1$，$\rho = 0.6$：$\min(-0.6, -0.8) = -0.8$，同样取裁剪项，梯度为 0。

**6.** KL $= \log N - (N-1)/N$：$N = 16$ 时约 1.84，$N = 256$ 时约 4.55。KL 只随 $\log N$ 增长；而且 Best-of-N 只在参考模型的样本中挑选，不会产生参考模型采样不到的回答，偏离的程度有限。

### 第 26 章

**1.** 由 $\pi^* = \pi_{\text{ref}}e^{r/\beta}/Z$ 得 $r(x, y) = \beta\log\frac{\pi^*(y\mid x)}{\pi_{\text{ref}}(y\mid x)} + \beta\log Z(x)$。代入 Bradley-Terry 的 $r_w - r_l$ 时，两个回答对应同一个提示，$\beta\log Z(x)$ 相减抵消，只剩下策略的概率比。这一步至关重要：$Z(x)$ 要对所有可能的回答求和，根本算不出来。

**2.** $\nabla\mathcal{L}_{\text{DPO}} = -\beta\,\sigma(\hat r_l - \hat r_w)\big[\nabla\log\pi_\theta(y_w) - \nabla\log\pi_\theta(y_l)\big]$，其中 $\hat r = \beta\log(\pi_\theta/\pi_{\text{ref}})$ 是隐式奖励。系数衡量隐式奖励把这一对排错的程度：排错得越厉害，更新越大；已经排对的，几乎不更新。

**3.** 标签确定时，同一对回答永远是 $y_w$ 胜，Bradley-Terry 的最大似然要求 $\hat r_w - \hat r_l\to\infty$，也就是把落选回答的概率推到 0。$\beta$ 只改变隐式奖励的尺度，不改变"差距要无穷大"这个目标，所以无论 $\beta$ 取多少都会坍缩。IPO 改用平方损失，让差距回归到一个有限的目标值。

**4.** 流向了偏好数据中没有出现的其他回答，包括更长的、风格奇怪的，甚至训练分布之外的文本。风险是生成的质量不可控：可能变得啰嗦、退化，甚至胡言乱语。

**5.** SimPO 没有参考模型，直接用策略的对数概率当奖励。对数概率的总和随长度变化（越长越负），模型学到的会是与长度有关的偏好，而不是与质量有关的偏好；按 token 平均消除了这个影响。

**6.** 要点：每轮对每个提示生成 4 到 8 个回答；用奖励模型或大模型评委打分，并控制长度偏差；取最好与最差的回答构造偏好对，过滤掉分差太小的；防止越写越长：评分时控制长度、限制胜者不能比败者长太多、使用长度归一化的 DPO；内部评测不再提升，或者长度、KL 持续增长时停止迭代。

### 第 27 章

**1.** 均值 0.25，总体标准差 $\sqrt{0.25\times0.75}\approx0.433$。答对的优势约 $+1.73$，答错的约 $-0.58$。奖励全是 1 时，标准差为 0，优势全为 0（实现中分母会加一个小的 $\epsilon$），这一组没有学习信号。

**2.** 每个 token 得到的梯度权重是 $A_i/\lvert o_i\rvert$。答错时 $A_i < 0$，回答越长，每个 token 分到的惩罚越小，所以又长又错的回答受到的惩罚比又短又错的轻，模型会倾向于在答错时写得更长。

**3.** R1-Zero 的奖励只看答案对不对，不管思维链用什么语言、是否可读，模型没有动力保持一致。冷启动 SFT 提供了可读的长思维链格式作为起点；语言一致性奖励直接奖励"思维链使用与提问相同的语言"。

**4.** 小模型自己探索时很难生成正确的长推理，奖励稀疏，学不到东西；大模型的推理数据直接提供了正确的推理过程，相当于把大模型通过强化学习发现的能力教给小模型。DeepSeek 的实验表明，蒸馏的效果明显好于对同样大小的模型直接做强化学习。

**5.** 强化学习把概率集中到了模型原本就能找到的正确路径上，提高了单次作答的成功率，但多样性下降，一些原本偶尔能答对的题现在答不对了。它没有扩展能力的边界，而是挑出并放大了已有的能力。

**6.** 例如：① 隐藏测试，模型看不到用于评分的测试用例；② 测试文件和评测脚本只读，禁止修改；③ 检测钻空子的模式，比如硬编码期望的输出、直接退出返回成功、修改断言；④ 每个任务用多组测试，包括随机生成的输入；⑤ 定期人工审查高奖励的样本和思维链；⑥ 对可疑的行为给负奖励。

调用：`{"name": "send_email", "arguments": {"to": "zhangsan@example.com", "subject": "明天的会议改到 3 点", "body": "张三你好，明天的会议时间改到下午 3 点。"}}`。模型并不知道张三的邮箱，应该先查通讯录或者询问用户。发邮件是对外的、不可撤回的操作，执行前应该让用户确认。

### 第 29 章

**1.** loss 对学生 logits 的梯度是 $(p_s - p_t)/\tau$，其中 $p = \operatorname{softmax}(z/\tau)$。$\tau$ 较大时，$p_s - p_t$ 约与 $(z_s - z_t)/\tau$ 成正比，所以梯度大约按 $1/\tau^2$ 缩小。乘以 $\tau^2$ 后，梯度的大小与 $\tau$ 无关，和硬标签的 loss 混合时，两部分的权重不必随 $\tau$ 重新调整。

**2.** 完整分布：$10^{12}\times128{,}256\times2$ 字节 $\approx256.5$ PB。只存前 64 个：$10^{12}\times64\times6$ 字节 $= 384$ TB。

**3.** 软标签在每个训练位置提供了一整个分布的信息，等于用更少的数据学到同样多的东西。$M$ 增大后，硬标签的样本也足以把分布估计准确，软标签多出来的信息就不那么重要了。

**4.** 前向 KL 让学生覆盖教师所有的模式，小模型容量不够时，会把概率分到模式之间、教师认为不可能的区域，生成长文本时容易出现不连贯的内容。反向 KL 让学生只抓住少数几个模式，质量高但多样性差，可能反复生成相似的内容，漏掉一些合理的回答。

**5.** 在线蒸馏中，教师对学生生成的每一个 token 都给出分布，信号稠密，但学生最多学到教师的水平；GRPO 只在回答结束时有一个奖励，信号稀疏，但不需要教师，有可能超越现有的能力。在线蒸馏适合有更强的教师、要让小模型接近教师的场景；GRPO 适合有可验证的奖励、要突破现有能力的场景。

**6.** $3\times10^9\times2$ 比特 $= 6\times10^9$ 比特 $= 750$ MB。设计：让模型专注于理解和推理，事实性问题通过检索（本地知识库或联网）回答，不依赖参数中的记忆；训练模型在不知道时说不知道；配合量化感知训练。

### 第 30 章

**1.** 标准误差 $\sqrt{0.6\times0.4/198}\approx3.5$ 个百分点，95% 置信区间约 $\pm6.8$ 个百分点（53% 到 67%）。60% 与 64% 的差距在误差范围之内，不能断言后者更好。在同一批题上做成对比较会灵敏一些，但 4 个百分点仍然很可能不显著。

**2.** 从 $n$ 次采样中不放回地抽 $k$ 次，全部抽到错误样本的概率是 $\binom{n-c}{k}/\binom{n}{k}$，所以 $1 - \binom{n-c}{k}/\binom{n}{k}$ 是 pass@$k$ 的无偏估计。直接代入 $1 - (1-\hat p)^k$（$\hat p = c/n$）时，$1 - (1-p)^k$ 是凹函数，由 Jensen 不等式，它的期望低于真实值。

**3.** 两个模型在同一批题上的得分是相关的（难题对两者都难）。成对比较时，题目难度带来的波动相互抵消，只剩下两者真正的差别，方差小得多。

**4.** 要点：用训练截止之后最新一年的 AIME（30 道题），再加前几年的题作为参照；每题采样 16 到 64 次，报告平均正确率（pass@1）和多数投票的结果；最大生成长度要足够长（比如 32K 以上）；用固定的规则抽取 `\boxed{}` 中的整数答案；报告置信区间、采样温度等全部设置。

**5.** 评委偏爱长的回答，被选为"更好"的回答往往更长，DPO 训练之后模型会越写越长，但不一定更好。防止：评分时控制长度（比如长度控制的胜率），构造长度相近的偏好对，对长度加惩罚，或者使用长度归一化的 DPO。

**6.** 示例：① 每个检查点都跑的快速评测（代码补全的 pass@1、小规模单元测试题、loss）；② 能力评测（SWE-bench Verified、LiveCodeBench、内部不公开的代码题），每天或每个候选模型运行；③ 产品场景评测（真实任务的回放、人工或大模型评委打分、延迟和成本），每次发布前运行；④ 安全与回归测试（拒绝不当请求、过度拒绝、已知问题的回归），每次发布前运行。

### 第 31 章

**1.** 示例。硬性规则：不生成恶意软件；不泄露系统提示、密钥等敏感信息；不经确认不执行破坏性操作（删除数据、强制推送）。默认行为：附上简要说明；不确定时说明自己的假设；遵循项目已有的代码风格。冲突时的优先级：硬性规则 > 开发者（系统提示）的指令 > 用户的指令 > 默认行为。

**2.** 用两组数据：一组有害请求，测照办率；一组看起来敏感、实际正当的请求，测误拒率。综合指标的示例：在误拒率不超过某个上限的前提下最小化照办率，或者按两类错误的代价加权，比如"10 × 照办率 + 误拒率"。

**3.** 例如：安全训练只用了英文数据，模型对用 base64 编码、小语种或角色扮演包装的有害请求仍然照办。这些输入在预训练中学过，模型能理解，但安全训练没有覆盖到。补救：在安全训练中加入各种编码、语言和包装形式的样本，让安全数据的多样性与预训练相当。

**4.** 激发得不够（没有好的提示、不给工具、不多次采样、不做微调），测出的能力就会低于模型真正具备的能力，导致低估风险，把本应受到更严格管控的模型当作安全的发布出去。

**5.** 上下文越长，能放进去的有害问答示例越多，模型的上下文学习会越来越倾向于模仿这些示例，压过安全训练的效果。防御：用分类器检测并改写提示中大量的对话示例；在安全训练中加入多样本攻击的样本；审查结构异常的超长输入。

**6.** 用户的点赞等即时反馈被当作奖励信号，这是"用户满意度"的代理指标，模型对它过度优化，学会了一味附和（古德哈特定律）。改进：① 发布前专门评测谄媚行为；② 不过度依赖短期的用户反馈作为奖励，与其他信号混合；③ 定性的人工评估要有否决权；④ 灰度发布并密切监控，出现问题能快速回滚。

### 第 32 章

**1.** $1/\sqrt{128}\approx0.088$，$1/\sqrt{8192}\approx0.011$。维度越高，随机方向之间越接近正交，能放下的"几乎正交"的方向就越多，可以远多于维度数，这为叠加提供了空间。

**2.** 如果不限制，模型可以把特征的激活值缩小、同时把解码向量放大同样的倍数，重建结果不变，L1 惩罚却可以任意小，稀疏的约束就失效了。

**3.** 用来解释模型，选 $\lambda = 3\times10^{-2}$：每个 token 只激活约 14 个特征，容易解读，尽管重建差一些。用来监控危险行为，更需要不漏掉信号，应该选重建率更高的设置，或者专门检查目标特征的召回率，并用探针等其他方法互相印证。

**4.** 做干预：沿"真假方向"把激活值往"真"或"假"的一侧推，或者把这个方向上的分量去掉，看模型对陈述真假的判断是否随之改变；再沿随机方向做同样大小的干预作为对照，结果不应改变。

**5.** 对开放权重的模型，任何人都能找到并去掉这个方向，几乎零成本地移除拒绝行为，所以发布时必须假设安全措施可以被移除。对闭源模型，用户无法修改权重；这个发现还可以用于防御，比如监控这个方向上的激活值来检测越狱。

**6.** 只在约 25% 的情况下如实承认，说明思维链常常不能反映真实的决策过程，不能单独作为可靠的安全手段。应该把它作为多层防御中的一层，配合输出过滤、行为评测、探针等可解释性方法、权限控制和人工审查。

### 第 33 章

**1.** $2\times32\times8\times128\times2 = 131{,}072$ 字节，即 128 KB/token；8K 上下文每条序列 1 GB。$80 - 16 = 64$ GB 可用，最多约 64 条，实际还要留出激活值等开销。

**2.** 吞吐量 $= B\div[(W + BK)/\text{BW}] = B\cdot\text{BW}/(W + BK)$，$B\to\infty$ 时趋于 $\text{BW}/K$。batch 很大时瓶颈变成读取 KV cache，最终要优化的是每条序列的 KV cache 大小（GQA、MLA、KV cache 量化）。

**3.** 8 张卡的总带宽约 26.8 TB/s。FP8 权重 70 GB；FP8 的 KV cache 每个 token 160 KB，每条 4K 上下文约 0.66 GB，64 条约 42 GB。每步约 $(70 + 42)\ \text{GB}\div26.8\ \text{TB/s}\approx4.2$ ms，吞吐量约 15,300 token/s。

**4.** 静态 batching 要等整批中最长的请求结束，短的请求结束后它的位置一直空着；输出长度差别很大时，大部分时间 batch 里只有少数几条序列在生成。continuous batching 每一步都可以填入新的请求，GPU 一直满载。

**5.** 省下 $3000/3200\approx94\%$ 的 prefill 计算。TTFT 大幅降低，因为只需处理约 200 个新 token；输入的成本也大幅下降，很多 API 对命中缓存的输入只收一小部分费用。

**6.** 输入 token 在 prefill 阶段并行处理，受限于算力，效率很高；输出 token 在 decode 阶段逐个生成，受限于显存带宽，每生成一个都要把权重和 KV cache 读一遍，成本高得多。输入长、输出短的应用，成本主要花在 prefill 和 KV cache 占用的显存上，前缀缓存和便宜的输入价格最重要。

### 第 34 章

**1.** BF16 约 140 GB；INT4 加每 128 个一组的 FP16 scale：$70\times10^9\times(0.5 + 2/128)$ 字节 $\approx36$ GB。2 张 H100 的总带宽约 6.7 TB/s：BF16 约 48 token/s，而且 140 GB 几乎占满了 160 GB 的显存；INT4 约 186 token/s。

**2.** 要点：输出 $x$ 的概率 = 草稿给出 $x$ 并被接受的概率 + 被拒绝后从残差分布中抽到 $x$ 的概率 $= q(x)\min\big(1, p(x)/q(x)\big) + (1 - \beta)\cdot\frac{\max(0, p(x) - q(x))}{1 - \beta} = \min(p, q) + \max(0, p - q) = p(x)$。其中接受率 $\beta = \sum_x\min\big(p(x), q(x)\big) = 1 - \mathrm{TV}(p, q)$。

**3.** $\gamma = 1$、3、5、$\infty$ 时，每次调用分别产生 1.80、2.95、3.69、5 个 token。每次调用的成本为 $1 + 0.05\gamma$，加速比 $= \big[(1 - 0.8^{\gamma+1})/0.2\big]/(1 + 0.05\gamma)$：$\gamma = 7$ 时 3.08，$\gamma = 8$ 时 3.09，$\gamma = 9$ 时 3.08。所以 $\gamma\approx8$ 最划算，约 3.1 倍。

**4.** batch 很大时，decode 已经接近受限于算力，多验证几个草稿 token 不再是免费的，被拒绝的草稿 token 都是浪费的计算，草稿模型本身也要占用资源。只有 batch 小、GPU 有大量空闲算力时，投机解码才划算。

**5.** 训练的 token 越多，模型把越多的信息压进每个参数，权重的每一位都更重要，量化造成的信息损失伤害更大。这意味着"过度训练小模型"和"激进地量化"两者的收益会部分抵消，需要量化感知训练，或者不要量化得太激进。

**6.** 要点：prefill 和 decode 分开部署。prefill 受限于算力，用较小规模的专家并行（DeepSeek-V3 为 32 张卡一组）；decode 受限于带宽和 all-to-all 通信，用大规模专家并行（DeepSeek-V3 为 320 张卡），每张卡只放少数几个专家，batch 尽量大。用模型自带的 MTP 做投机解码。权重用 FP8；MLA 的 KV cache 已经很小。热门专家多放几份副本。

### 第 35 章

**1.** $1024/14\approx73$，$768/14\approx55$，约 4,015 个块，2×2 合并后约 1,004 个 token。视频每帧 $32\times32 = 1024$ 个块，合并后 256 个；120 帧共 30,720 个 token。

**2.** $\mathcal{L} = -\frac{1}{2N}\sum_i\Big[\log\frac{e^{s_{ii}/\tau}}{\sum_j e^{s_{ij}/\tau}} + \log\frac{e^{s_{ii}/\tau}}{\sum_j e^{s_{ji}/\tau}}\Big]$，$s_{ij}$ 是第 $i$ 张图片与第 $j$ 段文字的余弦相似度。batch 越大，每个正样本要和越多的负样本区分开，任务更难，学到的表示更细致。

**3.** 一开始连接层是随机的，传给语言模型的视觉 token 相当于噪声；如果全部解冻，很大的错误梯度会破坏已经训练好的视觉编码器和语言模型。先只训练连接层，把视觉特征对齐到语言模型的输入空间，再解冻做完整的训练。

**4.** 每秒 $12.5\times8 = 100$ 个 token，10 分钟共 60,000 个。上下文很快会被占满，decode 的步数多、成本高，所以要减少码本的层数、在时间上做更多的压缩，或者分层生成（先生成语义 token，再生成声学 token）。

**5.** 已知 $x_k$ 时，$x_0$ 与 $\varepsilon$ 一一对应：$\hat x_0 = (x_k - \sqrt{1-\bar\alpha_k}\,\hat\varepsilon)/\sqrt{\bar\alpha_k}$。所以预测出噪声，就等于预测出原始数据；两种参数化只是 loss 在不同时间步上的权重不同。

**6.** 引导后的预测为 $\hat\varepsilon_\varnothing + w(\hat\varepsilon_c - \hat\varepsilon_\varnothing)$，$w > 1$ 时大致相当于从 $p(x)\,p(c\mid x)^w$ 中采样，样本会集中到"最符合提示词"的区域，所以多样性下降；$w$ 太大时，外推超出了训练中见过的范围，图片会过饱和、失真。

### 第 36 章

**1.** 计算量 $6\times30\times10^9\times20\times10^{12} = 3.6\times10^{24}$ FLOP，与 DeepSeek-V3 相当，最终预训练约 610 万美元；研究和消融是它的 2 到 5 倍，约 1,200 万到 3,000 万美元；后训练几百万到 1,000 万美元；数据 1,000 万美元以上；人员约 5,000 万美元。各项相加约 0.8 亿到 1.1 亿美元；数据和后训练没有上限，留出余量后约 1 亿到 2 亿美元（示意，不含推理服务和自建集群）。

**5.** 示意算法：按第 33 章的模型，70B、8 张 H100、$B = 256$ 时，满载的输出成本约 0.38 美元/百万 token；平均利用率 60% 时约 0.63 美元；毛利率 50% 要求价格是成本的 2 倍，输出约 1.3 美元/百万 token。输入在 prefill 阶段受限于算力：每个 token 约 $1.4\times10^{11}$ FLOP，8 张卡按 40% MFU 每小时约处理 8,100 万 token，满载成本约 0.25 美元/百万；按同样的利用率和毛利率，输入约 0.8 美元/百万 token。实际定价还要考虑更长的上下文、峰谷波动和竞争。

第 2、3、4、6 题是开放题。

### 第 37 章

**1.** $6\times1.5\times10^9\times30\times10^9 = 2.7\times10^{20}$ FLOP，$\div(2{,}000\times10^{13}\ \text{FLOP/s})$，约 13,500 秒，即 3.75 小时。这个阶段适合跑规模阶梯和各种消融实验，并把整套训练系统搭起来、验证一遍。

**2.** V100：$125\times10^{12}\div6.25\times10^9 = 20{,}000$；H100：$989\times10^{12}\div50\times10^9\approx19{,}780$。两者几乎相同，所以第 20 章"每卡每步要处理多少 token 才能藏住通信"的设计思路，在 2017 年依然适用。

第 3 到 7 题是开放题；第 7 题请与第 39 章的路线图对照。

### 第 38 章

**1.** 不做重新计算时，模型状态约 4.6 GB，激活值约 11.4 GB，加上缓冲区也在 32 GB 以内，放得下。省下约 33% 的额外计算，训练时间从约 6.8 周缩短到约 $6.8\times3/4\approx5.1$ 周。

**2.** 计算：8 个专家（6 个路由专家 + 2 个共享专家），每个 $2\times3\times4096\times1408\approx3.46\times10^7$ FLOP，共约 $2.77\times10^8$ FLOP。通信：最多发往 2 台机器，分发 $2\times4096\times2$ 字节、回收同样多，共约 32.8 KB。比值约 8,450 FLOP/字节，高于 V100 集群的约 6,400，有约 30% 的余量，计算与通信重叠得比较好时可以藏住。

第 3 到 6 题是开放题。
