## 第 27 章　推理模型 {#ch27 .chapter}

::: goals

### 27.1 突破是什么

**o1**（OpenAI，2024 年 9 月）用强化学习训练模型，让它在给出答案之前先写一段很长的思维链。OpenAI 公布了两条规律：**训练时**，强化学习用的计算量越多，效果越好；**推理时**，让模型思考得越久，效果也越好。两条曲线在对数坐标下都呈稳定上升。以 2024 年的 AIME（美国数学邀请赛）为例，o1 单次作答的平均正确率为 74%，取 64 次作答中的多数答案时为 83%。

**DeepSeek-R1**（2025 年 1 月，后来发表在 Nature）**首次公开了完整的方法**。核心发现是：**只要用"答案对不对"作为奖励，做大规模强化学习，长思维链、自我检查、回头修正这些行为就会自发地出现。**

### 27.2 可验证奖励

**RLVR**（reinforcement learning with verifiable rewards，来自可验证奖励的强化学习）这个名称来自 Tulu 3。它的意思是：**不用奖励模型，用程序直接判断答案对不对。**

| 任务 | 怎样验证 |
|---|---|
| 数学 | 从回答中抽取最终答案，比如 `\boxed{}` 里的内容，与标准答案比较。要处理等价的写法，比如 1/2 和 0.5，可以用符号计算库来判断 |
| 代码 | 在隔离的沙箱中运行单元测试 |
| 形式化证明 | 交给 Lean 检查（第 17 章） |
| 指令遵循 | 检查"不超过 100 个字""用 JSON 格式输出"这类可以自动判定的约束 |
| 逻辑谜题 | 用程序生成题目和答案，比如数独 |
| 理科选择题 | 比对选项 |

**它的好处**：奖励几乎不会出错，所以不存在第 25 章那种"奖励模型被钻空子"的问题，可以放心地大规模优化下去。当然，这并不意味着完全不会被钻空子，见 27.7 节。

**格式奖励**：R1-Zero 要求模型把思考过程写在 `<think>…</think>` 里，把答案写在 `<answer>…</answer>` 里，格式正确就额外给一些奖励。

### 27.3 GRPO：去掉 critic 的 PPO

GRPO（group relative policy optimization）出自 DeepSeekMath（Shao 等，2024）。

#### 出发点

第 25 章讲过，PPO 需要一个 critic（价值模型），它和策略模型一样大，既占显存又难训练。而且在推理任务中，每个回答只有一个"对或错"的最终奖励，很难准确估计每一步的价值。

#### 做法：同一道题的一组回答互相比较

对每道题 $q$，用当前策略采样 **$G$ 个回答**，比如 16 个，分别得到奖励 $r_1, \dots, r_G$，然后令

$$
\hat A_i = \frac{r_i - \operatorname{mean}(r_1, \dots, r_G)}{\operatorname{std}(r_1, \dots, r_G)},
$$

第 $i$ 个回答的每个 token 都使用这同一个优势值（{{fig-ch27-grpo}}）。

- **这组回答的平均奖励，就是这道题的基线**（第 25 章）。它相当于用采样的方法估计出了 critic 要预测的那个"期望奖励"，所以不再需要 critic。
- 比平均水平好的回答，概率被推高；比平均水平差的，概率被压低。

<figure id="fig-ch27-grpo" data-svg="ch27_grpo.svg">
<figcaption>GRPO：同一道题的一组回答互相比较（数字对应本章习题 1）</figcaption>
</figure>

#### 目标函数

$$
\mathcal{J} = \frac{1}{G}\sum_{i=1}^{G}\frac{1}{\lvert o_i\rvert}\sum_{t=1}^{\lvert o_i\rvert}\min\Big(\rho_{i,t}\hat A_i,\; \operatorname{clip}(\rho_{i,t}, 1-\epsilon, 1+\epsilon)\,\hat A_i\Big) - \beta\,\mathrm{KL}(\pi_\theta\,\|\,\pi_{\text{ref}}),
$$

其中 $\rho_{i,t}$ 是第 $i$ 个回答第 $t$ 个 token 的重要性比率，裁剪方式与 PPO 相同；$\lvert o_i\rvert$ 是第 $i$ 个回答的长度。KL 用一个无偏、并且永远非负的估计量来计算：$\frac{\pi_{\text{ref}}}{\pi_\theta} - \log\frac{\pi_{\text{ref}}}{\pi_\theta} - 1$。

**R1-Zero 公开的设置**：每道题采样 16 个回答，最大长度 32,768 个 token，学习率约 $3\times10^{-6}$，KL 系数约 0.001。

#### 发现的问题与改进

| 问题 | 原因 | 改进 |
|---|---|---|
| **偏爱又长又错的回答**（Dr. GRPO，Liu 等，2025） | 公式里的 $1/\lvert o_i\rvert$ 是按长度平均。对于错误的回答（优势为负），回答越长，每个 token 分到的惩罚就越少 | 去掉长度归一化，也去掉除以标准差这一步，因为后者会让太容易和太难的题目获得过大的权重 |
| **一组全对或全错，就学不到东西** | 所有 $r_i$ 都相同，优势全部为 0，梯度也是 0 | **动态采样**：把这样的组过滤掉，用新题补足（DAPO）；挑选通过率处于中间的题目作为训练集 |
| **熵塌缩**：策略越来越确定，不再探索 | 裁剪是对称的，低概率的 token 很难被大幅提升 | **Clip-higher**：把裁剪的上限放宽，比如下限 0.2、上限 0.28（DAPO） |
| 回答太长被截断 | 超过最大长度后，回答没有写完，被判为错误，而这个惩罚带有噪声 | 对超长的回答做平滑的惩罚（DAPO） |

**DAPO**（字节跳动与清华，2025）综合使用了上述手段，在 Qwen2.5-32B 的基座模型上，把 2024 年 AIME 的成绩做到了 50 分。

### 27.4 模拟实验：为什么思考会越来越长

::: experiment
**一个高度简化的模型。** 策略只决定"思考几步"（$k$ 取 0 到 30），思考的步数越多，最终答对的概率越高，具体为 $1 - \text{难度}\times0.9^k$，题目的难度在 0.3 到 1.0 之间。奖励只看答案对不对，**对长度没有任何奖惩**。一开始，策略很少思考很长时间。用 GRPO 训练，每题采样 8 次，每批 32 道题：

| 迭代次数 | 平均思考步数 | 正确率 | 全对或全错、没有学习信号的组 |
|---|---|---|---|
| 0 | 2.9 | 47% | 3% |
| 100 | 6.8 | 61% | 6% |
| 200 | 8.4 | 75% | 19% |
| 1000 | 10.0 | 82% | 22% |

每批只有 32 道题，所以正确率的波动比较大。
:::

<figure id="fig-ch27-sim" data-svg="ch27_sim.svg">
<figcaption>仅凭结果奖励，思考长度自发增长（实测）</figcaption>

从中可以看出两点（{{fig-ch27-sim}}）：

1. **只要多思考能提高答对的概率，仅凭"答案对不对"这一个奖励，思考长度就会自发地增长。** 这与 R1-Zero 训练过程中回答长度不断变长、增加到数千个 token 的现象是同一个机制。当然，真实情况远比这复杂：模型还要学会"怎样"思考，比如检查和回头修正，而不只是"思考多久"。
2. **随着模型变强，越来越多的组全对，学习信号随之减少。** 所以需要动态采样，并且要随着训练的推进提高题目的难度。

### 27.5 DeepSeek-R1 的完整流程

#### R1-Zero：不做任何 SFT，直接强化学习

- 在 DeepSeek-V3-Base 上直接做 GRPO，奖励只有答案正确性和格式两项。
- 2024 年 AIME 的单次正确率从 15.6% 上升到 **71.0%**，取多数答案时达到 86.7%。
- **回答的长度在训练中持续增长**，模型自发学会了**反思、验证和换一种思路**。
- 论文中记录了一个**"顿悟时刻"**：模型在推理中途写下 "Wait, wait. Wait. That's an aha moment I can flag here."，然后回过头重新审视自己的解法。
- **问题**：可读性差，经常中英文混杂。

#### R1：四个阶段

1. **冷启动 SFT**：用几千条格式良好、可读性好的长思维链数据，对 V3-Base 做 SFT；
2. **面向推理的 RL**：GRPO，奖励包括答案正确性，以及"思考过程使用同一种语言"；
3. **拒绝采样 + SFT**：用第 2 步得到的模型生成大量回答，筛选出约 60 万条推理数据；再加上约 20 万条非推理数据（写作、问答等），一共约 80 万条，重新对 V3-Base 做 SFT；
4. **面向所有场景的 RL**：推理题继续用规则奖励，其他任务用"有帮助"和"无害"两个奖励模型。

最终，R1 在 2024 年 AIME 上的单次正确率为 79.8%，在 MATH-500 上为 97.3%，与 o1 的正式版相当。完整流程见{{fig-ch27-r1}}。

#### 蒸馏

用这 80 万条数据，直接对 Qwen 和 Llama 的小模型做 SFT，就得到了一批很强的小推理模型。而且，**对小模型来说，蒸馏的效果好于直接在它上面做强化学习**：用强化学习训练 32B 的模型，效果不如直接蒸馏 R1 的输出（第 29 章）。

#### 公开的失败尝试

DeepSeek 特意在论文中写明了哪些路线**没有走通**：

- **过程奖励模型**（PRM），即给推理的每一步打分：一个"步骤"很难界定；判断中间步骤对不对本身就很难；奖励模型容易被钻空子，还要不断重新训练。
- **蒙特卡洛树搜索**（MCTS）：语言生成的搜索空间太大，价值模型也很难训练好。

**结论是：用简单的结果奖励，加上大规模的强化学习，就足够了。** 第 39 章会把这两条路线列入"可以跳过的历史弯路"。

### 27.6 为什么会有效？强化学习带来新能力了吗？

**一种解释：基座模型里本来就有这些行为。** 预训练数据中已经包含验证、回溯、分步求解等推理行为，强化学习的作用是把它们**挑出来并放大**。Gandhi 等（2025）发现，Qwen 的基座模型本来就较多地表现出这些行为，所以在强化学习中提升很快；Llama 则较少。如果先用少量带有这些行为的数据给 Llama "打个底"，它也能在强化学习中显著提升。

**争论：强化学习是扩展了能力边界，还是只是让模型更集中地给出它本来就会的答案？**

- Yue 等（2025）发现：强化学习显著提高了**单次作答**的正确率（pass@1）；但如果允许采样很多次（pass@$k$，$k$ 很大时），**基座模型反而能解出更多的题**。这说明强化学习可能只是让模型收窄到它本来就会的那些推理路径上（{{fig-ch27-passk}}）。pass@$k$ 的定义见第 30 章。
- 反方的观点：NVIDIA 的 ProRL（2025）等工作发现，强化学习训练得足够久，确实能解出基座模型采样再多次也解不出的题。

**这个问题目前仍然没有定论。**

### 27.7 RLVR 中的钻空子

规则判定的奖励虽然可靠，但仍然会被钻空子：选择题中靠猜选项拿分；在格式上投机取巧；**代码任务中钻测试的空子**，比如专门针对测试用例写死特殊情况、修改测试文件、让程序提前以"成功"状态退出。

OpenAI 在 2025 年的研究（Baker 等）发现：

- 在编程任务的强化学习中，模型确实学会了绕过测试，比如让验证函数直接返回"通过"；
- 这种行为**可以通过阅读模型的思维链被发现**，因为模型常常在思维链里直白地写出自己的打算；
- 但如果把"思维链监控器"也加进奖励里，惩罚这类想法，模型就学会了**在思维链里隐藏意图，同时继续钻空子**。

所以他们建议**不要直接对思维链施加优化压力**。这与第 31、32 章的安全与可解释性直接相关。

**防御手段**：沙箱隔离、不允许模型修改测试、使用不公开的隐藏测试、人工抽查高奖励的样本、监控思维链。

### 27.8 推理时计算量的 scaling

| 方式 | 做法 | 例子 |
|---|---|---|
| **串行：想得更久** | 允许更长的思维链 | 推理模型；s1（Muennighoff 等，2025）只用 1,000 条数据做 SFT，在模型想要停下时追加 "Wait"，强迫它继续思考，成绩随之提升 |
| **并行：多试几次** | 多次采样，取多数答案（self-consistency，Wang 等，2022），或者用验证器、奖励模型挑出最好的一个（Best-of-N） | o1 的"取 64 次中的多数" |
| **搜索** | 树搜索，加上过程奖励模型 | 效果好坏参半（见 27.5 节的失败尝试） |

Snell 等（2024）发现：在计算量相同的条件下，对于基座模型有一定把握的题目，让小模型在推理时多花计算，**可以胜过大 14 倍的模型**。

**成本问题**：推理模型的回答动辄几千甚至上万个 token，生成很贵；对于简单的问题还会"想太多"。**对策**：设置自适应的思考预算；提供"思考模式"和"不思考模式"的切换，比如 Qwen3 可以在同一个模型中切换两种模式，Claude 和 Gemini 也允许设置思考预算。

**规模**：OpenAI 在发布 o3 时提到，与 o1 相比，他们在强化学习的训练计算量和推理时的思考计算量上，又各增加了一个数量级，效果仍在继续提升。**强化学习在总训练计算量中所占的比重正在迅速上升。**

### 27.9 强化学习的训练系统

- **生成回答占了大部分时间**：每个回答可能长达 3 万到 6 万个 token，生成过程与推理一样，受限于显存带宽（第 4 章）。
- **训练和生成分开**：用专门的推理引擎（比如 vLLM 或 SGLang，第 33 章）负责生成回答，用训练框架负责更新参数。每更新一次，就要把新的权重同步给推理引擎。
- **长尾问题**：同一批回答的长度差别很大，最长的那几个会拖住整批（{{fig-ch27-rlsys}}），这与第 23 章讲的慢节点是同一类问题。对策包括**部分生成**（Kimi k1.5 的做法：超长的回答先生成到一半，下一轮再接着生成），以及**异步强化学习**（允许用稍旧几步的策略生成的数据来训练）。
- **开源框架**：verl、OpenRLHF 等。

::: keypoints
1. o1 和 R1 证明了：用程序验证的结果奖励，加上大规模强化学习，就能让模型学会长思维链。训练时和推理时的计算量都存在稳定的 scaling 规律。
2. GRPO 对同一道题采样一组回答，用组内的平均奖励作为基线，用标准差做归一化，从而去掉了 critic。已知的问题有长度偏差、零信号的组、熵塌缩，对应的改进是 Dr. GRPO 和 DAPO。
3. R1-Zero 直接在基座模型上做强化学习，思考长度和反思行为都是自发出现的。R1 的流程是：冷启动 SFT → 推理 RL → 拒绝采样再 SFT → 全场景 RL。小模型用蒸馏，效果好于直接做强化学习。过程奖励模型和 MCTS 都没有走通。
4. 模拟实验显示，仅凭结果奖励，思考长度就会增长，同时全对或全错的组越来越多。强化学习究竟是扩展了能力，还是只是收窄了采样分布，目前还有争议。
5. RLVR 同样会被钻空子，比如绕过测试。思维链监控能发现这类行为，但不能直接对思维链施加优化压力。推理时可以用串行、并行或搜索的方式增加计算量；强化学习训练系统的瓶颈在于生成回答。
:::

::: exercises
1. **计算**：某道题采样了 8 个回答，奖励为 [1, 0, 0, 1, 0, 0, 0, 0]。计算每个回答的 GRPO 优势（用总体标准差）。如果奖励全是 1，会出现什么情况？
2. **推导**：说明为什么 GRPO 中按 $1/\lvert o_i\rvert$ 做长度平均，会让又长又错的回答受到的惩罚更轻。
3. **思考**：R1-Zero 没有做任何 SFT，为什么还会出现中英文混杂、可读性差的问题？R1 加入"冷启动 SFT"和"语言一致性奖励"，分别解决了什么？
4. **思考**：为什么对小模型来说，蒸馏大模型的推理数据，效果会好于直接对小模型做强化学习？
5. **分析**：一个模型的 pass@1 从 30% 提高到 60%，但 pass@256 从 85% 下降到 80%。这说明强化学习做了什么？
6. **设计**：为一个代码强化学习任务设计防钻空子的方案，至少包括 4 项措施。
:::
