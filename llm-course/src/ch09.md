## 第 9 章　长上下文与高效注意力 {#ch9 .chapter}

::: goals
- 算清楚上下文变长之后，哪些成本在增长、增长多快；
- 理解 MLA、滑动窗口、稀疏注意力、线性注意力和状态空间模型分别靠什么省成本，又各自付出什么代价；
- 理解 RoPE 外推的原理，包括位置插值和 YaRN；
- 了解业界实际怎样训练和评测长上下文模型。

### 9.1 为什么要长上下文，难在哪里

需要很长上下文的场景越来越多：长文档、整个代码库、长对话、Agent 执行任务时累积的工具输出，以及推理模型的长思维链（第 27 章）。上下文长度的演进如下：

| 模型 | 上下文长度 |
|---|---|
| GPT-2 | 1K |
| GPT-3 | 2K |
| Llama 2 | 4K |
| Llama 3 | 8K（3.1 版扩展到 128K） |
| DeepSeek-V3 | 128K |
| Gemini 1.5 | 1M |

上下文变长后，有三样东西在增长：

| 成本 | 增长方式 | 后果 |
|---|---|---|
| **注意力的计算量**（训练，以及推理时处理提示词的阶段） | 每个 token 每层约 $4Td$，总量随 $T^2$ 增长 | 训练和处理长提示词都变得很贵 |
| **注意力矩阵的显存**（朴素实现） | 每个头要存一个 $T\times T$ 的矩阵 | FlashAttention 解决了这个问题（第 22 章），但它不减少计算量 |
| **KV cache**（推理时） | 每条序列随 $T$ 线性增长 | 生成每个 token 时都要把整个缓存读一遍，而这一步受显存带宽限制（第 4 章），所以越长越慢、越贵 |

此外还有一个与成本无关的问题：**模型得真的学会利用长上下文**。这涉及位置编码能否外推，以及有没有合适的训练数据。

**注意力的计算量占多少？** 第 6 章习题 6 推出：每层每个 token 中，注意力分数的计算量约为 $4Td$，矩阵乘法约为 $24d^2$，因此注意力所占的比例约为 $T/(T + 6d)$。以 $d = 4096$ 为例（估算，曲线见{{fig-ch09-share}}）：

| $T$ | 8K | 32K | 128K | 1M |
|---|---|---|---|---|
| 注意力占总计算量的比例 | 25% | 57% | 84% | 98% |

<figure id="fig-ch09-share" data-svg="ch09_share.svg">
<figcaption>上下文越长，注意力在计算量中所占的比例越大；模型越宽，这个转折点来得越晚（估算）</figcaption>
</figure>

这是粗略估计。因果掩码使得只需要算下三角，注意力的实际计算量大约是上面估计的一半。不过整体趋势不变：上下文足够长之后，**注意力会主导全部计算**。

### 9.2 MLA：把 KV cache 压成一个小向量

MLA（多头潜在注意力）出自 DeepSeek-V2，DeepSeek-V3 和 Kimi K2 也在用。

#### 思路：低秩压缩

普通注意力要为每个头分别缓存 K 和 V。MLA 只缓存一个低维的**潜在向量** $c$，需要时再从它还原出各个头的 K 和 V：

$$
c_t = x_t W_{DKV}\;(\text{把 } d \text{ 维压缩到 } d_c = 512 \text{ 维，只缓存它}), \qquad K = c\,W_{UK},\quad V = c\,W_{UV}.
$$

#### 关键技巧：矩阵吸收

如果每生成一步都要把所有历史 token 的 K 解压一遍，就太浪费了。但注意到

$$
q\,k^\top = (xW_q)(c\,W_{UK})^\top = x\,(W_q W_{UK}^\top)\,c^\top.
$$

$W_{UK}$ 可以预先和 $W_q$ 合并成一个矩阵。这样，query 可以直接和缓存中的潜在向量 $c$ 做点积，**完全不需要还原出 K**。同理，$W_{UV}$ 可以合并进输出投影 $W_o$。

#### RoPE 带来的麻烦

RoPE 会在 $q$ 和 $k$ 之间插入一个随位置变化的旋转矩阵（第 7 章）：$q\,R_{m-n}\,k^\top$。这个旋转矩阵夹在 $W_q$ 和 $W_{UK}$ 中间，而且对每一对位置都不同，上面的合并就做不成了。

DeepSeek 的解决办法叫**解耦 RoPE**：另外拿出一小段维度（64 维）专门携带 RoPE 位置信息，其中 key 这一部分由所有头共享，也一起缓存。最终，**每层每个 token 只需缓存 $512 + 64 = 576$ 个数**（{{fig-ch09-mla}}）。

<figcaption>MLA 的数据流：只缓存压缩后的潜在向量和一小段 RoPE key</figcaption>
</figure>

#### 缓存大小对比

以 DeepSeek-V3 的规格计算：128 个头，$d_h = 128$。

| 方案 | 每层每个 token 要缓存的数 |
|---|---|
| MHA | $2\times128\times128 = 32{,}768$ |
| GQA（8 组） | $2\times8\times128 = 2{,}048$ |
| **MLA** | **576**，约为 MHA 的 1/57（{{fig-ch09-kvbars}}） |

DeepSeek-V2 的论文报告：与他们之前的 67B 稠密模型相比，KV cache 减少了 93.3%；在他们的消融实验中，MLA 的效果甚至优于 MHA。还有一个额外的好处：生成文本时，每从显存读一个字节，MLA 能做更多计算，即算术强度更高，更适合受显存带宽限制的生成阶段。

### 9.3 滑动窗口与局部–全局混合

**滑动窗口注意力**：每个 token 只关注它前面的 $W$ 个 token。

- 计算量随 $TW$ 增长，而不是 $T^2$；
- KV cache 最多只需存 $W$ 个 token；
- 信息仍然可以传得更远：每经过一层，能"看到"的范围就扩大 $W$，$L$ 层之后理论上覆盖 $LW$ 个 token，这与卷积网络的感受野是一个道理；
- 代表：Mistral 7B，$W = 4096$。

**局部–全局混合**：把滑动窗口层和全注意力层交替堆叠。Gemma 2 的局部层和全局层按 1:1 交替，窗口为 4,096；Gemma 3 按 5:1 交替，窗口缩小到 1,024，大幅减少了 KV cache。GPT-3 当年也是让全注意力层和局部带状稀疏层交替使用。

**注意力汇聚点**（attention sink）：StreamingLLM（Xiao 等，2023）发现，模型会把大量注意力权重放在序列最开头的几个 token 上。如果推理时用纯滑动窗口把它们丢掉，模型的表现会崩溃；只要保留开头几个 token，就能恢复正常。这说明 softmax 需要一个可以"安放"多余注意力的地方。

### 9.4 稀疏注意力：按内容挑选要看的 token

滑动窗口的模式是固定的。稀疏注意力则根据内容，为每个 query 动态挑选少量 token 来做注意力：

- **NSA**（DeepSeek，2025）：把三路结果组合起来，分别是压缩后的粗粒度信息、精选出的 token 块，以及滑动窗口；
- **MoBA**（Moonshot，2025）：先把序列切成块，再像 MoE 选专家那样为每个 query 选出相关的块；
- **DSA**（DeepSeek-V3.2-Exp，2025）：用一个很轻量的"索引器"先给所有 token 打分，每个 query 只对得分最高的 2,048 个 token 做完整的注意力。它建在 MLA 之上，两者省的是不同的东西：MLA 让每个 token 缓存的数据变小，DSA 让每个 query 要看的 token 变少；全部 token 的潜在向量仍然留在缓存里，因为下一个 query 可能选中任何一个。

{{fig-ch09-patterns}} 把全注意力、滑动窗口、块稀疏和注意力汇聚点几种模式放在一起做了对比。这是当前工程和研究的前沿方向。

### 9.5 线性注意力与状态空间模型

#### 线性注意力

把 $\operatorname{softmax}(qk^\top)$ 换成 $\phi(q)\phi(k)^\top$，其中 $\phi$ 是某种特征映射（Katharopoulos 等，2020）。利用矩阵乘法的结合律，可以改变计算顺序：

$$
o_t = \phi(q_t)\,S_t, \qquad S_t = S_{t-1} + \phi(k_t)^\top v_t,
$$

$S$ 是一个固定大小的"状态"矩阵。每生成一个 token，只需要更新一次固定大小的状态，时间和显存都不再随 $T$ 增长，**本质上它又变回了 RNN**（第 6 章）。不同的是，训练时它有并行的计算形式（分块累积），不像传统 RNN 那样只能逐步串行。

#### 状态空间模型

代表是 **Mamba**（Gu 与 Dao，2023）。它的状态更新中的衰减和门控都由输入决定，所以叫"选择性"的状态空间模型（SSM），并配有针对硬件优化的扫描算法。Mamba-2（2024）进一步证明，这类模型和线性注意力在数学上是相通的。属于同一家族的还有 RetNet、GLA、RWKV、Gated DeltaNet 等。

#### 代价：精确回忆能力差

不管前面有多长，所有历史都被压缩进一个固定大小的状态里，这必然会丢失信息（{{fig-ch09-state}}）。所以这类模型在**需要精确回忆的任务**上明显不如全注意力，比如逐字复制很久以前出现的一段内容，或者从长文中准确找出某个细节。Zoology（Arora 等，2023）系统地测量过这个差距。

<figure id="fig-ch09-state" data-svg="ch09_state.svg">
<figcaption>softmax 注意力的缓存随序列增长；线性注意力和 SSM 只维护一个固定大小的状态</figcaption>
</figure>

#### 混合架构

用少量全注意力层负责精确检索，大量线性层或 SSM 层负责降低成本：

| 模型 | 混合方式 |
|---|---|
| Jamba（AI21，2024） | 1 层注意力配 7 层 Mamba |
| MiniMax-01（2025） | 每 8 层中 7 层用线性注意力，1 层用 softmax 注意力 |
| Qwen3-Next（2025） | Gated DeltaNet 与门控注意力按 3:1 组合 |
| Kimi Linear（2025） | 线性注意力层与 MLA 按 3:1 组合 |

截至课程讲授时，**混合架构正被越来越多地采用**，而主流的旗舰模型仍以全注意力（或其稀疏变体）为主。

### 9.6 RoPE 外推：让模型处理比训练时更长的序列

#### 问题出在哪里

第 7 章讲过，RoPE 的每一对维度都按自己的频率随位置旋转。频率 $\theta_i$ 对应的**波长**，即转完一整圈所需的位置数，是 $2\pi/\theta_i$。

- **高频的维度对**波长很短，在训练长度内已经转了很多圈，所有可能的角度都见过；
- **低频的维度对**波长超过了训练长度，训练时一圈都没转完，只见过一部分角度。

一旦位置超出训练长度，低频维度就会出现**从未见过的角度**，模型随即失效，困惑度急剧上升。

举个具体的数字：base = 10,000，$d_h = 128$，训练长度 4,096。64 对维度中，有 18 对的波长超过 4,096（第 46 到 63 对），另有 1 对的波长约为 4,080，与训练长度相当，合计约 19 对没有被充分覆盖。这些就是出问题的维度（{{fig-ch09-wave}}）。

<figure id="fig-ch09-wave" data-svg="ch09_wave.svg">
<figcaption>RoPE 各维度对的波长。base 越大，波长整体越长</figcaption>
</figure>

#### 几种解决方法

| 方法 | 做法 | 特点 |
|---|---|---|
| **位置插值**（PI，Meta，2023） | 把所有位置按 $T_{\text{train}}/T_{\text{target}}$ 等比例压缩，让角度都落回见过的范围 | 简单，需要少量微调（约 1,000 步），曾把 Llama 从 2K 扩展到 32K。缺点是高频维度也被压缩了，相邻 token 之间更难区分 |
| **NTK-aware 缩放**（开源社区，2023） | 不压缩位置，而是增大 base | 高频维度几乎不变，低频维度被拉伸 |
| **YaRN**（Peng 等，2023） | **按频率区别对待**：高频不动，低频做插值，中间平滑过渡；另外对注意力的温度做一点修正 | 所需的微调数据和步数都比以往方法少得多。DeepSeek-V3 用它从 4K 扩展到 32K，再到 128K，每个阶段只训练 1,000 步。Qwen 也在用 |
| **一开始就用很大的 base** | 例如 Llama 3 用 500,000 | 波长从一开始就更长，为后续扩展留出余地 |

### 9.7 实际怎样训练长上下文模型

#### 两阶段训练

1. **主体预训练用短序列**，通常是 4K 到 8K。原因是注意力的成本随 $T^2$ 增长，而大多数文档本来就不长。
2. **最后加一个"长上下文扩展"阶段**：继续训练，用更长的序列，调整 RoPE（改 base 或用 YaRN），并提高长文档在数据中的比例。

公开的例子：Llama 3 先在 8K 上预训练，再分 6 个阶段逐步从 8K 扩展到 128K，共用了约 8,000 亿 token；DeepSeek-V3 先在 4K 上预训练，然后用 YaRN 依次扩展到 32K 和 128K。

#### 数据

真正很长的文档很稀少，所以要专门处理：

- **提高长文档的采样比例**，比如书籍、代码仓库、论文；
- 同时**保留短数据**，避免模型在短文本上的能力退化；
- 有研究（Fu 等，2024）发现，只要各领域的长文档配比合理，几十亿 token 的继续训练就足以把模型扩展到 128K。

#### 打包与文档掩码

训练时，为了不浪费计算，通常把多篇短文档拼接成一条长序列，这叫**打包**（packing，见{{fig-ch09-packing}}）。这时需要加一个掩码，禁止一篇文档里的 token 去关注另一篇文档里的 token，Llama 3 就是这样做的。否则，模型会学到"前面那篇毫不相干的文章也是我的上下文"这种错误的模式。

<figcaption>打包与文档掩码（示意）</figcaption>

#### 系统层面

注意力的显存问题靠 **FlashAttention** 解决（第 22 章）。序列长到一张卡放不下时，就要把**一条序列切分到多张 GPU 上**，这叫上下文并行或 ring attention（第 21 章）。

### 9.8 怎样评测长上下文能力

| 评测 | 测什么 | 说明 |
|---|---|---|
| **大海捞针**（needle in a haystack） | 在一大段无关文本的随机位置插入一条信息，然后提问 | 太容易，大多数模型都能通过，不足以说明问题 |
| **RULER**（NVIDIA，2024） | 多根针、多跳追踪、信息聚合等更难的任务 | 发现很多模型的**有效上下文长度远短于宣称的长度** |
| **Lost in the middle**（Liu 等，2023） | 关键信息放在开头、中间、结尾时的表现 | 信息位于**中间**时，模型的表现明显更差 |

其他常用的长上下文基准还有 LongBench、HELMET 等。

### 9.9 汇总

| 技术 | 节省什么 | 代价 | 代表 |
|---|---|---|---|
| GQA | KV cache（约 4 到 8 倍） | 效果几乎不变 | Llama 3 |
| MLA | KV cache（约 57 倍） | 实现复杂，需要解耦 RoPE | DeepSeek-V2/V3，Kimi K2 |
| 滑动窗口 + 全局混合 | 计算量和 KV cache | 局部层看不远 | Gemma 2/3，Mistral |
| 稀疏注意力 | 长序列下的计算量 | 需要一套挑选机制 | NSA，MoBA，DSA |
| 线性注意力 / SSM（混合使用） | 计算量和显存都与长度无关 | 精确回忆能力较弱 | Jamba，Qwen3-Next |
| YaRN 等 RoPE 外推方法 | 长序列的训练成本（只需短期继续训练） | 仍需要合适的长数据 | DeepSeek-V3，Qwen |

::: keypoints
1. 上下文变长后，注意力的计算量随 $T^2$ 增长，KV cache 随 $T$ 增长。$T$ 远大于 $6d$ 时，注意力会主导全部计算。
2. MLA 通过低秩压缩和矩阵吸收，只缓存一个小向量，再用解耦 RoPE 解决位置编码的冲突。
3. 滑动窗口和稀疏注意力的思路是"只看一部分"。线性注意力和 SSM 把历史压缩成固定大小的状态，代价是精确回忆变差，所以常以混合架构的形式使用。
4. RoPE 外推失败，根源在于低频维度出现了训练中没见过的角度。YaRN 只对低频维度做插值。
5. 实际做法是：先用短序列预训练，再做长上下文扩展，配合长文档上采样、文档掩码和 RoPE 调整。评测要用比大海捞针更难的任务。
:::
