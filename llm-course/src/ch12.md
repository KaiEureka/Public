## 第 12 章　优化器与训练稳定性 {#ch12 .chapter}

::: goals
- 认出各种训练失稳现象，说清它们的常见成因；
- 掌握架构、优化器、数据、数值精度和监控这五个层面的防御手段；
- 知道 loss 暴涨之后怎样处理；
- 理解 Muon 等新一代优化器的原理，以及它们实际的收益有多大。
:::

### 12.1 失稳长什么样：真实案例

**loss spike**（loss 尖峰）：loss 本来在平稳下降，突然在几十步之内跳高一大截。有的尖峰会自己恢复；有的不会，loss 从此居高不下，或者直接变成 NaN（not a number，说明计算结果已经溢出或失效），这种情况叫**发散**（{{fig-ch12-spike}}）。

<figure id="fig-ch12-spike" data-svg="ch12_spike.svg">
<figcaption>loss 尖峰、发散与回滚（示意）</figcaption>
</figure>

| 案例 | 发生了什么 | 怎样处理的 |
|---|---|---|
| **OPT-175B**（Meta，2022） | 训练了 2 个月，单是硬件故障就造成至少 35 次人工重启，还有多次 loss 发散 | 从更早的检查点重启，并调低学习率。他们公开了完整的训练日志 |
| **PaLM 540B**（Google，2022） | 已经开了梯度裁剪，仍出现了约 20 次尖峰 | 从尖峰前约 100 步的检查点重启，**跳过约 200 到 500 个 batch 的数据**。他们发现原因并不是"数据本身有问题"，而是**某些数据与当时的模型状态碰到了一起** |
| **BLOOM 176B** | 前期 104B 规模的试验多次发散 | 在嵌入层后面加一个 LayerNorm，并改用 bf16 |
| **GLM-130B** | 训练前期不稳定 | 把嵌入层的梯度乘以 0.1 |
| **OLMo 2**（2024） | 经常出现尖峰 | 一组组合改动（见 12.3 节），并**过滤掉含有大量重复片段的文档** |
| **DeepSeek-V3** | 报告中说：整个训练过程中没有出现无法恢复的 loss 尖峰，也没有做过任何回滚 | 这是一项工程成就，不是理所当然的事 |
| **Kimi K2** | 用 Muon 训练了 15.5T token，没有出现一次尖峰 | 使用 QK-Clip（12.4 节） |

### 12.2 常见成因

**① 注意力 logits 不断增长。** 训练过程中 $q\cdot k$ 的值越变越大，softmax 变得几乎只关注一个 token，注意力分布的熵塌缩到接近 0。这时梯度变得很不稳定，最终发散。ViT-22B（Dehghani 等，2023）的训练就遇到了这个问题。

**② 输出层 logits 漂移。** 输出层所有 logits 的整体水平，即 $\log Z$（$Z$ 是 softmax 的分母），不断往一个方向漂，数值越来越大。

Wortsman 等（2023）的一个重要发现是：**用小模型配上偏高的学习率，就能复现 ① 和 ② 这两种大模型才会遇到的失稳。** 所以失稳问题可以用便宜的小规模实验来研究。

**③ Adam 的二阶矩"过时"。** 第 3 章讲过，Adam 用梯度平方的移动平均 $v$ 来给每个参数归一化步长。设想某个参数长时间梯度很小，比如一个罕见 token 的嵌入向量，它的 $v$ 就会衰减得很小。这时如果突然来了一个大梯度（比如这个罕见 token 一下子大量出现），更新量 $\hat m/\sqrt{\hat v}$ 会远远超过学习率，于是产生尖峰（{{fig-ch12-adam}}）。$\beta_2$ 越大，$v$ 的记忆越长，这个"过时期"也越长：$\beta_2 = 0.999$ 时，$v$ 大约记住最近 1,000 步；$\beta_2 = 0.95$ 时，只记住约 20 步，能更快跟上梯度的变化。这是大模型普遍用 $\beta_2 = 0.95$ 的原因之一。

<figure id="fig-ch12-adam" data-svg="ch12_adam.svg">
<figcaption>Adam 二阶矩“过时”造成的更新暴涨：β₂ 越大，v 跟上新梯度尺度越慢（数值模拟）</figcaption>
</figure>

$\epsilon$ 也有影响。模型越大，梯度的典型尺度越小，可能逐渐接近 $\epsilon$。一旦接近，Adam 的实际步长就会被悄悄压低。所以大模型往往需要更小的 $\epsilon$。

**④ 病态数据。** 长串重复的内容、乱码或者格式异常的文本，可能产生异常大的梯度。OLMo 2 发现，含有大量重复 n-gram（连续 $n$ 个 token 组成的片段）的文档是尖峰的来源之一。

**⑤ 数值精度。** fp16 能表示的最大值只有 65,504，很容易溢出成无穷大；bf16 的数值范围和 fp32 一样，但精度位更少，累加大量数时误差会积累。第 13 章细讲。

**⑥ 学习率过高，或 warmup 太短。** 见第 3、11 章。

**⑦ 硬件静默错误。** GPU 偶尔会算错，比如内存中某一位翻转了，而且不报任何错误。结果可能是 NaN，也可能是一个看起来莫名其妙的尖峰。第 23 章细讲。

### 12.3 防御手段

| 层面 | 手段 | 针对的成因 |
|---|---|---|
| **架构** | Pre-norm 与 RMSNorm（第 3 章） | 各层激活值的尺度失控 |
| | **QK-norm**：对 $q$ 和 $k$ 先做归一化，再计算点积（第 7 章） | ① |
| | **z-loss**：在 loss 上加一项 $10^{-4}\times(\log Z)^2$（PaLM 的设置） | ② |
| | **logit 软上限**（Gemma 2）：用 tanh 把注意力 logits 限制在 ±50 以内，把输出 logits 限制在 ±30 以内 | ①② |
| | 嵌入层之后加一个归一化（BLOOM）；去掉偏置（第 7 章） | 嵌入和激活值失控 |
| | **重排归一化的位置**（OLMo 2）：把归一化放在注意力和 MLP 的**输出**上，再加回残差流 | 残差流的数值增长 |
| **优化器** | $\beta_2 = 0.95$；梯度裁剪阈值 1.0；合适的 $\epsilon$；学习率宁可偏低；足够长的 warmup | ③⑥ |
| | 嵌入层不做权重衰减（OLMo 2） | 罕见 token 的嵌入被过度压缩 |
| | 逐参数的更新裁剪（StableAdamW） | ③ |
| **初始化** | 小的初始化标准差（0.02），残差分支的输出层按层数缩小；或者用 μP（第 11 章） | 训练初期不稳定 |
| **数据** | 过滤重复片段和乱码，充分打乱数据顺序 | ④ |
| **数值** | 用 bf16 而不是 fp16；softmax、归一化和 loss 这几类计算保留 fp32；保留一份 fp32 的主权重（第 13 章） | ⑤ |

OLMo 2 的做法是一套组合拳：RMSNorm、QK-norm、重排归一化的位置、z-loss、嵌入层不做权重衰减、调整初始化，再加上过滤重复数据。他们报告，这些改动加在一起之后，训练曲线明显变得平稳。

### 12.4 新一代优化器：Muon

#### 出发点

Adam 把每个参数当成一个独立的数来处理，完全不管一个权重矩阵内部的结构。实际上，梯度矩阵往往被少数几个方向主导：它的奇异值分布非常不均匀，有几个特别大，其余都很小。Shampoo（2018）和 SOAP（2024）这类方法会利用整个矩阵的统计信息来调整更新方向，但计算开销大、实现复杂。

#### Muon 的做法

Muon（Keller Jordan 等，2024）对每个二维的权重矩阵：

1. 先计算动量 $m$，与带动量的 SGD 相同；
2. 设 $m$ 的奇异值分解为 $m = U\Sigma V^\top$，**把所有奇异值都换成 1**，用 $UV^\top$ 作为更新方向。这一步叫**正交化**；
3. 精确计算 SVD 太慢，Muon 用 5 次 **Newton–Schulz 迭代**来近似。这个迭代全部由矩阵乘法组成，在 GPU 上很快，用 bf16 精度就可以。

**直观理解**：Adam 是对**每个坐标**分别做归一化，让每个参数的步长都差不多；Muon 是对**每个奇异方向**分别做归一化，让矩阵在每个方向上的更新幅度都差不多（{{fig-ch12-ortho}}）。这样，被大梯度方向淹没的那些"小方向"也能得到充分的更新。从理论上看，Muon 等价于在谱范数（矩阵的最大奇异值）约束下做最速下降。

<figure id="fig-ch12-ortho" data-svg="ch12_ortho.svg">
<figcaption>正交化的几何含义：把动量矩阵的所有奇异值换成 1，只保留方向（示意）</figcaption>
</figure>

```python
def newton_schulz(G, steps=5):
    a, b, c = 3.4445, -4.7750, 2.0315        # 原实现中的五次多项式系数
    X = G / (G.norm() + 1e-7)                # 先缩放，保证所有奇异值都不超过 1
    for _ in range(steps):
        A = X @ X.T
        X = a * X + (b * A + c * A @ A) @ X  # X 的奇次多项式：只改变奇异值，不改变奇异向量
    return X

# Muon 的一步（只用于隐藏层的矩阵）
m = beta * m + grad
W -= lr * newton_schulz(m)
```

::: experiment
**Newton–Schulz 正交化的数值演示。** 构造一个 $256\times512$ 的"类梯度"矩阵：有 3 个很强的方向，其余奇异值按指数递减。对它做 5 次 Newton–Schulz 迭代，比较奇异值：

| 第几个奇异值 | 0 | 1 | 2 | 10 | 50 | 128 | 255 |
|---|---|---|---|---|---|---|---|
| 原始梯度 $G$ | 50.0 | 20.0 | 8.0 | 0.825 | 0.276 | 0.033 | 0.001 |
| 5 次迭代之后 | 1.202 | 1.202 | 1.200 | 1.178 | 0.906 | 0.286 | 0.009 |

最强的 3 个方向在原始梯度中占更新量（按奇异值平方计）的 99.4%，正交化之后只占 4.6%。迭代结果与精确的 $UV^\top$ 之间的余弦相似度是 0.734。
:::

<figure id="fig-ch12-sv" data-svg="ch12_sv.svg">
<figcaption>Newton–Schulz 迭代前后的奇异值（实测，数据同上表）</figcaption>
</figure>

- 更新被均匀地分摊到了很多方向上（{{fig-ch12-sv}}）：大和中等的奇异值都被拉到了 1 附近。
- 极小的那些方向（基本是噪声）只被部分放大。这说明 5 次迭代只是一个近似；实际使用中，这样的近似已经够用。

#### 实际使用中的要点

- **只用于隐藏层的矩阵**。嵌入层、输出层、归一化层的 $\gamma$ 以及偏置，仍然用 AdamW。
- **状态更省**：Muon 每个参数只需要存一个动量，Adam 要存两个，所以每个参数能省 4 字节。
- **开销**：每一步要额外做几次矩阵乘法，一般只增加几个百分点的计算量。但在分布式训练中，权重矩阵通常被切分到多张卡上（第 20 章），而正交化需要完整的矩阵，所以实现起来更麻烦。

#### 已发表的证据

| 来源 | 结果 |
|---|---|
| NanoGPT speedrun（一个公开的"最快训练出 GPT-2 small"竞赛） | Muon 是刷新纪录的关键因素之一 |
| Moonshot《Muon is Scalable》（2025） | 加入权重衰减，并把每个矩阵的更新幅度缩放到与 AdamW 相当的水平，这样 AdamW 的超参数可以直接沿用。在他们的 scaling 实验中，**计算效率约为 AdamW 的 2 倍** |
| **Kimi K2**（1T 参数的 MoE） | 用 MuonClip 训练了 15.5T token，全程没有出现 loss 尖峰 |

MuonClip 中的 **QK-Clip** 是这样做的：一旦某个头的最大注意力 logit 超过阈值，就按比例直接缩小这个头的 $W_q$ 和 $W_k$。这与 QK-norm 一样，都是在防御 12.2 节的成因 ①。

#### 其他优化器

- **Lion**（2023）：只取动量的符号作为更新方向。
- **Adafactor**：对二阶矩做分解存储，节省内存，T5 用过它。
- **Schedule-free**（2024）：不需要设计学习率调度。它赢得了 2024 年 AlgoPerf 优化器竞赛中"无需调参"的赛道，而 Distributed Shampoo 赢得了允许外部调参的赛道。

#### 需要保持清醒

**很多新优化器宣称的提升，在把 AdamW 基线认真调好之后会明显缩水。** Wen 等（2025）做了系统比较，发现 Muon、SOAP 这类基于矩阵的方法在小模型上约有 1.3 倍的加速，到了 1.2B 参数的规模，只剩约 1.1 倍。评价新方法时，一定要和**调到最好的**基线比较，并且看它的收益是否随规模保持住。

### 12.5 训练时要监控什么

| 指标 | 用来发现什么 |
|---|---|
| 训练 loss 和验证 loss（分领域：代码、数学、多语言……） | 尖峰、发散，以及某个领域的能力是否在退化 |
| 全局梯度范数，以及每一层的梯度范数 | 尖峰的前兆。梯度范数往往先于 loss 出现异常 |
| 每一层的更新量与参数量之比 $\lVert\Delta\theta\rVert/\lVert\theta\rVert$ | 某一层是否在剧烈变化，或者已经停止学习 |
| 注意力 logits 的最大值、注意力的熵 | 成因 ① |
| 输出层 logits 的统计量，以及 $\log Z$ | 成因 ② |
| 激活值的范数、梯度裁剪被触发的比例 | 数值是否在失控 |
| 吞吐量、各 GPU 每步的耗时 | 硬件问题、掉队的慢节点（第 23 章） |

### 12.6 出现尖峰后的处理流程

整个流程见{{fig-ch12-flow}}。

1. **先判断**：这个尖峰会不会自己恢复？如果几百步之内就回到了原来的趋势线，通常可以不管它。
2. **回滚**：从尖峰前几十到几百步的检查点重新开始。所以检查点要存得足够频繁。
3. **跳过数据**：跳过尖峰附近的若干个 batch（PaLM 的做法），或者打乱数据顺序。
4. **临时调低学习率**（OPT 的做法），过一段时间再恢复。
5. **如果反复出现**，就要从结构上找原因：检查注意力和输出 logits 的统计量，考虑加入 QK-norm 或 z-loss，排查数据，排查硬件。在运行中的训练里改动结构，要承担一定的风险。
6. **每一次处理都要记录下来**，作为团队的运维知识。OPT 公开的训练日志是很好的学习材料。

::: keypoints
1. 大规模训练中，loss 尖峰和发散很常见，PaLM、OPT、BLOOM 都遇到过。它往往是"数据与模型状态"共同作用的结果。
2. 常见成因有：注意力 logits 增长、输出 logits 漂移、Adam 二阶矩过时、病态数据、数值精度、学习率过高，以及硬件错误。其中前两种可以用"小模型 + 高学习率"复现。
3. 防御要多层面组合：QK-norm 或 QK-Clip、z-loss、$\beta_2 = 0.95$、梯度裁剪、嵌入层不做权重衰减、数据过滤、bf16，再加上完善的监控和回滚流程。
4. Muon 用 Newton–Schulz 迭代对动量矩阵做正交化，让所有奇异方向的更新幅度大致相等。在大模型上已有成功案例（Kimi K2）。但实际收益需要和调好的 AdamW 认真比较，而且收益可能随规模缩小。
:::

::: exercises
1. **计算**：$\beta_2 = 0.999$ 和 $\beta_2 = 0.95$ 时，$v$ 的"有效记忆长度" $1/(1-\beta_2)$ 分别是多少步？用这个结果解释，为什么较小的 $\beta_2$ 能减少成因 ③ 导致的尖峰。
2. **推导**：z-loss 定义为 $\mathcal{L}_z = 10^{-4}(\log Z)^2$，求它对每个 logit 的梯度。说明当 $\log Z > 0$ 时，它会怎样影响所有的 logits。
3. **思考**：为什么 QK-norm 能给注意力 logits 设一个上限？这个上限由什么决定？
4. **推导**：设 $G = U\Sigma V^\top$，正交化之后的更新是什么？如果 $G$ 是秩为 1 的矩阵，Muon 的更新又是什么？它和"把梯度归一化"有什么关系？
5. **思考**：PaLM 处理尖峰时，为什么不是只跳过"那一个坏 batch"，而是要回退 100 步，并跳过几百个 batch？
6. **设计**：为一次为期 2 个月的大规模训练设计一份告警清单：选 5 个指标，分别给出触发告警的条件，以及触发后由谁、做什么处理。
:::
