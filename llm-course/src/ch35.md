## 第 35 章　多模态 {#ch35 .chapter}

::: goals
- 理解 ViT 怎样把图片变成 token；
- 推导 CLIP 的对比学习目标，并在实验中看到它把两种模态"对齐"到同一个空间；
- 比较视觉语言模型的几种架构（LLaVA 式、交叉注意力式、原生多模态），会计算图片的 token 数，知道它们的数据和训练流程；
- 理解语音的 token 化，以及级联式和端到端式语音模型的区别；
- 掌握扩散模型的数学和采样过程，在实验中看到它从纯噪声生成出数据；了解潜空间扩散、无分类器引导、DiT、流匹配，以及自回归的图像生成和统一模型。
:::

多模态要解决三类问题：**理解**，看懂图片、视频，听懂语音，然后用文字回答；**生成**，生成图片、语音、视频；**统一**，用一个模型同时完成理解和生成，各种模态可以自由地混合输入和输出。核心思路始终如一：**想办法把其他模态也变成"token"，让 Transformer 来处理。**

### 35.1 ViT：把图片切成小块当作 token

ViT（Dosovitskiy 等，2020）的做法是（{{fig-ch35-vit}}）：

1. 把图片切成固定大小的小块（patch），比如每块 16×16 像素；
2. 把每一块展平，用一个线性层投影成一个 $d$ 维向量，这就是一个"视觉 token"；
3. 加上位置嵌入，送进 Transformer 编码器。注意这里**没有因果掩码**，每个 token 都能看到所有其他 token。

<figure id="fig-ch35-vit" data-svg="ch35_vit.svg">
<figcaption>ViT：把图片切成小块当作 token</figcaption>
</figure>

**token 数的计算**：224×224 的图片，16×16 的块，得到 $(224/16)^2 = 196$ 个 token；336×336 的图片，14×14 的块，得到 $(336/14)^2 = 576$ 个 token，LLaVA-1.5 用的就是这个设置。

**一个历史上的发现**：ViT 几乎没有卷积网络那样的"图像先验"，比如局部性、平移不变性，所以在数据少的时候不如卷积网络。但当训练数据达到上亿张图片的规模时，它反而超过了卷积网络。这与语言模型"规模胜过精巧设计"的规律是一致的。

### 35.2 CLIP：把图片和文字对齐到同一个空间

#### 做法

CLIP（Radford 等，2021）的做法是：

1. 准备两个编码器，一个编码图片，一个编码文字，输出都归一化成单位向量；
2. 从网上收集了 **4 亿对图片和文字**；
3. 每个 batch 有 $B$ 对图文，计算 $B\times B$ 的相似度矩阵。**对角线上是真正配对的图文，其余位置都是不配对的**；
4. 把每一行看成一个 $B$ 分类问题，正确答案是对角线上的那一项；对每一列也做同样的处理，然后取平均。这叫对称的 **InfoNCE** 损失（{{fig-ch35-clip}}）：

$$
\text{logits} = \frac{I\,T^\top}{\tau}, \qquad
\mathcal{L} = \frac12\Big[\operatorname{CE}(\text{logits}, \text{对角线}) + \operatorname{CE}(\text{logits}^\top, \text{对角线})\Big],
$$

其中 $I$、$T$ 的每一行分别是图片和文字的单位向量，$\tau$ 是温度，比如 0.07。

<figure id="fig-ch35-clip" data-svg="ch35_clip.svg">
<figcaption>CLIP 的相似度矩阵与对称 InfoNCE</figcaption>
</figure>

#### 零样本分类

训练完成后，可以直接拿来做图片分类，不需要专门训练分类器：把每个类别名写成一句话，比如 "a photo of a dog"，分别编码，然后看图片和哪句话的向量最接近。CLIP 用这种零样本的方式，在 ImageNet 上达到了 76.2% 的准确率，与一个专门在 ImageNet 上监督训练出来的 ResNet-50 相当。

**SigLIP**（Zhai 等，2023）把 softmax 换成了对每一对图文分别做二分类的 sigmoid 损失，训练起来更高效。现在很多视觉语言模型都用它作为视觉编码器，比如 Gemma 3。

::: experiment
**对比学习的小实验。** 构造两种"模态"：它们都由同一个隐藏的变量 $z$ 生成，但经过不同的非线性变换，并加上了噪声。分别训练两个小编码器，使用上面的对称 InfoNCE 损失。在 1,000 个候选中找到真正配对的那一个（top-1 检索准确率）：

| | 检索准确率 |
|---|---|
| 训练前 | 0.1%（随机猜的水平） |
| 训练 2,000 步后 | 99.5% |
:::

两个编码器从未被告知 $z$ 是什么，但对比学习让它们各自学会了把输入映射到一个**共享的空间**里，在这个空间中，配对的样本彼此靠近。

### 35.3 视觉语言模型的架构

#### ① LLaVA 式："视觉编码器 + 连接层 + 语言模型"

LLaVA（Liu 等，2023）的数据流是（{{fig-ch35-llava}}）：图片 → CLIP 或 SigLIP 的视觉编码器 → 一个小的 MLP 连接层 → 视觉 token（576 个）→ 与文字 token 拼接在一起 → 语言模型 → 文字回答。**训练分两个阶段**：

1. 冻结视觉编码器和语言模型，只训练 MLP 连接层，用约 55.8 万对图片说明。目的是让视觉 token "说上语言模型的话"。
2. 解冻语言模型，做视觉指令微调。LLaVA 最初用了约 15.8 万条由 GPT-4 生成的视觉问答数据，LLaVA-1.5 扩充到了约 66.5 万条混合数据。

这种结构简单有效，是开源视觉语言模型的主流。

<figure id="fig-ch35-llava" data-svg="ch35_llava.svg">
<figcaption>LLaVA 式视觉语言模型的结构</figcaption>
</figure>

#### ② 交叉注意力式

- **Flamingo**（DeepMind，2022）：用一个"重采样器"把视觉特征压缩成固定数量的 token，再在冻结的语言模型中**插入额外的交叉注意力层**来读取它们。这些新加的层带有门控，初始化时门是关着的，所以一开始不会破坏语言模型原有的能力。
- **BLIP-2 的 Q-Former**：用一组可学习的查询向量，从视觉特征中提取出少量 token。

#### ③ 原生多模态（早期融合）

- **Chameleon**（Meta，2024）：先把图片也转换成**离散的 token**（用 VQ 方法，见 35.5 节），然后从预训练开始，就把图片 token 和文字 token 混在一起训练。所以它既能理解图片，也能生成图片。
- **Gemini** 被描述为从一开始就是原生多模态的模型；**GPT-4o**（"o"代表 omni）可以端到端地处理文字、图像和语音。

要注意，"原生"或"早期融合"说的是**从预训练一开始就把图文混在一起训练**，并不意味着不用视觉编码器。Llama 4 自称早期融合，图片仍先经过一个基于 MetaCLIP 的视觉编码器，变成连续的向量再送进语言模型；Qwen3-VL 的视觉编码器则是在 SigLIP-2 的基础上，继续用动态分辨率训练得到的。像 Chameleon 那样把图片变成离散 token 的做法，主要用在需要同时生成图片的模型上；只做理解时，离散化会丢掉细节，所以主流仍是"视觉编码器输出连续向量"。

#### 分辨率与 token 数

- 图片的分辨率越高，token 就越多。要看清文档、图表里的小字，必须用高分辨率。
- **动态切片**：把大图切成若干个子图，再加一张缩略图，比如 LLaVA-NeXT 和 InternVL。
- **原生动态分辨率**（Qwen2-VL）：不缩放图片，直接按原始尺寸切块，用二维的位置编码（M-RoPE），再把相邻的 2×2 个块合并成 1 个 token。例如一张 1344×1344 的图片，按 14 像素切块得到 $96\times96 = 9{,}216$ 个块，2×2 合并之后还有 **2,304 个 token**。
- **视频**：先抽取若干帧，再在时间方向上做压缩。视频的 token 数非常大，所以很依赖长上下文的能力（第 9 章）。

#### 数据

| 类型 | 例子 |
|---|---|
| 图片和说明文字的配对 | LAION-5B、DataComp |
| 图文交错的网页文档 | OBELICS、MMC4 |
| OCR、文档、图表数据 | 用来提升"看懂小字"的能力 |
| **重新生成的说明文字** | 网上图片配的文字往往很简短，或者与图片关系不大。所以常用强大的视觉语言模型给图片重新写一段详细的描述，DALL·E 3 就是这样做的 |
| 视觉指令数据 | 由强模型生成，或者由人工标注 |
| 安全过滤 | 第 31 章讲过的 LAION-5B 事件，说明必须做好数据过滤 |

**常用的评测基准**：MMMU（大学水平的多学科多模态题目，约 1.15 万道）、MathVista（视觉数学）、DocVQA（文档问答）、ChartQA（图表问答）、Video-MME（视频理解）。

### 35.4 语音

#### 语音识别：Whisper

Whisper（Radford 等，2022）用**约 68 万小时**弱监督的音频与文字数据训练。它把音频转换成 log-Mel 频谱图（一种表示声音在每个时刻、各个频率上能量的"图像"），按 30 秒一段输入，用编码器–解码器结构，由解码器输出文字。

#### 把语音变成 token

**神经音频编解码器**，比如 SoundStream、EnCodec，用**残差向量量化**（RVQ）把音频压缩成多层离散 token：第一层码本粗略地编码声音；第二层编码第一层留下的误差；依此类推，层数越多，还原的音质越好（{{fig-ch35-rvq}}）。EnCodec 在 24 kHz 的采样率下，每秒产生 75 帧，每帧可以有 2 到 32 层码本，对应 1.5 到 24 kbps 的码率。Kyutai 的 Mimi 编解码器把帧率降到每秒 12.5 帧。

**token 数的问题**：1 分钟的语音，按 12.5 帧/秒、8 层码本计算，就是 6,000 个 token；按 75 帧/秒、8 层，则是 36,000 个。所以要专门设计结构来处理多层码本。比如 Moshi 用一个大 Transformer 处理时间方向，再用一个小 Transformer 依次生成每一帧内的各层码本。

<figure id="fig-ch35-rvq" data-svg="ch35_rvq.svg">
<figcaption>残差向量量化（示意）</figcaption>
</figure>

此外还有两种不同的 token：**语义 token**，比如 HuBERT 特征聚类得到的 token，主要编码"说了什么"；**声学 token**，即编解码器得到的 token，主要编码"声音听起来怎样"。AudioLM（2022）把两者分层结合起来使用。

#### 两种语音助手的架构

| 架构 | 做法 | 特点 |
|---|---|---|
| **级联式** | 语音识别 → 语言模型 → 语音合成 | 实现简单，但延迟高，而且语气、情感这些信息会在转成文字时丢失 |
| **端到端式** | 语言模型直接接收音频 token，并直接输出音频 token | 延迟低，能保留和生成语气、情感，可以随时被用户打断。代表有 GPT-4o 的语音模式；Moshi 是全双工的，可以边听边说，延迟约 200 毫秒；Qwen2.5-Omni 采用"思考者 + 说话者"的结构 |

### 35.5 图像生成：扩散模型

#### 原理

扩散模型的思想来自 Sohl-Dickstein 等（2015），DDPM（Ho 等，2020）让它真正好用。

**前向过程（加噪声）**：分 $K$ 步，每一步往数据里加一点高斯噪声，$K$ 步之后就几乎变成了纯噪声。好在任意第 $k$ 步的状态，可以从原始数据一步算出：

$$
x_k = \sqrt{\bar\alpha_k}\,x_0 + \sqrt{1-\bar\alpha_k}\,\varepsilon, \qquad \varepsilon\sim\mathcal{N}(0, I), \qquad \bar\alpha_k = \prod_{s\le k}(1-\beta_s),
$$

$\beta_s$ 是每一步的噪声强度，$\alpha_k = 1 - \beta_k$。

**训练**：给定加了噪声的 $x_k$ 和步数 $k$，让一个神经网络**预测当初加进去的那份噪声 $\varepsilon$**：

$$
\mathcal{L} = \big\lVert \varepsilon - \varepsilon_\theta(x_k, k)\big\rVert^2.
$$

**采样（去噪）**：从纯噪声出发，一步一步地往回走：

$$
x_{k-1} = \frac{1}{\sqrt{\alpha_k}}\Big(x_k - \frac{\beta_k}{\sqrt{1-\bar\alpha_k}}\,\varepsilon_\theta(x_k, k)\Big) + \sqrt{\beta_k}\,z, \qquad z\sim\mathcal{N}(0, I)\ (\text{最后一步不加 } z).
$$

**直观理解**：预测出来的噪声方向，实际上就是"往数据更密集的地方走"的方向。数学上，它与对数概率密度的梯度（叫 score）成正比，所以扩散模型也被称为基于 score 的模型。

::: experiment
**二维扩散模型。** 数据是二维平面上、分布在半径为 1 的圆周上的点（半径的标准差为 0.05）。用一个小 MLP 预测噪声，训练 4,000 步，然后用 100 步去噪生成 4,000 个点：

| | 半径的均值 | 半径的标准差 | 四个象限中点的占比 |
|---|---|---|---|
| 真实数据 | 1.000 | 0.050 | 0.25, 0.24, 0.25, 0.26 |
| 纯高斯噪声（起点） | 1.237 | 0.645 | 0.25, 0.25, 0.25, 0.25 |
| **DDPM 生成的点** | **0.996** | **0.065** | 0.26, 0.24, 0.20, 0.30 |
:::

从一团杂乱的噪声出发，模型生成的点准确地落回到了圆周上（{{fig-ch35-diffusion}}）。四个象限的覆盖不太均匀（0.20 对 0.30），说明这个小模型训练得还不够充分。

#### 让扩散模型更实用的技术

| 技术 | 做法 |
|---|---|
| **潜空间扩散**（Rombach 等，2022，Stable Diffusion） | 先用一个 VAE 把图片压缩到一个小得多的潜空间（比如 512×512×3 压缩成 64×64×4），在潜空间里做扩散，最后再解码回图片。计算量大大降低 |
| **文字条件** | 用文本编码器（CLIP 或 T5）编码提示词，通过交叉注意力注入去噪网络 |
| **无分类器引导**（CFG，Ho 与 Salimans，2022） | 训练时有一定概率把文字条件丢掉，这样同一个模型既能做有条件的预测，也能做无条件的预测。生成时用 $\tilde\varepsilon = \varepsilon_{\text{无条件}} + w(\varepsilon_{\text{有条件}} - \varepsilon_{\text{无条件}})$，$w$ 大于 1 时，生成的图片会更贴合提示词 |
| **DiT**（Peebles 与 Xie，2022） | 把去噪网络从 U-Net 换成 Transformer，在潜空间的小块上运算。OpenAI 介绍 Sora 时，说它是在"时空小块"上运行的扩散 Transformer |
| **流匹配 / 整流**（2022） | 学习一条从噪声到数据的、尽量**笔直**的路径，用更少的步数就能生成。Stable Diffusion 3 采用了这种方法 |
| 减少采样步数 | DDIM（确定性的采样）、一致性模型等蒸馏方法，可以把步数压缩到 1 到 4 步 |

#### 另一条路线：自回归生成图像

用 VQ-VAE 或 VQGAN 把图片变成离散的 token，再用 Transformer 一个一个地生成，比如 DALL·E 第一代和 Parti。OpenAI 在 2025 年发布 GPT-4o 的图像生成功能时说明，与基于扩散的 DALL·E 不同，它是一个**原生嵌入在 GPT-4o 中的自回归模型**。

#### 统一模型

**Transfusion**（Meta，2024）在同一个 Transformer 中，文字部分用下一个 token 预测的 loss，图片部分用扩散的 loss，两者一起训练；**Janus**（DeepSeek）为"理解图片"和"生成图片"分别使用不同的视觉编码方式，但共用同一个 Transformer。

::: keypoints
1. ViT 把图片切成小块当作 token（336 像素的图、14 像素的块，得到 576 个 token），在大规模数据下胜过卷积网络。
2. CLIP 用对称的 InfoNCE 损失，把图片和文字对齐到同一个空间，可以做零样本分类。实验中，检索准确率从 0.1% 提升到了 99.5%。SigLIP 改用 sigmoid 损失。
3. 视觉语言模型有三种主要架构：LLaVA 式（视觉编码器 + MLP 连接层 + 语言模型，两阶段训练）、交叉注意力式（Flamingo）、原生多模态（Chameleon、Gemini、GPT-4o）。高分辨率的图片和视频会产生大量 token，需要用切片、动态分辨率和 token 合并来处理。
4. 语音：Whisper 负责识别；神经编解码器用残差向量量化把音频变成多层 token；端到端的语音模型（GPT-4o、Moshi）延迟低，而且能保留语气和情感。
5. 扩散模型训练网络去预测噪声，采样时一步一步去噪。实验中，生成的点的半径为 0.996，真实数据为 1.000。潜空间扩散、无分类器引导、DiT 和流匹配让它变得实用；此外还有自回归的图像生成，以及 Transfusion 这样的统一模型。
:::

2. **推导**：写出 CLIP 对称 InfoNCE 损失的完整公式。为什么 batch 越大，对比学习的效果往往越好？

4. **计算**：Mimi 编解码器每秒 12.5 帧，每帧 8 层码本。一段 10 分钟的语音对话会产生多少个 token？这对上下文长度和推理成本意味着什么？

:::
