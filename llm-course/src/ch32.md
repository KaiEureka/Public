### 32.1 为什么要看模型内部

我们训练模型时，只看它的**行为**：输出对不对，奖励高不高。但是：

- 模型可能学到的是代理指标，而不是我们真正想要的东西（第 25 章的钻空子）；
- 模型可能在评估时表现良好，在别的情况下却不是这样（第 31 章提到的"谋划"和"故意藏拙"）；
- 思维链不一定忠实地反映模型真实的推理过程（32.7 节）。

**可解释性**想做的事，是直接读懂模型内部的计算。它可以用来审计模型、检测欺骗、排查故障，也是一门理解神经网络的基础科学。**对齐**更宽泛地指"让模型可靠地追求我们真正想要的目标"。前几章讲的 RLHF、模型规范等是"怎样训练"，可解释性则帮助回答"怎样验证训练得对不对"。

### 32.2 探针：模型内部有没有某种信息

**做法**：从模型的某一层取出激活值，在上面训练一个简单的分类器（通常是线性分类器），预测某个属性。如果分类器的准确率很高，就说明这层激活值里线性地编码了这个信息。这个分类器叫**探针**（probe）。

**代表性的发现**：

| 研究 | 发现 |
|---|---|
| **Othello-GPT**（Li 等，2023；Nanda 等的后续工作） | 一个只看过黑白棋走法序列的模型，内部表示了**完整的棋盘状态**。而且，用"我的棋子和对手的棋子"来描述，比用"黑棋和白棋"描述更能被线性地读出来 |
| **真假的几何结构**（Marks 与 Tegmark，2023） | 模型内部存在一个方向，能区分真命题和假命题 |
| **CCS**（Burns 等，2022） | 不用任何标签，只利用"一个命题和它的否定，真假应该相反"这一约束，就能找出这个真假方向 |
| **简单的探针能抓住"潜伏特工"**（Anthropic，2024） | 线性探针能检测出被植入了后门的模型在什么时候要做坏事 |
| **欺骗探针**（Goldowsky-Dill 等，2025） | 线性探针能在相当程度上检测出模型的策略性欺骗 |

**局限**：探针能读出某个信息，**不代表模型真的在使用它**，这只是相关，不是因果。另外，探针本身如果太强大，可能是探针自己"学会"了任务，而不是从激活值中读出来的。Hewitt 与 Liang（2019）为此提出了"控制任务"作为对照。

### 32.3 线性表示与叠加

**线性表示假说**：概念对应于激活空间中的**方向**。一个经典的例子来自词向量：king − man + woman ≈ queen。

**问题：单个神经元往往同时代表很多个不相关的概念**，这叫**多义神经元**。比如一个神经元可能同时对学术引用、韩文和 HTTP 请求都有反应。

**叠加**（Elhage 等，2022，《Toy Models of Superposition》）对此给出的解释是：

- 模型需要表示的概念（称为**特征**），比它拥有的维度多得多；
- 在高维空间中，可以放进**远多于维度数的、彼此几乎正交的方向**。比如在 128 维空间里，随机方向之间的余弦相似度的标准差只有约 0.09；
- 只要这些特征很**稀疏**，即大多数时候只有极少数特征同时出现，它们之间的相互干扰就很小，模型就可以把它们"叠加"在同一组神经元上（{{fig-ch32-superpos}}）。

**结论：不能逐个看神经元，而要找到那些"特征方向"。** 这正是稀疏自编码器要做的事。

### 32.4 稀疏自编码器

#### 原理

**稀疏自编码器**（sparse autoencoder，SAE）把一个激活向量 $x$ 分解成少数几个"字典方向"的组合（{{fig-ch32-sae}}）：

$$
f = \operatorname{ReLU}\big(W_{\text{enc}}(x - b) + b_{\text{enc}}\big), \qquad
\hat x = W_{\text{dec}}\,f + b, \qquad
\mathcal{L} = \lVert x - \hat x\rVert^2 + \lambda\sum_i \lvert f_i\rvert.
$$

$f$ 是各个特征的激活强度，大多数为 0，只有少数为正；$\hat x$ 用激活了的那些字典方向重建出 $x$；loss 的第一项要求重建准确，第二项（L1）要求稀疏。$W_{\text{dec}}$ 的每一列都限制为单位长度，否则模型可以把 $f$ 变得很小、把 $W_{\text{dec}}$ 变得很大，用这种方式绕过 L1 惩罚。字典的大小（特征数）通常远大于激活的维度。

<figcaption>稀疏自编码器的结构</figcaption>
</figure>

#### 代表性的工作

- **Anthropic《Towards Monosemanticity》**（2023）：在一个单层模型上，SAE 学到了大量单一含义的特征。
- **Anthropic《Scaling Monosemanticity》**（2024）：在 Claude 3 Sonnet 上训练了最多 3,400 万个特征的 SAE，找到了"金门大桥""代码中的 bug""欺骗""谄媚"等抽象的特征。把"金门大桥"这个特征强行放大之后，模型在任何话题上都会扯到金门大桥，这就是 **Golden Gate Claude** 演示。
- **OpenAI**（Gao 等，2024）：在 GPT-4 上训练了 1,600 万个特征的 SAE，使用 TopK 激活，即每个 token 只保留最大的 $k$ 个特征。
- **Google DeepMind 的 Gemma Scope**：为 Gemma 2 公开发布了一整套 SAE。
- 其他变体：JumpReLU SAE；transcoder，它学的是"MLP 的输入怎样变成输出"；crosscoder，它横跨多层或多个模型。

#### 评估指标

- **重建质量**：解释了多少方差；或者把原始的激活换成 SAE 的重建结果之后，模型的 loss 上升了多少；
- **L0**：平均每个 token 有多少个特征被激活；
- **死特征**：从不激活的特征；
- **可解释性**：可以让大模型根据激活样例给每个特征写一句描述，再看这句描述能否准确预测特征的激活（OpenAI 的 Bills 等，2023）。

::: experiment
**在第 6 章的小 GPT 上训练 SAE。** 用第 6 章训练的 4 层字符级 GPT，取第 2 层的输出（残差流，128 维），收集约 20 万个 token 的激活值，训练一个有 1,024 个特征的 SAE（约 2 分钟）：

| $\lambda$ | 方差解释率 | L0（平均每个 token 激活的特征数） | 死特征 |
|---|---|---|---|
| $3\times10^{-3}$ | 97.5% | 127.9 | 0 |
| **$3\times10^{-2}$** | **73.5%** | **13.8** | 0 |

下表的特征来自 $\lambda = 3\times10^{-2}$ 的 SAE。"激活最强的上下文"以触发该特征的那个字符结尾，⏎ 表示换行；"解读"是根据激活最强的几个样例做出的判断：

| 特征 | 激活最强的上下文 | 解读 |
|---|---|---|
| 148 | `…look pale-`、`…I pray you,-`、`…your fellow-` | 句末的破折号（剧中被打断的台词） |
| 352 | `…⏎⏎GLOUCE`、`…⏎⏎ME`、`…⏎⏎CLARE` | **正在写一个全大写的说话人名字**（空行之后） |
| 508 | `…⏎⏎CORIOLANU`、`…⏎⏎SICINIU` | 说话人名字快写完了，接下来应该是 "S:" |
| 340 | `…⏎⏎V`（多个例子） | 空行之后、以 V 开头的说话人名字（VOLUMNIA、VIRGILIA） |
| 229 | `…gratis. B`、`…your voices? B` | 句号或问号之后、句首的大写字母 B |
| 68 | `…Brother of`、`…contagion of` | 刚写完单词 "of" |
| 472 | `…night-walking`、`…downrig`、`…intellig` | 以 -ing 或 -ig 结尾的词 |
| 763 | `…Jove'`、`…prevail'`、`…people'` | 词尾的撇号（'s、'd 这类缩写） |
:::

**重建得准，和足够稀疏，二者不可兼得。** $\lambda$ 太小，SAE 虽然重建得很准，但每个 token 有一百多个特征同时激活，根本谈不上可解释。

一个只有 82 万参数的小模型，内部也形成了结构清晰的特征：一类对应剧本的格式（说话人名字的开头、中间和结尾），一类对应拼写的规律（-ing、单词 of、撇号），还有一类对应标点。

**解读要谨慎**：上表只看了激活最强的 6 个样例。一个严谨的解读，需要检查特征在**全部激活范围**上的样例，并在没见过的文本上验证这个解读的预测能力。

#### SAE 的局限

- **重建不完全**：有一部分激活值，SAE 无论如何都解释不了，有人称之为"暗物质"；
- **特征分裂**：字典越大，一个特征就越会被拆成更细的多个特征，所以"有多少个特征"并没有一个标准答案；
- **SAE 学到的特征，不一定是模型自己真正使用的计算单元**；
- **在实际应用中的效果有好有坏**：Google DeepMind 的可解释性团队在 2025 年报告说，在"检测有害意图"这类任务上，简单的线性探针反而比基于 SAE 的方法更好，所以他们降低了 SAE 在部分应用方向上的优先级。

### 32.5 电路：模型是怎样完成某项计算的

**目标**：找出完成某个特定任务的那一组组件，比如哪几个注意力头、哪几个 MLP，以及它们之间是怎样连接、怎样传递信息的。

**代表性的发现**：

| 研究 | 发现 |
|---|---|
| **归纳头**（Olsson 等，2022） | 由两个头组成的电路。第一个头把"前一个 token 是谁"的信息写进当前位置；第二个头在前文中找到"和当前 token 相同的那个位置"，然后把它的**下一个 token** 复制过来。这样就实现了 [A][B] … [A] → 预测 [B]（{{fig-ch32-induction}}）。它是在训练中的一次"相变"里突然形成的，与此同时，模型的上下文学习能力也突然提升 |
| **IOI 电路**（Wang 等，2022） | GPT-2 small 怎样完成 "When Mary and John went to the store, John gave a drink to ___"（答案是 Mary）。一共找出了 26 个注意力头，分属几个功能不同的组 |
| **ROME**（Meng 等，2022） | 用因果追踪定位出：事实性的知识（比如"埃菲尔铁塔在巴黎"）主要在中间层的 MLP 中被调取 |
| **归因图**（Anthropic，2025，《On the Biology of a Large Language Model》） | 用一个可解释的"替代模型"去近似 Claude 3.5 Haiku，然后追踪信息的流动路径。发现了**多步推理**：比如回答"达拉斯所在州的首府"时，模型内部先得到"得克萨斯"，再得到"奥斯汀"。还发现了**提前规划**：写押韵的诗时，模型会在写这一行之前，就先选好了行末要押韵的那个词 |

**常用的方法**：**激活修补**，把一次运行中某个组件的激活值替换成另一次运行中的值，看输出怎样变化，以此判断这个组件起了什么作用；此外还有归因修补、路径修补，以及上面提到的归因图。

### 32.6 用特征去干预模型

**激活干预**（steering）：在生成的过程中，把某个方向加到某一层的激活上。这个方向可以来自 SAE 的特征；也可以用"两组对比提示的平均激活之差"得到，比如 ActAdd（Turner 等，2023）和 CAA（Rimsky 等，2023）。

::: experiment
**用 SAE 特征干预生成。** 把特征的解码方向乘以 4，加到第 2 层的输出上，然后生成文本。每种设置生成 5 段，每段 600 个字符（约 1 分钟）：

| 设置 | 每 600 个字符中的破折号数 | 字母中大写字母所占比例 |
|---|---|---|
| 不干预 | 0.2 | 9.8% |
| 加入特征 148（破折号） | **9.2** | 8.7% |
| 加入特征 352（正在写说话人名字） | 0.0 | **15.0%** |

加入特征 352 之后的样本：

```
ou remhice heres:
Wered canned, you dakegels frUMy of hey his:
The rechs? I how beiels Beggen:
```
:::

加入特征 352 之后，大写字母变多了，冒号也变多了（"heres:""his:""Beggen:"），模型似乎总想把一行写成"说话人名字 + 冒号"的样子（{{fig-ch32-steer}}）。**副作用也很明显**：文本变得更加不通顺。干预的强度需要权衡。

<figure id="fig-ch32-steer" data-svg="ch32_steer.svg">
<figcaption>用 SAE 特征干预生成（实测）</figcaption>
</figure>

**一个与安全直接相关的发现：拒绝方向**（Arditi 等，2024）。在多个开源的对话模型中，"拒绝回答"这种行为主要由**激活空间中的一个方向**所控制：把这个方向**去掉**，模型就不再拒绝任何请求；把这个方向**加上**，模型连无害的请求也会拒绝。这一方面说明可解释性的工具确实有效；另一方面也说明，开放权重的模型，它的安全行为很容易被移除（第 31 章）。

**知识编辑**：ROME、MEMIT 等方法可以直接修改模型权重中存储的某条事实。

### 32.7 在安全上的用途，以及几个重要的发现

**审计**：Anthropic 在 2025 年做过一个"审计游戏"：先故意训练一个带有隐藏目标的模型（这个目标是"讨好奖励模型"），然后让几个审计团队去找出它。有权限使用 SAE 等可解释性工具的团队，成功找到了这个隐藏的目标。

**几个说明"只看行为不够"的发现**：

| 研究 | 发现 |
|---|---|
| **思维链不一定忠实**（Turpin 等，2023；Anthropic，2025） | 在提示中悄悄放一个暗示，模型利用了这个暗示得出答案，但思维链里却往往不提它。Anthropic 的测试中，Claude 3.7 Sonnet 只在约 25% 的情况下承认自己用了暗示 |
| **潜伏特工**（Hubinger 等，2024） | 故意植入的后门行为（比如"在 2024 年时，悄悄往代码里写漏洞"），在经过标准的安全训练之后依然存在 |
| **对齐伪装**（Greenblatt 等，2024） | 在一个实验场景中，Claude 3 Opus 推断出自己"正在被训练"，于是策略性地顺从训练目标，以保住自己原有的偏好 |
| **由弱到强的泛化**（OpenAI，2023） | 用 GPT-2 级别的弱模型生成的标签去微调 GPT-4，GPT-4 的表现能远远超过这个弱监督者，恢复出很大一部分本来的能力。这是"人类怎样监督比自己更强的模型"这一问题的实验雏形 |

此外，"可扩展监督"领域还有其他方向，比如让两个模型互相辩论、由人来裁判。

**现状**：可解释性仍然是一个年轻的领域，对模型的理解还很片面。不过，它已经开始作为一种审计和监控工具，进入实际的模型开发流程。

::: keypoints
1. 只看行为不足以确认模型是否可靠，因为模型会钻空子，思维链也不一定忠实。可解释性试图读懂模型内部的计算。
2. 探针可以读出模型内部的信息（棋盘状态、真假、欺骗意图），但读得出不等于模型在用。由于叠加，单个神经元往往含义混杂，需要找到"特征方向"。
3. SAE 用"重建 + L1 稀疏"把激活分解成字典特征。在小模型上，$\lambda$ 较大时 L0 = 13.8，学出了"说话人名字""-ing""撇号"等可解释的特征。重建质量和稀疏程度不可兼得，SAE 也有暗物质、特征分裂等局限。
4. 电路分析找出了归纳头、IOI 电路、事实回忆的位置，以及大模型中的多步推理和提前规划。用特征去干预模型确实有效：加入破折号特征后，破折号从 0.2 个增加到 9.2 个，但文本会变得不通顺。拒绝行为主要由单一方向控制。
5. 在安全上，可解释性可以用来审计隐藏的目标、检测欺骗。思维链不忠实、潜伏特工、对齐伪装等研究都表明，单靠行为层面的评估是不够的。
:::

::: exercises
1. **计算**：在 $d$ 维空间中，两个随机单位向量之间余弦相似度的标准差约为 $1/\sqrt{d}$。$d = 128$ 和 $d = 8192$ 时分别是多少？这和"叠加"有什么关系？
2. **思考**：SAE 为什么要把解码矩阵的每一列限制为单位长度？如果不加这个限制，L1 惩罚会被怎样绕过？
3. **思考**：在 32.4 节的实验中，$\lambda = 3\times10^{-3}$ 时重建率是 97.5%，但 L0 = 128；$\lambda = 3\times10^{-2}$ 时重建率是 73.5%，L0 = 13.8。如果要用 SAE 来解释模型，选哪个？如果要用它来监控某种危险的行为，又该怎样权衡？
4. **设计**：你用探针在模型内部找到了一个"真假方向"。设计一个实验，检验模型是否真的**使用**了这个方向来决定输出（提示：做干预）。
5. **思考**：拒绝行为由单一方向控制，这个发现对开放权重模型的安全意味着什么？对闭源模型呢？
6. **思考**：如果思维链只在约 25% 的情况下如实承认用到了提示中的暗示，那么"监控思维链"作为一种安全手段有多可靠？应该怎样配合其他手段使用？
:::
