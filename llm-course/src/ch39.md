#### 2017 年第一季度：搭班子，下订单，启动数据

**组织**：成立公司，按第 36 章的顺序招人，先招基础设施、数据、预训练和评测的负责人；从 HPC 领域招系统工程师，从搜索引擎公司招爬虫和数据工程师（第 37 章）。

**硬件**：买入 256 到 1,000 张 P100（DGX-1），用于研究；开始规划 6 到 10 MW 的机房、InfiniBand EDR 网络和并行存储；V100 一发布就立即锁定供货（第 37 章）。

**数据**（只需要 CPU，所以立刻开始）：处理 Common Crawl，包括正文提取、fastText 语言识别、Gopher 规则、按快照做 MinHash 去重（第 15 章）；抓取 GitHub 和 arXiv；启动"购买实体书并扫描"的项目；招募专家，**建立不公开的评测集**（第 38 章）。

**软件**：在 PyTorch 上搭建 FP16 混合精度训练（带 loss scaling），实现基于 NCCL 2 或 MPI 的数据并行；搭建评测框架。

**研究**：实现 decoder-only 的 Transformer，组件一步到位：Pre-RMSNorm、RoPE、SwiGLU、GQA、QK-norm、z-loss；训练字节级 BPE 分词器，约 10 万词表，预留特殊 token；在 1,000 万到 10 亿参数的规模上，确认 loss 曲线符合预期。

#### 2017 年第二季度：在小规模上把科学问题都弄清楚

- **规模阶梯**：在 P100 集群上，用 $10^{18}$ 到 $10^{20}$ FLOP 的计算量，拟合出自己的 scaling law，以及学习率和 batch 随规模变化的规律，或者直接采用 μP（第 10、11 章）；
- **FP16 稳定性测试**：用"小模型 + 偏高的学习率"，验证每一项防御措施（第 12、38 章）；
- **数据**：训练第一版质量分类器；用 1B 的模型做数据消融实验（第 16 章）；
- **系统**：实现张量并行、流水线并行（1F1B 加交错调度）、ZeRO-1、激活重计算、分块注意力内核、融合内核、异步检查点、健康检查（第 20 到 23 章）。

#### 2017 年第三、四季度：V100 到货，开始第一次正式训练

- **集群上线**：老化测试、通信带宽测试，替换坏节点（第 18 章）；
- **去风险训练**：比如用约 1T token 训练一个 7B 模型。它既是对整套系统的演练，也是之后蒸馏和标注数据要用的工具模型；
- **第一代正式训练**：70B 稠密模型，1.4T token，在 4,096 张 V100 上大约 7 周（第 38 章）；
- **后训练 v1**：专家编写的 SFT 数据，加上迭代 DPO（第 24、26 章）；
- **推理引擎**：KV cache、continuous batching、分页管理 KV cache、INT8 量化（第 33、34 章）；
- **安全**：制定模型规范，做红队测试（第 31 章）。

**作为对照**：历史上，Transformer 是 2017 年 6 月才发表的；GPT-1 在 2018 年 6 月发布，只有 1.17 亿参数。

#### 2018 年：发布第一代，然后用它反哺自己

- **第一季度**：发布第一代 70B 的对话模型。作为参照，Chinchilla 70B 的 MMLU 是 67.5%，再加上更好的数据（更多代码和数学）和现代的后训练方法，**推测**它能达到 2023 年 Llama 2 70B 或 GPT-3.5 左右的水平。历史上，这个水平要到 2022 年底才出现。
- **用第一代模型反哺**：像 FineWeb-Edu 那样用它给数据打分（第 16 章）；生成合成数据（第 17 章）；做拒绝采样，扩充 SFT 数据（第 24 章）；蒸馏出便宜的小模型，用于产品（第 29 章）。
- **在数学和代码上做 RLVR**：搭建强化学习的基础设施和沙箱环境。在 70B 的基座上，推理能力的提升可能比较有限（第 27 章讲过，R1-Zero 依赖一个很强的基座），但能积累长思维链数据和工程经验。
- **扩充硬件**：2018 年 3 月起采购 32 GB 的 V100；第三季度起采购 DGX-2（NVSwitch 全互联），为第二代的 MoE 做准备；把集群扩大到 1 万到 2.5 万张卡。
- **为第二代做准备**：在小规模上验证 MoE；扩充数据（书籍、代码、多语言）。

#### 2019 年：第二代 MoE，推理模型

- **第二代正式训练**：MoE，约 $3\times10^{24}$ FLOP。在 1 万张 V100 上约 3 个月，2.5 万张上约 6 周。采用 FP16 下的各项防御措施、DualPipe 式的通信与计算重叠，每个 token 最多发往 2 台机器（第 38 章）；
- **长上下文扩展**：用 YaRN，扩展到 32K 再到 128K（第 9 章）；
- **完整的 R1 式后训练**：冷启动 SFT → 推理 RL（GRPO）→ 拒绝采样再 SFT → 全场景 RL → 蒸馏到小模型（第 27、29 章）；
- **工具使用与 Agent**（第 28 章）；
- **安全**：建立 RSP 式的框架，做危险能力评估（第 31 章）。

#### 2020 年以后

A100 在 2020 年 5 月发布：支持 bf16，每卡 40 GB 或 80 GB 显存，NVLink 带宽 600 GB/s，配 HDR 200G 网络。前面所有受 FP16 和显存限制的设计，到这时都可以放开。2022 年的 H100 又带来了 FP8。

#### 总体判断

只要执行得当，**有望把历史进程提前约 3 到 5 年**。但最终能做到什么程度，受三件事制约：当时的硬件（FP16、16 GB 显存）；当时的数据总量（网上的文本更少）；工程团队把这些系统写出来要花的时间。在这些约束下，2019 年前后能否达到今天 DeepSeek-V3 加 R1 的水平，**是不确定的**。

### 39.2 要跳过的历史弯路

| 弯路 | 正确的方向 | 章 |
|----------------------|----------------------|-----|
| 继续扩大 RNN/LSTM，或者用卷积做序列模型 | 直接用 decoder-only 的 Transformer | 6 |
| 把 BERT 式的"编码器 + 针对每个任务微调"作为主线；T5 式的编码器–解码器 | 只用一个因果模型，靠预训练加后训练解决所有任务 | 6、24 |
| 原始 Transformer 的 Post-LN、可学习或正弦的位置编码、预训练中使用 dropout | Pre-RMSNorm、RoPE、不用 dropout | 3、7 |
| 按 Kaplan 的建议，做参数过多、数据不足的大模型（GPT-3 175B 只训 300B token，MT-NLG 530B） | 按 Chinchilla 配比训练；考虑推理成本时就过度训练 | 10 |
| 训练中不加 QK-norm 和 z-loss，FP16 下溢出 | 从第一天起就加上 | 12、13 |
| 分词器不预留特殊 token，多语言覆盖不足 | 字节级 BPE，约 10 万词表，提前预留 | 5 |
| C4 式过于激进的规则（花括号、脏话词表）；跨所有快照做全局去重 | 用消融实验确定规则，检查被删掉的数据；在每个快照内部去重 | 15 |
| 一开始就上复杂的 PPO（需要单独训练 critic） | 先 SFT 加 DPO；推理能力用 GRPO | 25–27 |
| 过程奖励模型加 MCTS 的推理路线 | 结果奖励加大规模强化学习 | 27 |
| 部署巨大的稠密模型来提供服务 | MoE 加蒸馏加量化 | 8、29、34 |
| 评测不去污染，只信单一的排行榜 | 不公开的评测集、误差棒、多层评测体系 | 17、30 |
| 等发布前才考虑安全 | 安全从一开始就融入流程 | 31 |

### 39.3 必须背下来的数字与公式

以下按主题整理，附录 B 有更完整的版本。

#### 计算、显存与硬件

| 内容 | 数字或公式 |
|----------|------------------------------|
| 训练计算量 | $C \approx 6ND$（MoE 用激活参数）；注意力每层每 token 额外约 $12Td$（训练时，前向加反向） |
| 推理计算量 | 每个 token 约 $2N$；decode 每一步的耗时 $\ge$ 权重字节数 ÷ 显存带宽 |
| 训练显存 | 每个参数 16 字节；ZeRO-3 后为 $16\Psi/n$ |
| 激活值 | 每层约 $34Tbd$ 字节（使用 FlashAttention）；重新计算后约 $2Tbd$，计算量多 33% |
| KV cache | 每个 token 为 $2\times L\times n_{kv}\times d_h\times$ 字节数 |
| 参数量 | 每层约 $12d^2$；SwiGLU 的隐藏层宽 $\frac83 d$ 时参数量不变 |
| H100 | BF16 989 TFLOP/s，显存 3.35 TB/s、80 GB，NVLink 单向 450 GB/s，每卡跨机 50 GB/s，平衡点约 295 FLOP/字节 |
| V100 | FP16 125 TFLOP/s，显存 0.9 TB/s、16/32 GB |
| 算术强度 | $(B\times K)\cdot(K\times N)$ 的算术强度约等于 $B$；MFU 达到 40% 就算优秀 |

#### 规模与超参数

| 内容 | 数字或公式 |
|----------|------------------------------|
| Chinchilla | $D \approx 20N$；$L = E + A/N^\alpha + B/D^\beta$；$N_{\text{opt}}\propto C^{\beta/(\alpha+\beta)}$ |
| 数据重复 | 不超过约 4 遍 |
| 初始化 | 初始 loss 约为 $\ln V$；标准差约 0.02，残差分支的输出层再乘 $1/\sqrt{2L}$；tanh 增益 5/3，ReLU 增益 $\sqrt2$ |
| 优化器 | AdamW，$\beta = (0.9, 0.95)$，$\epsilon = 10^{-8}$，权重衰减 0.1，梯度裁剪 1.0 |
| 学习率 | warmup 加余弦衰减到 10%，或者 WSD；模型越大，学习率越小（GPT-3：125M 用 6e-4，175B 用 6e-5） |
| batch | 几百万 token |
| μP | 隐藏层的学习率与 $1/\text{宽度}$ 成正比 |
| 架构参数 | 注意力分数除以 $\sqrt{d_h}$；$d_h = 128$；$d/L$ 约为 100 到 130；RoPE base 从 1e4 到 5e5；词表 10 万到 26 万 |

#### 并行与运维

| 内容 | 数字或公式 |
|----------|------------------------------|
| 环形 all-reduce | 每张卡发送 $2(n-1)S/n$ |
| ZeRO-3 | 通信量是数据并行的 1.5 倍 |
| FSDP 藏住通信 | 每卡每步至少处理 $F/\text{BW}$ 个 token，H100 跨机时约 8,000 |
| 张量并行 | 放在机器内部 |
| 流水线气泡 | $(p-1)/(m+p-1)$ |
| 检查点间隔 | $\tau^* = \sqrt{2c/\lambda}$ |

#### 数据与精度

| 内容 | 数字或公式 |
|----------|------------------------------|
| MinHash + LSH | 候选概率 $P = 1 - (1 - J^r)^b$，转折点约为 $(1/b)^{1/r}$ |
| FineWeb 的经验 | 在每个快照内部去重 |
| 精度 | FP16 最大值 65,504；BF16 在 1 附近的相对间隔约 $2^{-7}$；FP8 E4M3 最大值 448；细粒度缩放用 $1\times128$ 和 $128\times128$ 的块 |

#### 后训练、推理与评测

| 内容 | 数字或公式 |
|----------|------------------------------|
| 奖励模型（Bradley-Terry） | $\mathcal{L} = -\log\sigma(r_w - r_l)$ |
| RLHF 的最优策略 | $\pi^*\propto\pi_{\text{ref}}\,e^{r/\beta}$ |
| DPO | $\mathcal{L} = -\log\sigma\big(\beta\cdot[\text{对数概率比之差}]\big)$ |
| GRPO | 优势 = (奖励 − 组内均值) / 组内标准差；PPO 的裁剪参数 $\epsilon = 0.2$ |
| MoE 辅助损失 | $\alpha E\sum_i f_iP_i$ |
| 投机解码 | 以 $\min(1, p/q)$ 的概率接受；每次调用期望产生 $(1-\alpha^{\gamma+1})/(1-\alpha)$ 个 token |
| pass@$k$ 的无偏估计 | $1 - \binom{n-c}{k}/\binom{n}{k}$ |
| 评测的标准误差 | $\sqrt{p(1-p)/n}$ |

#### 参照点

| 模型 | 数字 |
|----------|------------------------------|
| GPT-3 | $3.1\times10^{23}$ FLOP |
| Llama 3 405B | $3.8\times10^{25}$ FLOP，1.6 万张 H100，MFU 41%，54 天里中断 466 次 |
| DeepSeek-V3 | $3.3\times10^{24}$ FLOP，278.8 万 H800 卡时 |

### 39.4 毕业设计

**A. 纸上项目**：闭卷写一份 15 到 20 页的《2017 复现手册》，覆盖组织和预算、硬件和集群、数据流水线、模型架构和分词器、scaling 研究方案、精度和稳定性、并行方案、需要开发的系统、预训练和后训练的配方、评测与安全、推理部署、季度路线图、风险清单。每一个决定都要给出数字依据。

**B. 动手项目**（如果将来有算力）：用一台 8 卡的机器，从零走完整条流程：

1. 训练分词器；
2. 在 FineWeb-Edu 上预训练一个约 5 亿到 10 亿参数的模型，用 100 亿到 300 亿 token；
3. 做 SFT；
4. 在 GSM8K 上做 GRPO；
5. 评测；
6. 用带 KV cache 的推理引擎提供服务。

Karpathy 在 2025 年 10 月发布的开源项目 **nanochat** 就是这样一套完整流程，在 8 张 H100 上大约 4 小时、花费约 100 美元就能跑完，可以作为参照。

::: keypoints
1. 路线图的核心顺序是：数据流水线与团队立即启动 → 小规模上把 scaling、超参数和 FP16 稳定性弄清楚 → 2017 年底用 V100 训练第一代稠密模型 → 2018 年用第一代反哺数据并扩充硬件 → 2019 年训练第二代 MoE，并做 R1 式的后训练。
2. 穿越者最大的价值是跳过弯路：不走 RNN、BERT 主线和 Post-LN，不做"参数多、数据少"的大模型，不走 PRM + MCTS，不一开始就上 PPO，评测从第一天起就去污染、不公开，安全从第一天起就融入流程。
3. 必须记住的数字集中在计算（$6ND$、16 字节/参数、KV cache 公式）、规模（$D\approx20N$、4 遍重复）、超参数（AdamW 0.9/0.95、0.1、1.0）、并行（$2(n-1)S/n$、$(p-1)/(m+p-1)$、$F/\text{BW}$）和后训练（BT、DPO、GRPO、投机解码）几类。
4. 有望把历史进程提前 3 到 5 年，但受当时的硬件、数据总量和工程时间的制约，结果并不确定。
:::
