### 6.1 要解决的三个问题

| 问题 | 来源 |
|---|---|
| ① MLP 把上下文直接拼接起来，每个位置都用自己独立的一套权重，也没法挑出相关的位置。结果上下文越长，效果反而越差 | 第 2 章 |
| ② GPU 只有在做大矩阵乘法时才快，逐个 token 串行处理的效率很低 | 第 4 章 |
| ③ 训练时希望一次前向计算就能同时得到每个位置的预测 | 第 1 章 1.3 节 |

### 6.2 上一代方案：RNN 及其缺陷

**RNN**（循环神经网络）从左到右逐个读入 token，维护一个"记忆向量" $h$，每一步都用同一套权重：

$$
h_t = \tanh(W_h h_{t-1} + W_x x_t).
$$

- **优点**：所有位置共享同一套权重，部分解决了问题 ①。理论上它能记住无限长的上下文。
- **缺点一，信息瓶颈**：前面所有内容都必须挤进一个固定大小的向量 $h$。
- **缺点二，梯度问题**：梯度要穿过很多步才能传回去，容易消失或爆炸（第 3 章）。它的改进版 LSTM 缓解了这个问题，但没有根除。
- **缺点三，无法并行**：第 $t$ 步必须等第 $t-1$ 步算完。每一步只是一次矩阵乘向量，算术强度约为 1（第 4 章），这正好违反了问题 ②。

2014 年，Bahdanau 等人在用 RNN 做机器翻译时加入了**注意力**：生成每个词时，允许模型回头查看输入中所有位置的状态，而不必完全依赖 $h$。2017 年的论文《Attention Is All You Need》（Vaswani 等）更进一步：**干脆去掉循环，只保留注意力**（{{fig-ch06-rnn}}）。这就是 Transformer。

### 6.3 注意力的直觉：按内容检索

预测下一个字符时，真正有用的信息往往集中在前文的某几个位置上：

- 在一个单词内部，最有用的是前面几个字母；
- 在剧本里，需要知道当前说话的人是谁，而人名出现在很多行之前；
- 遇到右引号时，需要找到与它配对的左引号。

所以我们需要这样一种机制：**每个位置都能按"内容相关程度"给前面所有位置分配权重，再把这些位置的信息加权平均；而且所有位置都使用同一套参数。**

可以把它类比为查字典，只不过是"软"的查法：每个位置提出一个问题，叫 **query**；每个位置挂出一个标签，叫 **key**；每个位置还准备好一份内容，叫 **value**。query 和哪些 key 匹配得越好，就从对应的 value 里取得越多。

### 6.4 单头注意力：逐步推导

设 $X$ 是一个 $T\times d$ 的矩阵，第 $i$ 行是第 $i$ 个位置的向量，$T$ 是序列长度，$d$ 是模型宽度。

**第 1 步：生成 query、key、value。** 用三个可学习的矩阵 $W_q, W_k, W_v$，形状都是 $d\times d_h$：

$$
Q = XW_q,\quad K = XW_k,\quad V = XW_v \qquad (\text{都是 } T\times d_h).
$$

**第 2 步：计算相关度分数。**

$$
S = \frac{QK^\top}{\sqrt{d_h}} \qquad (T\times T).
$$

$S_{ij}$ 是 $q_i$ 和 $k_j$ 的点积，表示"位置 $j$ 对位置 $i$ 有多相关"。

为什么要除以 $\sqrt{d_h}$？如果 $q$ 和 $k$ 的每个分量都是独立的、方差为 1 的随机数，那么它们的点积是 $d_h$ 项之和，方差为 $d_h$。$d_h = 64$ 时，分数的标准差是 8，softmax 会变得极度尖锐，几乎饱和，梯度就消失了（与第 3 章讲的饱和是同一个道理）。除以 $\sqrt{d_h}$ 之后，方差回到 1。

**第 3 步：因果掩码**（causal mask）。位置 $i$ 只能看到 $j \le i$ 的位置，否则它会直接看到自己要预测的答案（目标是预测下一个 token）。做法是把 $j > i$ 的分数设成 $-\infty$，经过 softmax 后权重就变成 0。

**第 4 步：softmax 并加权求和。**

$$
A = \operatorname{softmax}(S) \;(\text{每一行分别做 softmax，每行之和为 1}), \qquad O = AV \;(T\times d_h).
$$

每个位置得到的是前文 value 的加权平均。合起来写就是

$$
\operatorname{Attention}(Q, K, V) = \operatorname{softmax}\Big(\frac{QK^\top}{\sqrt{d_h}} + M\Big)V,
$$

其中掩码矩阵 $M$ 在 $j > i$ 处为 $-\infty$，其余为 0（{{fig-ch06-mask}}）。

<figure id="fig-ch06-mask" data-svg="ch06_mask.svg">
<figcaption>注意力矩阵的计算过程：分数加上因果掩码，再逐行做 softmax。−∞ 经过 softmax 变成 0，所以右上角全是空白</figcaption>
</figure>

**一个手算的例子**（示意，$d_h = 2$）。位置 3 的 query 是 $q = [1, 0]$，三个位置的 key 和 value 如下：

| 位置 $j$ | $k_j$ | $q\cdot k_j/\sqrt2$ | softmax 权重 | $v_j$ |
|---|---|---|---|---|
| 1 | [2, 0] | 1.414 | **0.576** | [10, 0] |
| 2 | [0, 1] | 0 | 0.140 | [0, 10] |
| 3 | [1, 1] | 0.707 | 0.284 | [5, 5] |

输出 $= 0.576\times[10, 0] + 0.140\times[0, 10] + 0.284\times[5, 5] = [7.18,\ 2.82]$。位置 1 的 key 与 query 最匹配，所以它贡献得最多（{{fig-ch06-qkv}}）。

<figure id="fig-ch06-qkv" data-svg="ch06_qkv.svg">
<figcaption>注意力是“软”的查字典：query 和每个 key 打分，softmax 变成权重，再按权重混合 value</figcaption>
</figure>

**这个设计怎样解决 6.1 节的三个问题？**

- 所有位置共用 $W_q, W_k, W_v$，解决了"每个位置一套权重"的问题 ①；权重由内容动态决定，远处的位置只要相关，也能获得很高的权重；
- 全部计算都是大矩阵乘法，$T$ 个位置同时进行，解决了问题 ② 和 ③。

**代价**：$S$ 是 $T\times T$ 的矩阵，计算量和显存都随序列长度的平方增长。长上下文的处理放在第 9 章，FlashAttention 放在第 22 章。

### 6.5 位置信息

注意力本身对顺序不敏感：它只是对前文做加权平均，而权重只由内容决定。如果把前面的 token 打乱顺序，第一层中最后一个位置得到的结果完全一样。但"狗咬人"和"人咬狗"的意思完全不同。

GPT-2 的做法是给每个位置也学一个向量，叫**位置嵌入**（position embedding），再加到 token 的嵌入上：

$$
x_i = E[\text{token}_i] + P[i], \qquad P \text{ 是一张 } T_{\max}\times d \text{ 的可学习表}.
$$

现代模型改用一种叫 RoPE 的方法（第 7 章）。

严格地说，因果掩码本身也会泄露一点顺序信息，因为不同位置能看到的前缀长度不同。研究表明，不加位置编码（称为 NoPE）的因果模型也能学到一定程度的位置感，但显式的位置编码效果更好，也更可靠。

### 6.6 多头注意力

一个 softmax 分布在同一时刻只能关注一种模式。**多头注意力**的做法是：把 $d$ 维平均分给 $n_h$ 个头，每个头的维度是 $d_h = d/n_h$，每个头有自己的 $W_q, W_k, W_v$，各自独立地计算注意力。然后把 $n_h$ 个头的输出拼接起来，变回 $T\times d$，再乘一个 $d\times d$ 的输出矩阵 $W_o$（{{fig-ch06-multihead}}）。

<figcaption>多头注意力：把向量的维度平均分给各个头，各头独立做注意力，拼接后再乘输出矩阵</figcaption>
</figure>

不同的头会学到不同的分工，比如一个头专看前一个字符，另一个头专看单词的开头，6.10 节的实验里可以看到。多头注意力的总计算量和一个 $d$ 维的单头差不多。

### 6.7 MLP 层

$$
\operatorname{FFN}(x) = \operatorname{GELU}(xW_1)\,W_2, \qquad W_1: d\times 4d,\quad W_2: 4d\times d.
$$

**GELU** 是一种平滑版的 ReLU：$\operatorname{GELU}(x) = x\,\Phi(x)$，其中 $\Phi$ 是标准正态分布的累积分布函数。这一层也叫**前馈层**（feed-forward，FFN）。

**分工**：注意力负责在**位置之间交换信息**，MLP 负责**在每个位置上独立地做计算**。模型约三分之二的参数都在 MLP 里，一般认为大量知识就存放在这里。

### 6.8 组装成 GPT

GPT 的完整结构如{{fig-ch06-gpt}} 所示。每一层（一个 **Transformer block**）都采用第 3 章的 Pre-norm 残差结构：

$$
x \leftarrow x + \operatorname{MHA}(\operatorname{LN}(x)), \qquad x \leftarrow x + \operatorname{MLP}(\operatorname{LN}(x)),
$$

其中 MHA 是多头注意力，LN 是 LayerNorm。

#### 参数量

- 每层注意力有 $W_q, W_k, W_v, W_o$ 四个 $d\times d$ 矩阵，共 $4d^2$；
- 每层 MLP 有 $d\times4d$ 和 $4d\times d$ 两个矩阵，共 $8d^2$；
- **每层合计约 $12d^2$，全模型约 $12Ld^2 + Vd$。**

验证：GPT-2 small 的 $L = 12$，$d = 768$，$V = 50{,}257$。$12\times12\times768^2 \approx 8{,}490$ 万，加上 $50{,}257\times768 \approx 3{,}860$ 万，再加位置嵌入约 79 万，合计约 **1.24 亿**，与官方数字一致。

#### 计算量

每个 token 的前向计算，约为 $2\times$ 参数量（矩阵乘法部分），再加上每层 $4Td$（注意力中的 $QK^\top$ 和 $AV$ 各 $2Td$）。后一项正是第 0 章 $6ND$ 公式中被忽略掉的那一项。

#### 训练与生成

**训练**：输入 `x[:, :-1]`，目标 `x[:, 1:]`。因为有因果掩码，一次前向就能同时得到 $T$ 个位置的预测，而且每个位置只用到了它之前的信息。第 2 章的 MLP，每个长为 $K$ 的窗口只能得到 1 个预测。

**生成**：把提示词送进模型，取最后一个位置的 logits，采样出一个 token，接到序列末尾，然后重复。如果每生成一步都把整个序列重新算一遍，就太浪费了。实际系统会把前面位置算好的 $K$、$V$ 缓存起来，这叫 **KV cache**（第 33 章）。

### 6.9 核心代码

```python
class CausalSelfAttention(nn.Module):
    def __init__(self, d, H):
        super().__init__()
        self.H, self.qkv, self.proj = H, nn.Linear(d, 3 * d), nn.Linear(d, d)   # 所有头的 Wq、Wk、Wv 合成一次矩阵乘
    def forward(self, x):                                                     # x: (B, T, d)
        B, T, d = x.shape
        q, k, v = self.qkv(x).split(d, dim=2)
        q, k, v = (t.view(B, T, self.H, d // self.H).transpose(1, 2) for t in (q, k, v))  # (B, H, T, d_h)
        att = q @ k.transpose(-2, -1) / math.sqrt(d // self.H)                # (B, H, T, T) 分数
        mask = torch.triu(torch.ones(T, T, dtype=torch.bool), diagonal=1)     # j > i 的位置是未来
        att = att.masked_fill(mask, float("-inf")).softmax(dim=-1)
        return self.proj((att @ v).transpose(1, 2).reshape(B, T, d))          # 拼接各头，再乘 Wo

class Block(nn.Module):
    def __init__(self, d, H):
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.attn = CausalSelfAttention(d, H)
        self.mlp = nn.Sequential(nn.Linear(d, 4 * d), nn.GELU(), nn.Linear(4 * d, d))
    def forward(self, x):
        x = x + self.attn(self.ln1(x))      # 位置之间交换信息
        return x + self.mlp(self.ln2(x))    # 每个位置独立计算

class GPT(nn.Module):
    def __init__(self, V, T, d, L, H):
        super().__init__()
        self.tok, self.pos = nn.Embedding(V, d), nn.Embedding(T, d)
        self.blocks = nn.ModuleList(Block(d, H) for _ in range(L))
        self.ln_f, self.head = nn.LayerNorm(d), nn.Linear(d, V, bias=False)
        self.head.weight = self.tok.weight                                    # 输入嵌入与输出层共享权重
    def forward(self, idx):                                                   # idx: (B, T) 的 token id
        x = self.tok(idx) + self.pos(torch.arange(idx.shape[1]))
        for blk in self.blocks: x = blk(x)
        return self.head(self.ln_f(x))                                        # (B, T, V)
```

代码中的 `H` 即正文中的头数 $n_h$。训练用第 3 章的配方：AdamW，权重衰减 0.1（只作用于矩阵），warmup 加 cosine 学习率，梯度裁剪 1.0，权重按标准差 0.02 初始化，残差分支的输出层再乘以 $1/\sqrt{2L}$。

### 6.10 小实验：Transformer 怎样利用上下文

::: experiment
**设置**：字符级莎士比亚数据（同第 1 章）。模型 4 层，$d = 128$，4 个头，上下文 128 个字符，共 818,048 个参数。batch 为 32 条序列，峰值学习率 $10^{-3}$，warmup 100 步，cosine 衰减到 10%，共 1,000 步。PyTorch，CPU 上运行约 2.5 分钟。

**要如实说明的一点**：在这么小的算力预算下，它还**没有超过**第 2 章的 MLP（1.711）。Transformer 每一步的计算更贵，在这个预算下它远没有训练充分。作为参照，nanoGPT 公开的结果是：在 GPU 上用 1,070 万参数训练 5,000 步，同一份数据能达到 1.47。Transformer 的优势要在更大的规模下才显现出来，这正是第 10 章 scaling law 要讨论的问题。

**这次实验能说明的是"它会利用长上下文"**：上下文越长，loss 越低（{{fig-ch06-ctx}} 左），到 32 个字符左右基本持平，**但从来没有变差**。对比第 2 章：MLP 把上下文从 4 加到 16，结果反而变差了。

**各个头有明显的分工**（{{fig-ch06-ctx}} 右）：有的头只看很近的几个字符，有的头看得很远。举一个具体的例子：上下文是 `…methinks you walk like a s`，在预测 `s` 后面的字符时，第 1 层的几个头把 40% 左右的注意力放在前面的空格上，相当于在定位"当前单词从哪里开始"。其中一个头还有 0.14 的权重落在 43 个字符之前的换行符上，那是这一行台词的开头。

生成的样本已经很像剧本，但不少词还拼错了。

| 整体结构 | **编码器–解码器**：编码器可以双向查看整段输入（比如原文），解码器只能看过去的内容（比如译文），用于翻译 | **只有解码器**（decoder-only）：一个因果模型完成所有任务 |
| 归一化的位置 | Post-norm | Pre-norm（第 3 章） |
| 位置编码 | 固定的正弦函数 | GPT-2 用可学习的位置嵌入，现代模型用 RoPE（第 7 章） |

2018 年的 BERT 只用编码器部分，擅长分类、理解这类任务，但不能自然地生成文本。如今的通用大模型都是 decoder-only 的结构（{{fig-ch06-encdec}}），也就是本章搭的这一种。

::: keypoints
1. RNN 必须串行处理，所有信息都要挤进一个固定的记忆向量。注意力让每个位置按内容直接从前文中取信息，所有位置共享参数，并且可以并行计算。
2. 注意力的计算是 $\operatorname{softmax}(QK^\top/\sqrt{d_h} + M)V$。除以 $\sqrt{d_h}$ 是为了防止 softmax 饱和，因果掩码 $M$ 防止模型看到答案。
3. 注意力对顺序不敏感，所以需要位置编码。多头注意力让不同的头可以分工。
4. 一个 block 由"注意力（位置之间交换信息）+ MLP（每个位置独立计算）"组成，采用 Pre-norm 残差结构，每层约 $12d^2$ 个参数。
5. 一次前向就能得到 $T$ 个位置的预测，训练效率高。代价是注意力的计算量和显存随 $T^2$ 增长。
:::

::: exercises
1. **手算**：沿用 6.4 节的例子，把 query 换成 $q = [0, 1]$，求三个权重和最终输出。
2. **推导**：假设 $q$ 和 $k$ 的各个分量相互独立，均值为 0，方差为 1。证明 $\operatorname{Var}(q\cdot k) = d_h$。
3. **思考**：如果训练时忘了加因果掩码，训练集的 loss 会怎样？用这个模型生成文本时又会怎样？
4. **思考**：去掉位置编码之后，把前面的 token 打乱顺序，第一层中最后一个位置的输出会变吗？到了更深的层，模型有没有可能重新"感知"到顺序？
5. **计算**：GPT-2 medium 的 $L = 24$，$d = 1024$，$V = 50{,}257$，上下文长度为 1024，估算它的参数量。
6. **计算**：每层每个 token，注意力分数部分的前向计算量约为 $4Td$，矩阵乘法部分约为 $24d^2$。$T$ 超过多少时，前者会超过后者？当 $d = 4096$、$T = 8192$ 时，注意力部分大约占多少？
:::
