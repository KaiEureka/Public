## 第 17 章　合成数据与评测污染 {#ch17 .chapter}

::: goals
- 了解合成数据的各种用法：改写、教科书式生成、蒸馏、可验证数据、自举、翻译和格式转换；
- 掌握做好合成数据的原则：多样、正确、有真实数据作依据；
- 理解"模型崩溃"是怎么回事，什么时候会发生，怎样避免；
- 理解评测污染：它是怎样混进训练数据的，有多大影响，怎样检测和清除。
:::

为什么需要合成数据？有四个原因：

1. **高质量的人类数据不够用了**（第 10、14 章）。
2. **有些能力本来就缺数据**：步骤完整的数学解答、带测试用例的代码、形式化证明，这类数据在网上很少。
3. **可以控制形式**：比如让数据呈现为问答、教科书讲解、逐步推理等形式。
4. **后训练阶段大量依赖合成数据**（第六篇）。

### 17.1 合成数据的类型

#### ① 改写真实文本

- **WRAP**（Maini 等，2024）：用一个指令模型，把 C4 中的网页改写成"维基百科风格"或"问答风格"，再与原始数据混在一起训练。报告的结果是预训练速度约快了 3 倍。
- **Nemotron-CC**（第 16 章）：把低质量的文档改写一遍，再把高质量的文档改写成问答、要点提取等多种形式。

**优点**：事实内容来自真实文档，模型只是换了一种说法，所以不太会凭空编造事实。这种做法叫**有依据的合成**。

#### ② 从零生成"教科书"

- **Phi-1**（Gunasekar 等，2023，《Textbooks Are All You Need》）：一个 13 亿参数的模型，训练数据约 70 亿 token，包括 60 亿经过筛选、达到"教科书质量"的网页，以及 10 亿由 GPT-3.5 生成的教科书和练习题。它在 HumanEval（一个编程基准）上达到了 50.6%。
- 后续的 Phi 系列都以合成数据为核心。Phi-4（14B）用了约 4,000 亿 token 的合成数据，涵盖几十种不同类型。也有评论认为，Phi 系列的基准分数与实际使用体验之间存在落差。
- **TinyStories**（2023）：用只有约 1,500 个常用词的词表合成儿童故事。用这份数据训练，不到 1,000 万参数的模型就能写出连贯的英文故事。
- **Cosmopedia**（HuggingFace，2024）：用 Mixtral 生成了约 250 亿 token 的教科书和故事类文本，以网页和精选主题作为生成的种子。

#### ③ 从强模型蒸馏

用更强的模型生成数学题的逐步解答、问答对，甚至长篇的思维链。MetaMath 改写和扩充了数学题；NVIDIA 的 OpenMathInstruct-2 用 Llama-3.1-405B 生成了约 1,400 万道题的解答；DeepSeek-R1 用长思维链数据蒸馏出了一批小模型（第 27、29 章）。

#### ④ 可验证的合成数据

**用程序来验证数据是否正确**，是保证合成数据质量最可靠的手段：

- **代码**：同时生成题目、解答和单元测试，只保留能通过测试的解答；
- **数学**：只保留最终答案可以核对且正确的解答；
- **形式化证明**：DeepSeek-Prover 合成了大量 Lean 证明（Lean 是一种能由程序自动检查证明是否正确的语言），只保留通过检查的那些；
- **AlphaGeometry**（2024）：用符号推理引擎生成了 1 亿个几何证明作为训练数据，**完全没有用到人类示范**。

#### ⑤ 自举

**STaR**（Zelikman 等，2022）：让模型为每道题生成推理过程，只保留最终答案正确的那些，用它们微调模型，然后重复这个过程。这已经是强化学习的雏形了（第 27 章）。{{fig-ch17-verify}} 把可验证的合成和自举放在一起做了对比。

#### ⑥ 翻译与格式转换

把高质量的英文数据机器翻译成资源稀缺的语言；把原始文档转换成"指令 + 回答"的形式（Instruction Pre-Training，2024）；在表格、代码和自然语言之间互相转换。

### 17.2 做好合成数据的原则

| 原则 | 做法 |
|---|---|
| **多样性** | 合成数据最大的问题是容易千篇一律。要在生成时提供多种多样的"种子"，比如主题、受众、写作风格；Tencent 的 Persona Hub（2024）构造了 10 亿个虚拟人设，让模型以不同人设的口吻来写。还可以提高采样温度、使用多种提示模板，并对生成的结果做去重 |
| **正确性** | 优先用程序来验证（执行代码、核对答案、Lean 检查）。其次可以用大模型当评审，或者让模型多次作答、取多数一致的答案 |
| **有依据** | 尽量改写真实文档，而不是让模型凭空编造事实，以减少幻觉内容 |
| **与真实数据混合** | 合成数据的占比要通过消融实验来确定。比如 Nemotron-CC 中，合成数据占 1.9T / 6.3T |
| **成本** | 生成每个 token 大约需要 $2\times$ 教师模型参数量的 FLOP。用 70B 模型生成 1T token，约需 $1.4\times10^{23}$ FLOP，相当于训练一个中等规模模型的计算量 |
| **许可条款** | 有些模型的服务条款禁止用它的输出去训练有竞争关系的模型，使用之前要仔细查看 |

### 17.3 模型崩溃

#### 现象

Shumailov 等（2024，发表于 Nature）发现：如果每一代模型**只用上一代模型生成的数据**来训练，这样一代代传下去，分布的**尾部**（罕见的内容）会逐渐消失，最终整个分布退化，多样性越来越低。

#### 机制

1. 每一代都只能从模型中**有限地采样**。罕见的内容出现的概率很低，很可能一次都没被抽到。
2. 一旦一次都没被抽到，下一代模型就会认为它的概率是 0；而概率为 0 的内容再也不会被抽到，**永远回不来了**（{{fig-ch17-tail}}）。
3. 一代代下来，尾部被不断蚕食。模型本身的误差还会在代际之间累积。

::: experiment
**模型崩溃的模拟。** 用莎士比亚文本中词语的出现频率作为"模型"。每一代都从当前模型中抽取 204,062 个词（与原始语料一样多），再用抽到的样本重新统计频率，作为下一代的模型。比较两种做法：

- **替换**：每一代只用上一代生成的样本；
- **累积**：每一代都保留原始的真实数据，再加上之前所有代生成的样本。

"罕见词"指在原始语料中只出现过 1 到 2 次的词，共 7,628 个。

|---|---|---|---|---|---|---|
| 0 | 12,631 | 9.752 | 100% | 12,631 | 9.752 | 100% |
| 1 | 10,200 | 9.707 | 69% | 12,631 | 9.740 | 100% |

- **替换**（{{fig-ch17-collapse}}）：仅仅一代之后，就有约三成的罕见词消失了；30 代之后，词表只剩原来的约 22%。熵下降得相对缓慢，因为消失的都是本来就罕见的词。**尾部是最先受损的部分。**
- **累积**：基本保持稳定。这与 Gerstgrasser 等（2024）的结论一致：**只要保留真实数据，并且合成数据是在真实数据的基础上累积，而不是替换掉它，崩溃就可以避免。**

#### 实践中的含义

- 崩溃主要发生在"只用自己的输出、不断替换掉真实数据"这种极端设置下。实际训练中，团队会始终混入真实数据，对合成数据做验证和筛选，并用更强的模型作为教师。所以合成数据本身并不会自动导致崩溃。
- **真正需要警惕的是互联网正在被 AI 生成的文本污染**（第 15 章）。未来抓到的网页里，AI 生成的内容会越来越多。所以要记录数据的来源，有些用途要优先使用较早的快照，同时继续研究怎样检测 AI 生成的文本。
- 即使没有崩溃，合成数据也容易偏向常见、平均的表达方式，所以 17.2 节的多样性措施很重要。

### 17.4 评测污染

#### 定义

**评测污染**指基准测试的题目（或者它们的改写版本）出现在了训练数据中。后果是分数虚高，不同模型之间也无法公平比较。

#### 污染是怎样混进来的

1. 基准测试本身就公开在网上，比如 GitHub 仓库、论文、论坛帖子、答案解析页面，Common Crawl 会把它们抓进来。
2. 用来生成合成数据的那个模型，可能见过基准的题目，于是在生成时"复述"出来。
3. 后训练数据集里，有意或无意地混入了基准题目（三条途径见{{fig-ch17-contam}}）。

<figure id="fig-ch17-contam" data-svg="ch17_contam.svg">
<figcaption>评测污染的三条途径</figcaption>
</figure>

**改写过的题目很难被发现。** Yang 等（2023）发现，把测试题用别的话改写一遍，就能躲过常规的 n-gram 重叠检测。用这样改写过的题目训练，一个 13B 的模型在 MMLU 和 HumanEval 上就能达到接近 GPT-4 的分数。

#### 污染的影响有多大

- **GSM1k**（Scale AI，2024）：仿照 GSM8K（小学数学应用题基准）的风格和难度，重新出了 1,000 道全新的题目。结果，有些模型家族在新题上的准确率比在 GSM8K 上下降了**最多约 13 个百分点**，说明它们对 GSM8K 有过拟合；前沿模型的下降则很小。
- **按时间检验**：比较模型在训练截止日期**之前**和**之后**发布的编程竞赛题上的表现，截止日期之后的题目上成绩明显下降（Roberts 等，2023）。LiveCodeBench 就是基于这个思路设计的：只用较新发布的题目来评测。

#### 检测方法

| 方法 | 做法 |
|---|---|
| **n-gram 重叠** | 检查训练数据与测试题之间有没有很长的相同片段。GPT-3 用 13-gram；Llama 2 的标准是：一个 token 只要属于某个长于 10 个 token、且同时出现在测试题和训练数据中的片段，就算被污染；GPT-4 从每道题中随机抽取 3 段 50 个字符的子串，在训练数据里查找 |
| **语义相似度** | 用嵌入向量，或者让大模型判断，来找出被改写过的版本，如 Yang 等（2023）的 LLM decontaminator |
| **从模型的角度检测** | **Min-K% Prob**（Shi 等，2023）：计算一段文本中概率最低的那 $k\%$ 的 token 的平均对数概率。模型见过的文本很少出现概率极低的 token，所以这个值会偏高。**补全测试**：给出一道题的前半部分，看模型能不能一字不差地接出后半部分 |
| **金丝雀字符串** | 在基准数据里放一个独特的随机字符串，方便别人过滤掉它，也方便检测模型是否背下了它。BIG-bench 中就有一个特定的 GUID 字符串 |

#### 清除污染的流程

1. 为所有关心的评测集建立索引（n-gram 索引或后缀数组）；
2. 扫描全部训练数据，包括预训练、中期训练和后训练的数据；
3. 删除命中的文档，或者只删除重叠的那部分片段，并记录下来；
4. 在技术报告中公布污染检测的方法和结果。

#### 评测时降低污染影响的做法

第 30 章会细讲，这里先列出几种：使用不公开的私有测试集；使用持续更新的基准，比如只用当年新出的 AIME（美国数学邀请赛）题目，或者 LiveCodeBench；在题目的改写版本或扰动版本上测试，看分数是否稳定。

::: keypoints
1. 合成数据可以补足人类数据的不足，主要用法有：改写真实文本、生成教科书、从强模型蒸馏、生成可验证的数据、自举，以及翻译和格式转换。
2. 好的合成数据要满足：多样（用丰富的种子，生成后去重）、正确（优先用程序验证）、有依据（尽量改写真实文档），并且与真实数据混合使用。
3. 如果只用自己生成的数据、不断替换掉真实数据，就会发生模型崩溃，罕见的内容最先消失。模拟实验中 30 代之后，词表只剩约 22%。保留真实数据、累积而不是替换，就能避免崩溃。
4. 评测污染会让分数虚高，而改写过的题目可以躲过 n-gram 检测。GSM1k 和按时间检验都表明，部分模型存在过拟合。
5. 检测和清除污染的方法有：n-gram 重叠、语义相似度、Min-K% 这类从模型角度的检测、金丝雀字符串。预训练、中期训练和后训练的数据都要做去污染，并在报告中公开。
:::

::: exercises
1. **思考**：在模型崩溃的模拟中，假设某个词在当前代的概率是 $p$，每一代抽取 $N$ 个词。它在下一代消失的概率是多少？代入 $p = 1/N$，结果是多少？用这个结果解释，为什么第一代就有约三成罕见词消失了。
2. **设计**：为"中学物理题 + 逐步解答"设计一条合成数据流水线，说明怎样保证多样性和正确性。
3. **思考**：为什么"有依据的改写"比"从零生成"更不容易产生幻觉内容？它的局限又是什么？
4. **计算**：用一个 70B 的模型生成 500B token 的合成数据，需要多少 FLOP？与用这些数据去训练一个 8B 模型相比，哪个更贵？
5. **思考**：一个模型在 GSM8K 上得了 90%，在 GSM1k 上只有 78%。这说明了什么？还需要哪些证据，才能判断它是否被污染了？
6. **设计**：为你的预训练数据写一份去污染方案：要检测哪些评测集，用什么方法、什么阈值，命中之后怎样处理，最后怎样在报告中呈现。
:::
