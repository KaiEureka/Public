## 第 0 章　一个前沿模型的一生 {#ch0 .chapter}

::: goals
- 说出一个前沿模型项目从立项到上线要经过哪些阶段，每个阶段由哪个团队负责；

### 0.1 一个前沿模型项目的生命周期

一个前沿模型项目通常持续 12 到 18 个月。{{fig-ch00-timeline}} 是一个典型的时间安排。

各阶段的内容和负责团队如下：

| 阶段 | 做什么 | 主要负责团队 |
|---|---|---|
| 立项 | 确定目标能力、算力预算和时间表 | 领导层与研究负责人 |
| 集群 | 买卡、建机房、装网络、做压力测试，往往是周期最长的一环 | 基础设施（Infra） |
| 数据 | 爬取、清洗、去重、打分、确定各类数据的比例，最后切成 token | 数据团队 |
| 小规模研究 | 先在小模型上做消融实验，拟合 scaling law，确认配方之后再押注大模型 | 预训练研究 |
| 预训练 | 一次连续跑几个月的大规模训练，每天都要处理坏卡和 loss 突然飙升 | 研究与 Infra 轮流值班 |
| 中期训练 | 训练末期换成高质量数据，同时把学习率降下来（称为退火），并扩展上下文长度 | 研究与数据 |
| 后训练 | 监督微调 → 偏好优化 → 强化学习。模型的推理能力主要在这一步形成 | 后训练团队 |
| 评测与安全 | 贯穿全程。评测是所有决策的依据，安全评估决定模型能否发布 | 评测与安全团队 |
| 部署 | 推理优化、API 服务、成本控制 | 推理团队 |

表中有几个词需要先解释一下。**消融实验**是一种对照实验：每次只改变一个因素，看它对结果有什么影响。**scaling law**（规模定律）描述的是模型的 loss 怎样随参数量和数据量变化，有了它，就能用一组小模型的结果去预测大模型的表现（第 10 章）。**学习率**是每次更新参数时迈出的步长（第 2、3 章）。

有一点常被忽略：**技术报告里写的"训练成本"，通常只算最后那一次训练。** 例如，DeepSeek-V3 报告的 557.6 万美元，是按 278.8 万 H800 GPU 小时、每小时 2 美元算出来的，报告明确说明它不包括前期的研究和消融实验。而研究阶段消耗的算力，往往和最终那次训练处于同一个量级。这正是第三篇"规模化的科学"的价值所在：用尽量少的小规模实验，尽早确定正确的配方。

### 0.2 所有决策背后的核心账本

下面几个公式是全书最常用的，值得记住。

#### 训练计算量：$C \approx 6ND$

先定义单位。**FLOP**（floating-point operation）指一次浮点运算，即一次加法或一次乘法。训练的总计算量用 FLOP 来计量，记为 $C$。

- $N$ 是模型的参数量。对 MoE 模型，$N$ 取**激活参数量**，即处理每个 token 时实际参与计算的参数数。
- $D$ 是训练用的 token 总数。

**为什么是 6？** 模型的参数绝大部分都在矩阵乘法里。以一个线性层 $y = xW$ 为例，设 $W$ 的形状是 $d_{\text{in}} \times d_{\text{out}}$，共有 $d_{\text{in}} d_{\text{out}}$ 个参数。对一个 token，$x$ 是长为 $d_{\text{in}}$ 的行向量：

- **前向**：$y$ 的每个分量需要 $d_{\text{in}}$ 次乘法和 $d_{\text{in}}$ 次加法，总共 $2 d_{\text{in}} d_{\text{out}}$ FLOP，也就是**每个参数 2 FLOP**。
- **反向**：已知 loss 对 $y$ 的梯度 $dy$，要计算两样东西。一是传给前一层的梯度 $dx = dy\,W^\top$，二是本层权重的梯度 $dW = x^\top dy$。两者都是同样规模的矩阵乘，各需 $2 d_{\text{in}} d_{\text{out}}$ FLOP，合计**每个参数 4 FLOP**。这两个公式会在第 2 章推导。

前向加反向，每个参数每个 token 共 6 FLOP。把 $D$ 个 token 都过一遍，就是 $C \approx 6ND$（{{fig-ch00-6nd}}）。

<figure id="fig-ch00-6nd" data-svg="ch00_6nd.svg">
<figcaption>训练计算量为什么是 6ND：一个线性层在前向和反向中各做一次同样规模的矩阵乘法</figcaption>
</figure>

这个公式忽略了两类计算。一类是注意力中 token 之间两两计算的部分，每层每个 token 的前向约为 $4Td$ FLOP，其中 $T$ 是上下文长度，$d$ 是模型宽度（第 6 章）。上下文较短时它可以忽略，上下文很长时就要加上（第 9 章）。另一类是归一化、激活函数这类逐元素运算，它们的 FLOP 很少，但会占用不少时间，原因在第 4 章解释。

#### 训练时间

$$
\text{训练时间} = \frac{C}{\text{GPU 数} \times \text{单卡峰值算力} \times \text{MFU}}
$$

**算力**以 FLOP/s（每秒浮点运算次数）为单位。**MFU**（Model FLOPs Utilization，模型算力利用率）是实际用于模型计算的有效算力与硬件峰值算力之比。优秀的工程大约能做到 35%–50%，糟糕的工程只有 10%–20%。**基础设施团队存在的意义，很大程度上就是把这个数字往上推。**

举个例子（估算）：GPT-3 的训练计算量约为 $3.14 \times 10^{23}$ FLOP。放在 1,024 张 H100 上训练，每张卡的 bf16 峰值算力约为 989 TFLOP/s（T 表示 $10^{12}$），按 40% 的 MFU 计算：

$$
\frac{3.14\times10^{23}}{1024 \times 989\times10^{12} \times 0.4} \approx 7.8\times10^{5}\ \text{秒} \approx 9\ \text{天}.
$$

#### 训练显存：每个参数约 16 字节

**显存**指 GPU 上的内存。用 bf16 混合精度加 Adam 训练时，每个参数要存：

| 内容 | 格式 | 字节数 | 用途 |
|---|---|---|---|
| 权重 | bf16 | 2 | 前向和反向计算时使用 |
| 梯度 | bf16 | 2 | 反向传播的结果 |
| 主权重 | fp32 | 4 | 精确地累加每一步的微小更新（第 13 章） |
| Adam 一阶矩 $m$ | fp32 | 4 | 梯度的滑动平均（第 3 章） |
| Adam 二阶矩 $v$ | fp32 | 4 | 梯度平方的滑动平均（第 3 章） |
| **合计** | | **16** | |

所以一个 7B 模型光是这些就要 $7\times10^9 \times 16 = 112$ GB，一张 80 GB 的 H100 放不下（{{fig-ch00-mem16}}），必须把它们切分到多张卡上（第 20 章）。这还没有算**激活值**，即前向传播的中间结果，反向传播时要用到它们。激活值随 batch 大小和序列长度增长，往往是更大的一块。

<figure id="fig-ch00-mem16" data-svg="ch00_mem16.svg">
<figcaption>用 bf16 混合精度加 Adam 训练时，每个参数约占 16 字节；7B 模型仅这一项就超出了一张 H100 的显存</figcaption>
</figure>

#### 推理：生成速度受限于显存带宽

- 模型训练好以后，用它生成文本的过程叫**推理**。生成每个 token 需要做一次前向，约 $2N$ FLOP。
- 生成文本时，模型每次只产生一个 token，然后把它接到输入后面，再产生下一个，这个阶段叫 **decode**。当只有一条请求时（batch = 1），每生成一个 token，都要把**全部权重**从显存读一遍。所以单条序列的生成速度存在上限：

$$
\text{每秒生成的 token 数} \lesssim \frac{\text{显存带宽}}{\text{模型占用的字节数}}.
$$

举例（估算，见{{fig-ch00-decode}}）：Llama 3 8B 用 bf16 存储约 16 GB，H100 的显存带宽约 3.35 TB/s，所以单条序列最多每秒生成约 $3350/16 \approx 200$ 个 token。这时实际用到的算力只有 $2 \times 8\times10^9 \times 200 \approx 3.3\times10^{12}$ FLOP/s，不到峰值的 0.4%。也就是说，**decode 阶段的瓶颈是显存带宽，而不是算力。** 第 4 章会解释为什么，第 33、34 章讨论怎么应对。

<figcaption>decode 阶段的瓶颈：每生成一个 token，都要把全部权重从显存读一遍（以 Llama 3 8B、一张 H100 为例）</figcaption>

#### 用真实模型检验

| 模型 | $N$ | $D$ | $6ND$ | 公开数字 |
|---|---|---|---|---|
| GPT-3（2020） | 175B | 300B | $3.15\times10^{23}$ | $3.14\times10^{23}$ |
| Llama 3 405B（2024） | 405B | 15.6T | $3.79\times10^{25}$ | $3.8\times10^{25}$ |
| DeepSeek-V3（2024） | 37B 激活 / 671B 总量 | 14.8T | $3.3\times10^{24}$ | 278.8 万 H800 GPU 小时 |

前两行几乎完全吻合。对第三行，可以反推每张卡的有效算力：$3.3\times10^{24} / (2.788\times10^{6} \times 3600\ \text{秒}) \approx 330$ TFLOP/s，约为 H800 bf16 峰值的三分之一，量级合理。

另一个要记住的数字是 **Chinchilla 比例**：在计算量固定时，要让 loss 最低，训练 token 数大约应该是参数量的 20 倍，即 $D \approx 20N$。不过，现代模型为了降低推理成本，往往会远远超出这个比例。例如 Llama 3 8B 用了 15T token 训练，相当于每个参数约 1,900 个 token。第 10 章会讲这样做的理由。

### 0.3 全书的配方概要

全书可以概括为下面十条。这些术语现在看不懂没关系，每一条都会在对应的章节里从头讲起。读完全书时，你应该能闭卷写出每一条背后的所有细节。

1. **架构**（第二篇）：decoder-only Transformer，采用 Pre-RMSNorm、RoPE、SwiGLU、GQA 或 MLA；规模大了以后用细粒度 MoE。
2. **目标函数**（第 1 章）：只用"预测下一个 token"这一个目标，然后把规模做大。
3. **规模化**（第 10、11 章）：先用一组小模型拟合 scaling law，外推之后再押注大模型；每个参数对应的训练 token 数，要远高于早期研究建议的值。
4. **数据**（第四篇）：质量比数量重要；要去重；用质量分类器筛选；代码和数学要占足比重；训练末期用高质量数据退火。
5. **系统**（第 4 章、第五篇）：混合精度、ZeRO/FSDP，加上张量、流水线、专家等多种并行的组合，再加 FlashAttention 和容错机制。
6. **稳定性**（第 12、13 章）：学习率预热、梯度裁剪、z-loss 与 QK-norm、数值精度管理。
7. **后训练**（第六篇）：少而精的监督微调 → 偏好优化 → 基于可验证奖励的强化学习，推理能力主要从最后一步来。
8. **评测**（第 30 章）：建立内部评测体系，严防测试题泄漏进训练数据。
9. **推理**（第 33、34 章）：KV cache 管理、量化、投机解码。
10. **组织**（第 36 章）：工作量最大的是基础设施和数据，而不是模型结构本身。

::: keypoints
1. 一个前沿模型项目要经过立项、集群、数据、小规模研究、预训练、中期训练、后训练、评测与安全、部署等阶段，各由不同的团队负责。评测和安全贯穿全程。
2. 训练计算量 $C \approx 6ND$：前向每参数每 token 2 FLOP，反向 4 FLOP。训练时间等于 $C$ 除以总的有效算力，有效算力等于峰值乘以 MFU。
3. 混合精度加 Adam 训练，每个参数约占 16 字节显存，激活值另算。
4. 推理每个 token 约 $2N$ FLOP。batch 为 1 时，生成速度的上限是显存带宽除以模型字节数，瓶颈在带宽而不在算力。
5. 技术报告中的训练成本通常只包括最后一次训练，研究阶段的花费与之同一量级。
:::

::: exercises
1. **计算量与时间。** 在 2T token 上训练一个 7B 的稠密模型，需要多少 FLOP？用 1,024 张 H100，每张卡的有效算力按 400 TFLOP/s（约 40% MFU）计算，要跑多少天？Llama 2 7B 的报告称训练用了 18.4 万 A100 GPU 小时，A100 的 bf16 峰值算力是 312 TFLOP/s，请反推它的 MFU。
2. **反向传播的计算量。** 为什么反向传播的计算量大约是前向的 2 倍？如果为了节省显存，在反向传播时把前向重新计算一遍（称为激活重计算，第 20 章），总计算量变成多少？
3. **显存。** 用混合精度加 Adam 训练一个 70B 的稠密模型，仅权重、梯度和优化器状态就需要多少显存？假设可以完美切分、不考虑激活值，最少需要多少张 80 GB 的 H100？
4. **推理速度。** 估算一个 70B 模型（bf16）在 batch 为 1 时的生成速度上限。假设它被平均切分到 8 张 H100 上，每张卡同时读取自己那一份权重。
5. **团队分工。** 下面这些工作分别归哪个团队？(a) 训练到第 12,000 步时 loss 突然飙升，要决定是否回退；(b) 发现某个数学测试集的题目出现在了训练数据中；(c) 让 API 每百万 token 的成本降低一半；(d) 决定代码数据在训练数据中占多大比例；(e) 某台服务器上的 GPU 反复报错；(f) 让模型学会拒绝明显危险的请求。
:::
