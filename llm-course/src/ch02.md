第 1 章的结尾留下了两个需求：用学出来的向量（embedding）表示字符，以及用一个所有上下文共用参数的函数来做预测。本章把它们实现出来。

### 2.1 从查表到函数

#### one-hot 向量与线性层

第 1 章定义过 **one-hot 向量**：一个 $V$ 维向量，只有第 $y$ 个位置是 1，其余都是 0。比如在 65 个字符中，`c` 的编号是 41，它的 one-hot 向量就是第 41 位为 1 的 65 维向量。

用 one-hot 向量去乘一个矩阵，结果就是把矩阵的某一行取出来：

$$
\operatorname{onehot}(a)\, W = W[a], \qquad (1\times65)\cdot(65\times65) = (1\times65).
$$

所以第 1 章的 bigram 查表，等价于"one-hot 输入乘以一个矩阵"。这就是一个最简单的**线性层**（{{fig-ch02-onehot}}）。

<figure id="fig-ch02-onehot" data-svg="ch02_onehot.svg">
<figcaption>one-hot 向量乘矩阵，就是把矩阵的一行取出来：查表与线性层是一回事</figcaption>
</figure>

线性层的一般定义是 $y = xW + b$：

- $x$ 是输入向量，形状为 $1\times n$；
- $W$ 是 $n\times m$ 的矩阵，叫**权重**；
- $b$ 是 $m$ 维向量，叫**偏置**；
- $y$ 是 $m$ 维输出。

$W$ 和 $b$ 都是要学习的参数。实际计算时一次处理 $B$ 个样本，把它们叠成一个 $B\times n$ 的矩阵 $X$，一次矩阵乘法就能全部算完：$Y = XW + b$，其中 $b$ 被加到每一行上。这 $B$ 个样本合称一个 **batch**。

#### embedding：让字符之间有"相似"可言

用 one-hot 表示字符有一个根本问题：**任意两个字符都同样不相似**。任意两个不同字符的 one-hot 向量，点积都是 0，距离都是 $\sqrt{2}$。`k` 和 `K` 之间的距离，与 `k` 和 `!` 之间的距离完全一样。

**embedding** 的做法是给每个字符分配一个 $d$ 维的实数向量，比如 $d = 16$。这些向量存在一张 $65\times16$ 的表 $E$ 里，查第 $a$ 行就得到字符 $a$ 的向量：$E[a] = \operatorname{onehot}(a)\,E$。这些向量也是参数，随训练一起学习。

为什么学出来的向量能体现相似性？因为整个模型必须仅凭这 16 个数完成预测。如果 `k` 和 `K` 在预测下一个字符时的作用差不多，梯度下降就会把它们的向量推到相近的位置。一旦它们相近，在 `k` 上学到的规律就自动地部分适用于 `K`。

#### 非线性：为什么不能只叠线性层

两个线性层叠在一起，仍然是一个线性层：$(xW_1)W_2 = x(W_1W_2)$，叠多少层都一样。

线性模型的局限在于：输入的每一部分各自贡献一份，然后简单相加，"A 位置是什么"不会影响"B 位置该怎样解读"。经典的反例是异或（XOR）：两个输入恰好有一个为 1 时输出 1，否则输出 0，任何线性函数都表达不了它。语言里到处是这类组合关系：`k`、`i`、`n` 这几个字母**同时**按顺序出现，后面才很可能是 `g`。这种"同时出现"的组合，没法拆成每个字母各自的贡献再相加。

解决办法（{{fig-ch02-xor}}）是在线性层之间插入一个**激活函数**，对向量的每个元素各自做一次非线性变换。本章用 **tanh**，它把任意实数压到 $(-1, 1)$ 区间，是一条 S 形曲线。

<figure id="fig-ch02-xor" data-svg="ch02_xor.svg">
<figcaption>左：异或的四个点无法用一条直线分开；右：tanh 激活函数</figcaption>
</figure>

#### MLP

把"线性层 → 激活函数 → 线性层"串起来，就是最基本的神经网络，叫**多层感知机**（MLP）：

$$
h = \tanh(xW_1 + b_1), \qquad \text{logits} = hW_2 + b_2.
$$

中间的向量 $h$ 叫**隐藏层**，它的每个元素叫一个**隐藏单元**。**万能近似定理**保证：只要隐藏层足够宽，这种结构可以任意精确地逼近任何连续函数。但这个定理只说明"存在这样一组参数"，没有说能不能用梯度下降找到它，也没有说需要多少数据。

### 2.3 反向传播：怎样算出 10 万个梯度

#### 问题

梯度下降需要 loss 对每一个参数的偏导数。最笨的办法是**数值梯度**：把一个参数加上一个很小的数 $\varepsilon$，重新算一遍 loss，看它变了多少。这样每个参数要做两次前向计算，10 万个参数每一步就要算 20 万次前向。

**反向传播**只需要一次前向加一次反向（反向的代价大约是前向的 2 倍），就能得到全部 10 万个梯度。

**链式法则**：如果 $L$ 通过中间量 $y$ 依赖于 $x$，那么 $\dfrac{\partial L}{\partial x} = \dfrac{\partial L}{\partial y}\cdot\dfrac{\partial y}{\partial x}$。

**反向传播**就是从 $L$ 出发往回走。每个节点把自己收到的梯度乘上自己的**局部导数**，传给它的输入：

| 节点 | 局部导数 | 收到的梯度 × 局部导数 | 结果 |
|---|---|---|---|
| $L$ | — | 起点 | $\partial L/\partial L = 1$ |
| $d, f$（$L = d\cdot f$） | $\partial L/\partial d = f$，$\partial L/\partial f = d$ | $1\times4$，$1\times(-1)$ | $\partial L/\partial d = 4$，$\partial L/\partial f = -1$ |
| $e, c$（$d = e + c$） | 都是 1 | $4\times1$，$4\times1$ | $\partial L/\partial e = 4$，$\partial L/\partial c = 4$ |
| $a, b$（$e = a\cdot b$） | $\partial e/\partial a = b$，$\partial e/\partial b = a$ | $4\times(-2)$，$4\times3$ | $\partial L/\partial a = -8$，$\partial L/\partial b = 12$ |

验证一下：把 $a$ 从 3 改成 3.000001，$L$ 从 $-4$ 变成 $-4.000008$，变化量除以 0.000001 正好是 $-8$。

**第二条规则：一个变量如果通过多条路径影响结果，各条路径的梯度要相加。** 比如 $y = x\cdot x$，$x$ 同时是乘法的两个输入，两条路径各贡献 $x$，合起来是 $2x$，这正是 $x^2$ 的导数。

**处理顺序**：一个节点必须等它所有下游节点的梯度都传回来，才能继续往回传。把节点排成"每个节点都排在它的所有输入之后"的顺序，叫**拓扑排序**；然后倒着处理即可。

#### 一个完整的自动微分引擎

下面约 30 行代码就是一个能用的自动微分引擎（完整版见附录 C）：

```python
class Value:
    """一个标量节点：记住自己的值、梯度、由哪些节点算出来，以及怎样把梯度传回去"""
    def __init__(self, data, parents=()):
        self.data, self.grad, self._parents = data, 0.0, parents
        self._backward = lambda: None

    def __mul__(self, other):
        out = Value(self.data * other.data, (self, other))
        def _backward():                           # 局部导数：d(ab)/da = b，d(ab)/db = a
            self.grad  += other.data * out.grad    # 用 += 而不是 =：多条路径的梯度相加
            other.grad += self.data  * out.grad
        out._backward = _backward
        return out

    # __add__ 和 tanh 的写法相同，局部导数分别是 1 和 1 - tanh²

    def backward(self):
        order, seen = [], set()
        def visit(v):                              # 拓扑排序
            if v not in seen:
                seen.add(v)
                for p in v._parents: visit(p)
                order.append(v)
        visit(self)
        self.grad = 1.0                            # ∂L/∂L = 1
        for v in reversed(order):                  # 从输出往回，逐个节点传递梯度
            v._backward()
```

对{{fig-ch02-graph}} 的例子运行它，得到 $\partial L/\partial a = -8$，$\partial L/\partial b = 12$，$\partial L/\partial c = 4$，$\partial L/\partial f = -1$，与手算一致；$y = x\cdot x$ 在 $x = 3$ 处的梯度算出来是 6。

**PyTorch 的 autograd（自动微分）做的就是这件事**：每做一次运算，就记下"输入是谁、梯度怎样传回去"；调用 `loss.backward()` 时，按拓扑排序的逆序把图走一遍。区别只在于 PyTorch 的节点是整个张量（多维数组），而不是单个数。

**为什么要从后往前算？** 我们只有 1 个输出（loss），却有 10 万个输入（参数）。从后往前走一趟（称为**反向模式**），就能得到 loss 对所有输入的导数。如果从前往后（**前向模式**），每个输入都得单独走一趟。

### 2.4 矩阵形式的反向传播

实际训练时，节点是矩阵而不是单个数。用标量规则推导一下，就能得到矩阵规则。约定 $dY$ 表示 $\partial L/\partial Y$，形状和 $Y$ 相同。

**矩阵乘 $Y = XW$**（$X$ 是 $B\times n$，$W$ 是 $n\times m$）：$Y_{ij} = \sum_k X_{ik}W_{kj}$。$W_{kj}$ 影响所有的 $Y_{ij}$（$i = 1,\dots,B$），按"多条路径相加"的规则：

$$
dW_{kj} = \sum_i dY_{ij}\,X_{ik} \;\Rightarrow\; dW = X^\top dY, \qquad
dX_{ik} = \sum_j dY_{ij}\,W_{kj} \;\Rightarrow\; dX = dY\,W^\top.
$$

检查形状：$X^\top dY$ 是 $(n\times B)(B\times m) = n\times m$，与 $W$ 相同；$dY\,W^\top$ 是 $(B\times m)(m\times n) = B\times n$，与 $X$ 相同。一个记忆技巧（{{fig-ch02-matgrad}}）：结果的形状必须与原变量相同，满足这个条件的矩阵乘法基本只有一种写法。

<figure id="fig-ch02-matgrad" data-svg="ch02_matgrad.svg">
<figcaption>矩阵乘法的反向传播。dX 和 dW 各是一次与前向同样规模的矩阵乘，结果的形状与原变量相同</figcaption>
</figure>

**这就是第 0 章"反向的计算量约是前向的两倍"的来源**：前向的每一次矩阵乘，在反向时都对应两次同样大小的矩阵乘，一次求 $dX$，一次求 $dW$。

| 前向运算 | 反向规则 | 原因 |
|---|---|---|
| $Y = XW$ | $dX = dY\,W^\top$，$dW = X^\top dY$ | 上面的推导 |
| $Y = X + b$（$b$ 加到每一行） | $db$ = $dY$ 的各行之和 | $b$ 被 $B$ 个样本各用了一次，多条路径相加 |
| $h = \tanh(a)$ | $da = dh \odot (1 - h^2)$ | 逐元素运算，$\odot$ 表示逐元素相乘 |
| softmax 加交叉熵，对 batch 求平均 | $d\,\text{logits} = (\operatorname{softmax} - \operatorname{onehot})/B$ | 第 1 章的公式；除以 $B$ 是因为求了平均 |
| $x = E[\text{字符编号}]$（查表） | 把 $dx$ 累加回 $E$ 中被用到的那些行 | 同一个字符可能在多个位置、多个样本中出现，梯度相加 |

本章模型的反向传播，完整代码就是下面这些（数据流见{{fig-ch02-backflow}}）：

```python
# 前向：x = E[ctx] 拼接 → a = x·W1 + b1 → h = tanh(a) → logits = h·W2 + b2
dlogits = softmax(logits); dlogits[range(B), y] -= 1; dlogits /= B   # softmax − onehot
dW2 = h.T @ dlogits;   db2 = dlogits.sum(0)
dh  = dlogits @ W2.T
da  = dh * (1 - h**2)                                                # 穿过 tanh
dW1 = x.T @ da;        db1 = da.sum(0)
dx  = (da @ W1.T).reshape(B, K, D)
dE  = np.zeros_like(E);  np.add.at(dE, ctx, dx)                      # 累加回被查过的行
```

### 2.5 训练

**小批量随机梯度下降**（SGD）。每一步都用整个训练集（100 万个位置）计算梯度太贵了。实际的做法是每步从训练集中随机抽 $B = 256$ 个位置组成一个 batch，用它们的平均梯度代替全量梯度。这个梯度有噪声，但平均来看方向是对的，而一步的计算量只有全量的约四千分之一。参数更新一次叫一个 **step**。

**初始化**。参数的初始值取随机的小数。为什么不能全设为 0？如果 $W_1$ 全是 0，512 个隐藏单元的输入权重完全相同，它们算出的值和收到的梯度也完全相同，会永远保持一样，相当于只有 1 个隐藏单元。随机初始化可以打破这种对称。本章的实验中，$E$ 的元素取标准正态分布，$W_1$ 取标准正态再乘以 $(5/3)/\sqrt{128}$，$W_2$ 取标准正态再乘以 0.01。$W_2$ 特意取得很小，这样初始的 logits 都接近 0，输出接近均匀分布，初始 loss 约等于 $\ln V$：实测初始 loss 是 4.196，而 $\ln 65 = 4.174$。这些系数是怎样来的，第 3 章会解释。

**学习率**。前 60% 的步数用 0.1，之后降到 0.03，最后 15% 用 0.01。直观的理解是：一开始离答案远，步子大一点走得快；接近答案时，步子大了会来回跳，所以要缩小。第 3 章会系统地讲。

用 PyTorch 写，模型和训练步骤是这样的（这段代码仅作对照，本章的实验用 numpy 手写的版本完成）：

```python
class MLPLM(nn.Module):
    def __init__(self, V, K=8, D=16, H=512):
        super().__init__()
        self.E, self.fc1, self.fc2 = nn.Embedding(V, D), nn.Linear(K*D, H), nn.Linear(H, V)
    def forward(self, ctx):                       # ctx: (B, K) 的整数张量
        return self.fc2(torch.tanh(self.fc1(self.E(ctx).flatten(1))))

loss = F.cross_entropy(model(ctx), y)
loss.backward()                                   # autograd 自动完成 2.4 节手写的那几行
with torch.no_grad():
    for p in model.parameters():
        p -= lr * p.grad; p.grad = None
```

### 2.7 新暴露的问题：MLP 用不好长上下文

再看 $K = 4$、8、16 三行：**上下文越长，结果反而越差**，至少在这个训练预算下是这样。原因有两个（{{fig-ch02-context}}）：

<figure id="fig-ch02-context" data-svg="ch02_context.svg">
<figcaption>上下文长度与验证集 loss（实测）。同样的上下文长度下 MLP 胜过计数法，但上下文再加长，MLP 也会变差</figcaption>
</figure>

1. **每个位置各有一套独立的权重。** 在 $W_1$ 中，"第 3 个位置上的 e"和"第 7 个位置上的 e"对应完全不同的行，要分别学习。数据被分散到各个位置上，这是 n-gram 问题的温和版本。
2. **远处的字符大多与预测无关**，模型必须学会忽略它们。参数越多，训练越慢，也越容易把噪声当成规律。训练集和验证集的差距从 $K = 4$ 时的 0.17 扩大到 $K = 16$ 时的 0.25。

如果数据更多、训练更久，$K = 16$ 也许能追上来，但结构上的问题还在。真正需要的是：**所有位置共用同一套权重来处理，并由模型自己决定该看哪些位置。** 这就是第 6 章要讲的注意力机制和 Transformer。现在只需要记住它要解决的问题是什么。

::: keypoints
1. 查表等于"one-hot 乘矩阵"，也就是线性层。embedding 用学出来的低维向量代替 one-hot，让相似的字符可以共享规律。
2. 线性层叠多少层都还是线性的，必须在中间插入非线性的激活函数。线性层与激活函数交替堆叠，就是 MLP。
3. 反向传播 = 链式法则 + 多条路径的梯度相加 + 按拓扑排序倒着走。一次反向就能得到所有参数的梯度，代价约为前向的 2 倍。
4. 矩阵规则：$dX = dY\,W^\top$，$dW = X^\top dY$。前向的每次矩阵乘对应反向的两次，这就是 $6ND$ 中"6"的来源。
5. 神经网络通过共享参数解决了"没见过的上下文"问题（$K = 4$ 时 1.711 < 1.770），但这种 MLP 还不会利用长上下文。
:::
