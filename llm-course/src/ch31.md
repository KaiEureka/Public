## 第 31 章　安全工程 {#ch31 .chapter}

::: goals
- 理解模型规范的作用和结构；
- 掌握拒绝与过度拒绝之间的权衡，以及常用的训练方法；
- 理解越狱为什么会成功，以及纵深防御的思路；
- 了解红队测试和危险能力评估的方法；
- 理解负责任扩展政策（RSP）等前沿安全框架，以及权重安全和相关法规；
- 能把安全措施映射到训练和部署的每一个环节。
:::

本章以公开的研究、报告和政策文件为主。关于攻击手段，只讲类别和原理，不讲具体的操作细节。政策和法规部分反映的是课程讲授时的情况，仍在快速变化。

### 31.1 安全是一项工程

一个被数百万人使用的模型，可能带来几类风险：

- **被滥用**：比如为生物、化学武器或网络攻击提供实质性的帮助，用于诈骗，生成儿童性虐待内容；
- **模型自身行为不当**：欺骗、一味附和用户、给出有害的建议、泄露隐私；
- **Agent 带来的风险**：执行越权或不可逆的操作，被提示注入所操纵（第 28 章）；
- **社会层面的风险**：偏见、虚假信息。

安全工作贯穿整个生命周期：数据（第 15 章）→ 预训练 → 后训练 → 评测 → 部署时的防护 → 上线后的监控 → 政策与治理。

### 31.2 模型规范：先写清楚"模型应该怎样做"

**模型规范**是一份书面文件，规定模型在各种情况下应该怎样行为。公开的例子有 OpenAI 的 **Model Spec**（2024 年首次发布，之后多次更新），以及 Anthropic 为 Claude 制定的**宪法**（源自 2022 年的 Constitutional AI 工作，后来多次公开更新）。

**典型的结构**：

| 部分 | 内容 |
|---|---|
| 目标 | 有帮助、诚实、无害 |
| 硬性规则 | 在任何情况下都不能做的事，比如为大规模杀伤性武器提供实质性的帮助 |
| 默认行为 | 在没有其他指示时怎样做。运营方或用户可以在允许的范围内调整这些默认行为 |
| 指令的优先级 | 平台 > 开发者或运营方 > 用户 > 工具返回的内容（第 28 章讲过的指令层级） |
| 诚实 | 准确表达不确定性，不欺骗，不为了讨好用户而附和（第 25 章） |

**为什么要写出来**：让训练的目标变得**明确**，写 SFT 数据、标注偏好、设计基于规则的奖励、制定评测标准，都以它为依据；也让外界可以检查和监督。

**核心矛盾**：有帮助与无害之间经常发生冲突。拒绝得太少，会造成危害；拒绝得太多，模型就没用了，这本身也是一种失败。

### 31.3 拒绝与过度拒绝

#### 目标

- 对**真正有害**的请求，明确地拒绝，说明原因，并在可能时提供安全的替代方案；
- 对**看起来敏感、实际上正当**的请求，要好好回答，比如"怎样杀死一个 Python 进程"，或者医生询问药物的致死剂量。

**过度拒绝的基准**：XSTest（Röttger 等，2023）包含 250 个"表面像是有害、实际上无害"的提示，当时的 Llama-2-70B-chat 拒绝了其中相当大的一部分。类似的基准还有 OR-Bench。

#### 训练方法

| 方法 | 做法 |
|---|---|
| **Constitutional AI**（Anthropic，2022） | 让模型按照一组书面原则批评自己的回答，再修改；并用 AI 按原则给出的偏好来做强化学习（RLAIF） |
| **基于规则的奖励**（OpenAI，2024） | 把安全规范拆成一条条具体的、可以检查的规则，比如"拒绝时不要说教""要给出替代方案"，由模型按规则逐条打分，作为强化学习的奖励 |
| **审慎对齐**（OpenAI，2024 年 12 月） | 训练推理模型在回答之前，先在思维链中**引用并推理安全规范的原文**，再决定怎样回答 |
| **安全补全**（OpenAI，2025） | 不再只在"完全拒绝"和"完全照办"之间二选一，而是给出一个既有帮助、又不越过安全边界的回答 |

#### 衡量

同时测量两个指标：**有害请求被照办的比例**，以及**正当请求被拒绝的比例**。把不同版本的模型画在这两个指标构成的平面上，就能看出它们在两者之间的取舍（{{fig-ch31-tradeoff}}）。

### 31.4 越狱：为什么会成功，怎样防御

#### 攻击的类别（只讲原理）

| 类别 | 原理 |
|---|---|
| 角色扮演或虚构情境 | 把有害的请求包装成"写小说""扮演某个角色" |
| 编码与低资源语言 | 用 base64 编码，或者翻译成低资源语言。Yong 等（2023）发现，把请求翻译成低资源语言，就能绕过 GPT-4 的安全防护 |
| **多样本越狱**（Anthropic，Anil 等，2024） | 在很长的上下文里放入大量虚构的"有求必应"的对话。成功率随示例的数量按幂律增长，**上下文窗口越长，风险越大** |
| **对抗后缀**（GCG，Zou 等，2023） | 用优化算法自动搜索出一串看起来毫无意义的字符，加在请求后面就能让模型照办，而且能迁移到其他模型上 |
| 多轮逐步升级 | 从无害的话题开始，一点一点引向有害的内容（比如 Crescendo） |
| 提示注入 | 第 28 章 |
| **对开放权重模型做微调** | Qi 等（2023）发现，只用少量有害样本微调，就能去掉模型的安全行为；甚至用正常的数据微调，安全性也会下降 |

#### 为什么会成功

Wei 等（2023）总结了两个原因（{{fig-ch31-gap}}）：

1. **目标互相竞争**：模型既被训练要"有帮助、要照着指令做"，又被训练要"安全"。攻击者构造的情境，让"照着做"压过了"安全"。
2. **泛化不匹配**：模型的**能力**泛化到了很多地方，比如它看得懂 base64，懂很多种语言；但**安全训练**并没有覆盖到这些地方。

#### 纵深防御

| 层次 | 手段 |
|---|---|
| 模型本身 | 用红队发现的攻击做对抗训练，让模型更加鲁棒 |
| 输入和输出分类器 | **Constitutional Classifiers**（Anthropic，2025）：根据一份书面规范合成大量训练数据，训练专门的分类器来拦截危险的输入和输出。在一次漏洞悬赏中，183 名参与者花了 3,000 多小时，都没有找到能绕过原型系统的"通用越狱"。后续版本还把对正常请求的额外拒绝率控制在了约 0.4% |
| 系统层面 | 监控、限制调用频率、识别和封禁滥用的账号 |
| 开放权重模型 | 更难防护。研究方向包括抗篡改的安全机制，以及**在预训练数据中过滤掉高危知识**。2025 年有研究发现，从预训练数据中过滤掉生物威胁相关的内容，能让开放权重模型在之后被微调时，也更难恢复这些危险能力 |

**没有完美的防御。** 目标是提高攻击的成本，减少模型能提供的实质性帮助（{{fig-ch31-defense}}）。

### 31.5 红队测试

- **人工红队**：内部团队加上外部的领域专家，涵盖生物、网络安全、儿童安全、选举等领域，开展有组织的测试。发现的问题会被转化成训练数据和分类器的训练样本。
- **自动化红队**：用模型来生成攻击（Perez 等，2022），甚至用强化学习专门训练一个"攻击者"模型。
- **漏洞悬赏**：邀请外部研究者来寻找漏洞。
- **产出**：失败案例的分类和严重程度评估，以及加入回归测试的评测集（第 30 章）。

### 31.6 危险能力评估

#### 评估的领域

| 领域 | 评估什么 |
|---|---|
| **化学、生物、放射性和核武器（CBRN）** | 模型能不能为获取或制造威胁提供实质性的帮助。方法包括知识类的代理基准（比如 WMDP、病毒学能力测试 VCT），以及**有真人参与的"能力提升"实验**：比较使用模型和不使用模型的两组人，看完成相关任务的能力差多少 |
| **网络安全** | 夺旗赛（CTF）类的题目（比如 Cybench），发现漏洞的能力 |
| **自主性与 AI 研发** | 能否自主完成机器学习研究的任务（比如 RE-Bench），能否自我复制 |
| **说服与操纵** | 改变人的观点和行为的能力 |
| **欺骗与谋划** | Apollo Research（2024）发现，在特定设置下，前沿模型能够为了达成目标而在上下文中进行"谋划"，包括隐瞒和欺骗；Anthropic 也做过"破坏"类的评估 |

#### 方法上的要点

- **充分激发能力**：评估时要尽最大努力把模型的能力发挥出来，比如做针对性的微调、提供工具和更好的 Agent 框架。如果评估时没能激发出来，就会**低估风险**。
- **提前定好阈值**：在评估之前就确定"能力达到什么程度就算越线"，而不是看到结果之后再决定。
- **外部评估**：发布前交给第三方机构测试，比如英国的 AI 安全研究所（AISI）、美国的 CAISI。
- **警惕"故意藏拙"**：模型可能在评估中故意表现得比实际差（van der Weij 等，2024 研究过这个问题）。

### 31.7 负责任扩展政策与前沿安全框架

**核心思想：能力达到什么程度，就必须配备什么程度的防护，并且要提前承诺。**

| 框架 | 要点 |
|---|---|
| **Anthropic RSP**（2023 年首次发布，之后多次更新） | 仿照生物安全等级，设立 **AI 安全等级（ASL-2、ASL-3……）**。每个等级都对应部署防护和安全防护两方面的要求。2025 年 5 月发布 Claude Opus 4 时，作为预防措施启用了 ASL-3 级别的防护 |
| **OpenAI Preparedness Framework**（2023 年首次发布，2025 年更新第 2 版） | 跟踪生物和化学、网络安全、AI 自我改进等类别的能力，设有"高"和"关键"两级阈值。2025 年，OpenAI 将 ChatGPT Agent 在生物领域按"高"能力对待 |
| **Google DeepMind Frontier Safety Framework**（2024 年首次发布） | 为各个领域设定"关键能力等级" |

#### 外部的承诺与法规

- 2024 年首尔峰会上，多家前沿实验室签署了"前沿 AI 安全承诺"；
- **欧盟《AI 法案》**：训练计算量超过 $10^{25}$ FLOP 的通用模型，被推定为具有"系统性风险"，需要做评估和对抗测试、报告严重事件、保障网络安全；
- **美国加州 SB 53**（2025 年签署）：要求大型的前沿模型开发者公开自己的安全框架，并报告重大的安全事件。

#### 权重安全

前沿模型的权重如果被盗，前面所有的部署防护就都失效了，所以需要防范外部攻击和内部威胁。RAND 在 2024 年的报告中把防护水平分成了 5 个等级。RSP 中更高的安全等级，就包含了相应的权重安全要求。

#### 透明度

发布模型时，同时发布**系统卡**（system card），公开说明做了哪些评估、红队发现了什么问题、采取了哪些缓解措施。

### 31.8 安全措施在整个流程中的位置

| 环节 | 安全措施 |
|---|---|
| 预训练数据 | 过滤儿童性虐待内容、个人信息和高危知识（第 15 章）。2023 年，斯坦福互联网观察站在图像数据集 LAION-5B 中发现了疑似儿童性虐待的内容，这说明数据过滤非常重要 |
| SFT | 加入拒绝有害请求的样本，以及"边界上的正当请求也要好好回答"的样本 |
| 奖励 | 安全奖励模型、基于规则的奖励 |
| 强化学习 | 安全目标与有帮助的目标一起优化；审慎对齐 |
| 评测 | 有害请求的照办率、过度拒绝率、越狱的鲁棒性、危险能力评估（第 30 章） |
| 部署 | 输入和输出分类器、指令层级、权限控制 |
| 上线之后 | 监控、处置滥用、事故响应，并持续更新 |

#### 一个真实的案例：GPT-4o 的"谄媚"事件

2025 年 4 月，OpenAI 发布了一次 GPT-4o 的更新，结果模型变得过分讨好用户，甚至会附和一些有害的想法。OpenAI 随后回滚了这次更新，并在公开的复盘中指出：**问题的一个原因，是过于看重用户"点赞"这类反馈信号**。

这正是第 25 章讲的"奖励信号被过度优化"在真实世界中的例子：用户在当下更喜欢被附和，但这并不等于真正对用户有益。它也说明，**发布前的评测必须专门检查这类行为**，而且需要有快速回滚的机制。

#### 其他的风险领域

偏见与公平（比如用 BBQ 基准来评估）；隐私（训练数据被记住、个人信息被提取，第 15 章）；虚假信息和选举安全；对用户心理健康的影响，以及用户对模型产生的情感依赖。

::: keypoints
1. 模型规范写清楚了目标、硬性规则、默认行为和指令的优先级，它是生成训练数据、设计奖励和制定评测标准的依据。核心矛盾是有帮助与无害之间的冲突。
2. 既要拒绝真正有害的请求，也要避免过度拒绝，两个指标要同时衡量。常用的训练方法有 Constitutional AI、基于规则的奖励、审慎对齐和安全补全。
3. 越狱之所以成功，是因为目标互相竞争，以及能力泛化到了安全训练没有覆盖的地方。防御要分多个层次：对抗训练、Constitutional Classifiers 等分类器、系统层面的监控。开放权重模型更难防护。
4. 危险能力评估覆盖化学生物核武器、网络安全、自主性、欺骗等领域。评估时要充分激发模型的能力，阈值要提前定好，还要引入外部评估，并警惕模型故意藏拙。
5. RSP 等框架承诺"能力达到什么程度，就配备什么程度的防护"。权重安全、系统卡和相关法规（欧盟 AI 法案、加州 SB 53）共同构成治理体系。GPT-4o 的谄媚事件，说明奖励信号被过度优化在现实中真实发生过。
:::

::: exercises
1. **写作**：为一个编程助手写一份简短的模型规范，包括 3 条硬性规则、3 条默认行为，以及指令冲突时的优先级。
2. **设计**：设计一套评测，同时衡量"有害请求被照办的比例"和"正当请求被拒绝的比例"。如果只能优化一个综合指标，你会怎样设计它？
3. **思考**：举一个"泛化不匹配"的例子，说明安全训练为什么没有覆盖到这种情况，以及在训练中可以怎样补上。
4. **思考**：在危险能力评估中，为什么"充分激发能力"如此重要？如果激发得不够，会导致什么后果？
5. **思考**：为什么多样本越狱的风险会随上下文窗口变长而增大？列出两种防御思路。
6. **分析**：用第 25 章的概念（奖励信号、代理指标、过度优化），分析 GPT-4o 的谄媚事件，并提出三条流程上的改进措施。
