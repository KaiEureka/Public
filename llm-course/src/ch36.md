## 第 36 章　公司运营 {#ch36 .chapter}

::: goals
- 列出一家大模型公司的全部成本构成，并做出数量级的预算；
- 设计团队的组织结构，知道各个岗位分别对应本书的哪些章节；
- 制定研发路线图，管理"一次训练失败就损失上千万美元"这类风险；
- 理解开源与闭源的取舍；
- 了解主要的商业模式、单位经济模型和融资环境；
- 为一家新公司选择合适的战略定位。
:::

本章涉及公司财务的数字，都来自公开报道或研究机构的估算，**只能作为量级参考**。标为"示意"的预算，是根据前面各章的数字搭出来的，不是任何一家公司的真实账目。

### 36.1 一家大模型公司的本质

一家大模型公司要做的，是**持续地**训练出有竞争力的模型，并把它们变成收入。它同时受到五样东西的约束：**算力**、**人才**、**数据**、**资本**、**分发渠道**（有没有用户，有没有企业客户）。技术只是其中一环，很多技术很强的团队，最后败在了资本或分发上。

### 36.2 算力经济学

#### 成本构成

| 类别 | 说明 | 参考 |
|---|---|---|
| **最终训练** | 报告里写的那个数字 | DeepSeek-V3 的最终训练约 278.8 万 H800 卡时，按每卡时 2 美元计算，约 560 万美元。Llama 3.1 405B 约用了 3,084 万 H100 卡时，按同样的价格约 6,000 万美元。OpenAI 曾表示 GPT-4 的训练花了"超过 1 亿美元" |
| **研究与消融实验** | 规模阶梯、数据消融、架构实验、失败的尝试（第 0、10、16 章） | 常常和最终训练是同一个量级，甚至更多。DeepSeek 明确说明，560 万美元不包括这部分 |
| **后训练** | SFT、偏好优化、大规模强化学习（第 24 到 29 章） | 占比正在快速上升（第 27 章） |
| **推理服务** | 用户越多，花得越多（第 10、33 章） | 对一个被大量使用的模型来说，这往往是长期来看最大的一块 |
| **数据** | 版权授权、人工标注（尤其是专家标注）、合成数据所需的算力 | 专家级的标注非常贵 |
| **人员** | 顶尖研究员和工程师的薪酬很高 | — |
| **其他** | 存储、网络、安全、法务、合规 | — |

Epoch AI（Cottier 等，2024）分析了前沿模型的训练成本，发现：**最大规模训练的成本，每年增长约 2.4 倍**；成本构成中，硬件的折旧占 47% 到 67%，研发人员占 29% 到 49%，电费只占 2% 到 6%。

#### 推理的单位经济

回顾第 33 章：每百万 token 的成本 = GPU 每小时的成本 ÷ 每小时能生成的 token 数，利用率决定一切，包括 batch 开多大、白天和夜里的负载差异、前缀缓存的命中率。

- **同等能力的价格在快速下降。** Epoch 的研究发现，达到同一水平所需的价格，每年下降的幅度从几倍到几百倍不等，具体取决于看的是哪个水平。
- DeepSeek 在 2025 年公开的线上数据显示，按他们的定价，理论上的成本利润率可以达到 545%（第 34 章）。这说明推理服务**可以**有很高的利润，前提是系统优化得足够好、利用率足够高。

#### 示意预算：做一个 DeepSeek-V3 级别的模型，第一年要花多少

以下按租用算力、每卡时 2 美元来估算（{{fig-ch36-budget}}）：

| 项目 | 估算 | 依据 |
|---|---|---|
| 最终预训练 | 约 600 万美元 | $3.3\times10^{24}$ FLOP（第 0 章） |
| 研究与消融实验 | 1,000 万到 3,000 万美元 | 最终训练的 2 到 5 倍 |
| 后训练（含强化学习） | 数百万到上千万美元 | 视强化学习的规模而定 |
| 数据（授权 + 标注 + 合成） | 1,000 万美元以上 | — |
| 人员（约 100 人） | 约 5,000 万美元 | 按人均全口径年成本约 50 万美元计 |
| **合计（不含推理服务、不含自建集群）** | **约 1 亿到 2 亿美元** | — |

如果要**自建集群**，硬件就要几亿到十几亿美元（第 18 章）。而如果模型上线后被大量使用，推理服务的成本还会持续增长。

### 36.3 团队与组织

#### 岗位和本书的对应关系

| 团队 | 职责 | 对应章节 |
|---|---|---|
| 预训练研究 | 架构、scaling、超参数、训练配方 | 第 6–13 章 |
| 数据 | 采集、清洗、配比、合成、合规 | 第 14–17 章 |
| 基础设施与系统 | 集群、训练框架、内核、运维 | 第 18–23 章 |
| 推理 | 服务、量化、加速、成本 | 第 33、34 章 |
| 后训练 | SFT、强化学习、推理能力、Agent、蒸馏 | 第 24–29 章 |
| 评测 | 内部评测体系、去污染 | 第 17、30 章 |
| 安全、对齐与可解释性 | 模型规范、红队、危险能力评估、可解释性 | 第 31、32 章 |
| 多模态 | 视觉、语音、生成 | 第 35 章 |
| 产品与应用 | API、应用、企业解决方案、开发者关系 | — |
| 运营与支持 | 算力采购、财务、法务、政策、安全、标注供应商管理 | 第 14、18、31 章 |

#### 规律

- **基础设施往往是工程师最多的团队。**
- **研究和工程之间没有明确的界线**："研究工程师"是最核心的角色，既要提出想法，又要能在上千张卡上把它跑起来。
- **小团队也能做出前沿成果**：Mistral 在 2023 年 4 月成立，同年 9 月就发布了 Mistral 7B；DeepSeek 的团队规模不大，据报道成员以年轻的应届生为主。关键在于人才密度，以及研究与基础设施之间配合得有多紧密。

#### 初创公司招人的优先顺序（建议）

1. 基础设施负责人，以及集群（没有集群，什么都做不了）；
2. 预训练负责人；
3. 数据负责人；
4. **尽早建立评测**（第 30 章：评测是一切决策的指南针）；
5. 后训练团队；
6. 安全团队，要从一开始就参与，而不是等到发布前才补上；
7. 产品团队。

### 36.4 路线图与风险管理

#### 研发的节奏

- **预训练**：大规模训练不频繁，每次投入巨大。每一次都要先用 1/100、1/10 规模的"去风险"训练做验证，再由评审决定是否正式开跑。
- **后训练**：快得多，也便宜得多，可以每隔几个月就发布一个新版本。
- **并行推进**：一边跑当前这一代的正式训练，一边研究下一代的架构和数据。

#### 正式开跑前的检查清单

| 检查项 | 依据 |
|---|---|
| scaling law 预测的 loss 和下游能力，达到了目标吗？ | 第 10 章 |
| 超参数迁移和稳定性，在去风险训练中验证过了吗？ | 第 11、12 章 |
| 数据准备好了吗？去过污染吗？合规审核通过了吗？ | 第 14–17 章 |
| 集群通过验收了吗？MFU 达标了吗？检查点和自动重启经过演练了吗？ | 第 18–23 章 |
| 预算和时间表还有余量吗？ | — |

#### 风险清单

| 风险 | 应对 |
|---|---|
| 训练不稳定或失败 | 去风险训练、频繁保存检查点、回滚预案（第 12、23 章） |
| 数据的版权和污染问题 | 记录数据来源、法务审核、去污染（第 14、17 章） |
| 硬件交付延迟、供应短缺 | 多个供应商，用云上的算力补位 |
| 竞争对手抢先发布，模型发布即过时 | 寻找差异化；让后训练能快速迭代 |
| 关键人员流失 | 写好文档，保留训练日志，避免知识集中在少数人手里 |
| 权重被盗 | 完善的安全体系（第 31 章） |
| 法规变化 | 关注各地的立法动态，提前满足合规要求 |
| **巨额投入的回报不如预期** | 用 scaling law 预测回报；并行发展推理和后训练等更划算的路线 |

最后一条有一个真实的例子：OpenAI 在 2025 年 2 月发布了 GPT-4.5，这是一次规模很大的预训练，但它的提升幅度不如同期的推理模型，推理成本却很高。几个月之后，OpenAI 宣布在 API 中下线它。这说明**算力投入并不会自动转化为商业回报**。

### 36.5 开源还是闭源

| | 开放权重 | 闭源 |
|---|---|---|
| 代表 | Llama、DeepSeek、Qwen、Gemma、Mistral 的部分模型、OpenAI 的 gpt-oss | OpenAI、Anthropic 的旗舰模型，Google 的 Gemini |
| 好处 | 被广泛采用，形成生态；吸引人才；社区帮忙贡献改进；满足用户对信任和"数据主权"的需求；可以把竞争对手赖以盈利的东西变成免费的 | 可以通过 API 和产品直接赚钱；可以控制滥用；可以保持领先优势 |
| 代价 | 没法直接靠模型本身赚钱；竞争对手也能用；**安全措施很容易被移除**（第 31、32 章）；更容易受到监管审视 | 必须证明自己值得比开源模型付更多的钱 |

**混合策略很常见**：开放小模型，保留最强的旗舰模型。比如 Google 开放了 Gemma，但 Gemini 是闭源的；OpenAI 在 2025 年 8 月开放了 gpt-oss。

**许可证的细节很重要**："开放权重"不等于"开源"，按照开源促进会（OSI）的定义，开源需要同时公开数据和代码；Llama 的许可证有限制条款，比如月活跃用户超过 7 亿的公司需要另行获得授权；DeepSeek-R1 用的是 MIT 许可证，Qwen 的很多模型用的是 Apache 2.0，这些都更宽松。

### 36.6 商业模式

| 模式 | 说明 |
|---|---|
| **API（按 token 计费）** | 面向开发者和企业。价格竞争激烈，提示缓存会带来折扣（第 33 章） |
| **个人订阅** | 比如 ChatGPT 的每月 20 美元和 200 美元两档，Claude 也有 Pro 和 Max 等档位 |
| **企业服务** | 按席位收费、私有化部署、定制微调；受监管的行业往往需要在本地部署 |
| **Agent 和垂直产品** | 编程 Agent（Claude Code、Codex，以及 Cursor 这样的第三方产品）已经成为重要的收入来源 |
| **与云厂商合作** | 比如微软 Azure 与 OpenAI，AWS、Google 与 Anthropic |
| **开源公司的变现方式** | 提供技术支持、托管服务、企业版许可；或者获得国家和战略层面的资金支持 |

**单位经济**：毛利 = 收入 − 推理成本。按月订阅的用户中，如果有人用量特别大，公司在他身上可能是亏钱的，所以订阅产品都会设置用量上限。

### 36.7 资本与融资

**这是一个资本极度密集的行业**：算力需要提前很久签约锁定。投资方包括风险投资、战略投资者（云厂商、芯片厂商）以及主权基金。

**近期的环境**（据公开报道，2025 年）：出现了一批超大额的融资，比如 OpenAI 由软银领投的约 400 亿美元，Anthropic 约 130 亿美元的 F 轮，Mistral 由 ASML 领投的约 17 亿欧元；宣布了 Stargate 这样的超大规模基础设施计划（规划规模达 5,000 亿美元），各大科技公司的资本开支也在大幅增加；头部实验室的年化收入增长很快，但投入更大。

**行业在整合**：2024 年，有几家做前沿模型的初创公司，以"许可协议 + 核心团队加入大公司"的方式退出了独立竞争：Inflection 与微软，Character.AI 与 Google，Adept 与亚马逊。**这说明独立训练前沿模型的门槛在不断提高。**

**融资时要讲清楚的事**：团队（人才密度和过往的成果）；算力从哪里来；技术和数据上有什么差异化；分发渠道；以及怎样走到营收。

#### 新进入者的几种战略定位

| 定位 | 要求 | 例子 |
|---|---|---|
| 通用前沿模型 | 数十亿美元以上的资本 | OpenAI、Anthropic、Google、xAI |
| **用工程效率追赶前沿** | 顶尖的工程能力；接受硬件受限的条件 | DeepSeek |
| 专精某个领域 | 领域数据和领域客户 | 代码、法律、医疗、语音、小模型和端侧模型、多语言或主权模型 |
| 在开源模型上做后训练和产品 | 后训练能力和产品能力 | 大量应用层的公司 |

### 36.8 文化与流程

- **反馈要快**：从想法到小规模实验，再到结论，周期越短越好；
- **评测优先**：没有可靠的评测，就不要做决策（第 30 章）；
- **一切都要记录**：训练日志、决策的过程和理由（第 23 章）；
- **可复现**：数据、代码和配置都要做版本管理；
- **重视安全**：既包括权重和数据的安全，也包括模型本身的安全，并且要融入日常的流程中（第 31 章）；
- **想清楚发表策略**：哪些成果公开发表、哪些开源，要和公司的战略一致。

**合规清单（回顾）**：数据授权（第 14 章）、隐私（第 15 章）、出口管制（第 18 章）、各地的 AI 法规和安全框架（第 31 章）、内容溯源（数字水印、C2PA 等标准）。

::: keypoints
1. 成本包括最终训练、研究和消融实验（往往与最终训练同一量级）、后训练、推理服务（长期往往最大）、数据和人员。最大规模训练的成本每年增长约 2.4 倍，其中硬件占大头，电费只占很小一部分。一个 DeepSeek-V3 级别的项目，第一年大约需要 1 亿到 2 亿美元（示意，不含自建集群和推理服务）。
2. 团队按"预训练、数据、基础设施、推理、后训练、评测、安全、多模态、产品、运营"来组织。基础设施往往人数最多，研究工程师是核心角色，人才密度比人数更重要。
3. 研发的节奏是：预训练不频繁、规模巨大，必须先做去风险训练，并通过开跑前的检查；后训练迭代快。要维护一份风险清单。GPT-4.5 的例子说明，算力投入不一定能换来商业回报。
4. 开放权重带来生态和人才，但安全措施容易被移除，也难以直接变现；闭源可以直接变现，也便于控制风险。混合策略很常见，许可证的细节很重要。
5. 主要的商业模式有 API、订阅、企业服务、Agent 产品和云合作。这个行业资本极度密集，正在整合。新进入者要在"通用前沿、工程效率、垂直领域、基于开源做后训练"中选好自己的定位。
:::

::: exercises
1. **预算**：用本章的示意方法，为一个"30B 激活参数、600B 总参数的 MoE 模型，训练 20T token"的项目做第一年的预算。分别算出最终预训练、研究消融、后训练、数据和人员的费用。
2. **组织**：你有 60 个人的名额，请分配到 36.3 节的各个团队，并说明理由。如果只有 20 个人呢？
3. **风险**：为一次计划跑 3 个月、价值 3,000 万美元的预训练写一份风险清单，至少包括 6 项风险，分别给出发生的可能性、影响和应对措施。
4. **决策**：你的公司刚训练出一个 30B 的模型，在多个基准上接近闭源的前沿模型。写一份半页纸的建议，说明它该开源还是闭源，用什么许可证，以及理由。
5. **定价**：用第 33 章的成本模型，为一个 70B 模型的 API 定价：输入和输出 token 分别定多少钱，才能在 60% 的平均利用率下实现 50% 的毛利率？
6. **战略**：如果你今天拿到 2 亿美元创业，你会选择 36.7 节中的哪种定位？写出你的理由，以及前 12 个月的里程碑。
:::
