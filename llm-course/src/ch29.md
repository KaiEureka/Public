## 第 29 章　蒸馏与小模型 {#ch29 .chapter}

::: goals
- 掌握两种蒸馏方式：基于 logits 的蒸馏和基于数据的蒸馏，并理解"软标签"为什么更高效；
- 理解前向 KL 和反向 KL 的区别；
- 理解在线蒸馏，以及它和强化学习的关系；
- 了解"剪枝 + 蒸馏"的做法（Minitron、Llama 3.2）；
- 掌握小模型的训练要点和容量上限；
- 知道蒸馏能做到什么、做不到什么。
:::

为什么需要小模型？推理便宜、速度快（第 4、10 章）；可以部署在手机、电脑等终端设备上，数据不出本地，有利于隐私；对很多任务来说，小模型已经够用了。**蒸馏**就是让一个小的**学生**模型去模仿一个大的**教师**模型。

### 29.1 基于 logits 的蒸馏（软标签）

#### 做法

Hinton 等（2015）的做法是：在每一个位置上，让学生的输出分布去逼近教师的**完整**输出分布，

$$
\mathcal{L} = \mathrm{KL}\big(p_{\text{教师}}\,\big\|\,p_{\text{学生}}\big),
$$

逐 token 计算，通常再和普通的交叉熵 loss 加权相加。还可以引入一个温度 $\tau$，用 $\operatorname{softmax}(z/\tau)$ 把教师和学生的分布都变得更平缓，这时 loss 要再乘以 $\tau^2$，以保持梯度的量级不变（习题 1）。

#### 为什么比只看"正确答案"更好

普通训练用的是**硬标签**：每个位置只告诉模型"下一个 token 是什么"。而教师的完整分布里还包含大量额外的信息，比如"哪些答案也有一定道理、各自有多大可能"，Hinton 称之为**暗知识**（{{fig-ch29-soft}}）。所以每个训练位置能提供多得多的信息。

::: experiment
**软标签与硬标签。** 用第 1 章的字符级 bigram 模型当"教师"，它在验证集上的 loss 是 2.482。学生也是一个 bigram 表，只能从 $M$ 个训练位置学习：硬标签是在每个位置按教师的分布抽一个字符作为答案；软标签是在每个位置直接使用教师的完整概率分布。表中是学生在验证集上的 loss：

| 训练位置数 $M$ | 学生用硬标签 | 学生用软标签 |
|---|---|---|
| 300 | 3.302 | **2.908** |
| 1,000 | 2.896 | **2.645** |
| 3,000 | 2.687 | **2.545** |
| 10,000 | 2.560 | **2.499** |
:::

用 1,000 个位置的软标签（2.645），比用 3,000 个位置的硬标签（2.687）还要好。**在这个例子里，软标签的样本效率大约是硬标签的 3 倍。**

<figcaption>软标签与硬标签</figcaption>
</figure>

#### 实际中的困难与做法

- **存储完整的 logits 不现实**：词表有 12.8 万个 token，用 BF16 存一个位置的完整分布要 256 KB，乘以上万亿个 token，根本存不下。常见的做法有两种：只保存概率最高的几十个 token；或者在训练学生的同时运行教师模型，即时计算它的输出。
- **Gemma 2**（2024）：2B 和 9B 的模型在预训练阶段**用蒸馏代替了普通的下一个 token 预测**，用一个更大的模型作为教师，训练用的 token 数也远超 Chinchilla 的最优值。**Gemma 3** 的所有尺寸都使用了蒸馏，每个位置按教师的概率采样 256 个 logits 作为目标。
- **Llama 3.2 的 1B 和 3B**：在预训练阶段，把 Llama 3.1 8B 和 70B 的 logits 作为每个 token 的学习目标。

### 29.2 前向 KL 与反向 KL

| | 前向 KL：$\mathrm{KL}(\text{教师}\,\|\,\text{学生})$ | 反向 KL：$\mathrm{KL}(\text{学生}\,\|\,\text{教师})$ |
|---|---|---|
| 倾向 | **覆盖所有模式**：教师认为可能的地方，学生都必须给一些概率 | **只抓住一个模式**：学生只在自己有把握的地方放概率 |
| 学生容量不足时 | 可能把概率摊得很开，生成"几种答案的混合体"，什么都不像 | 只学会其中一种，但学得很像 |

::: experiment
**教师是一个有两个峰的分布**（两个峰分别在 −2 和 +2，标准差为 0.5），**学生只能是一个单峰的高斯分布**：

| 最小化的目标 | 学生的均值 | 学生的标准差 | 含义 |
|---|---|---|---|
| 前向 KL | +0.00 | 2.06 | 横跨两个峰，中间那一大片区域教师其实认为几乎不可能 |
| 反向 KL | −2.00 | 0.50 | 只准确地抓住了其中一个峰（{{fig-ch29-kl}}） |
:::

对语言模型来说，"把概率摊开"可能意味着生成教师根本不会写的句子。所以有一些工作（比如 MiniLLM，2023）在生成任务的蒸馏中使用**反向 KL**。

### 29.3 基于数据的蒸馏

**做法**：用教师模型生成文本，然后用这些文本对学生做 SFT（Kim 与 Rush，2016，称为**序列级蒸馏**）。

**优点**：不需要教师的 logits，只要能调用教师模型就行，哪怕只能通过 API 调用。

**例子**：Alpaca、Vicuna 等早期的开源聊天模型（第 24 章）；Orca（微软，2023），用 GPT-4 生成带有详细解释的回答；Phi 系列（第 17 章）；**DeepSeek-R1-Distill**，用 80 万条 R1 生成的数据对 Qwen 和 Llama 的小模型做 SFT（第 27 章），其中 32B 的 Qwen 版本在 2024 年 AIME 上的单次正确率达到 72.6%。

**局限**：

- 教师的错误和幻觉，会原样传给学生；
- 学生和教师的能力差距太大时，学生只学到了说话的风格，却没学到真正的能力（第 24 章的"模仿不等于能力"）；
- **学生只见过教师写的开头，从没见过自己犯错之后的样子。** 到了实际使用中，一旦自己写错了一步，就不知道该怎样继续。这与第 25 章说的 SFT 的局限是同一回事。

### 29.4 在线蒸馏

**做法**：**让学生自己生成回答**，然后让教师对学生生成的每一个 token 打分，通常是计算这一位置上学生分布与教师分布之间的反向 KL，用它作为学习信号。它结合了两种方法的优点：

| | 强化学习（第 27 章） | 基于数据的蒸馏 | **在线蒸馏** |
|---|---|---|---|
| 学的是谁生成的数据 | 学生自己（好） | 教师 | **学生自己（好）** |
| 反馈有多密集 | 每个回答只有一个奖励 | 每个 token 都有（好） | **每个 token 都有（好）** |

学生在自己真实会犯的错误上得到反馈，学会怎样从错误中恢复；同时每个 token 都有教师的指导，学习信号比强化学习密集得多（{{fig-ch29-three}}）。

<figure id="fig-ch29-three" data-svg="ch29_three.svg">
<figcaption>基于数据的蒸馏、强化学习与在线蒸馏</figcaption>
</figure>

**例子**：GKD（Agarwal 等，2023）是这个方向较早的系统性工作；**Qwen3** 的小模型采用了"从强到弱的蒸馏"：先做离线蒸馏，再做在线蒸馏，他们报告说，与直接做强化学习相比，所需的 GPU 时间只有约十分之一，效果却更好；Thinking Machines 在 2025 年的文章中也报告了类似的结论：在线蒸馏能以远低于强化学习的计算量，达到相近的效果。

### 29.5 剪枝 + 蒸馏

**思路**：不从零开始训练小模型，而是**从大模型上"裁剪"出一个小模型**，再用蒸馏把它的能力恢复回来。

**Minitron**（NVIDIA，2024，见{{fig-ch29-prune}}）：

1. 用一小批校准数据跑一遍大模型，根据激活值的大小，评估每一层、每个注意力头、每个 MLP 神经元、每个隐藏维度的重要性；
2. 裁掉不重要的部分。可以减少宽度，即砍掉头、神经元和隐藏维度；也可以减少深度，即删掉整层；
3. 用原始的大模型做教师，进行 logits 蒸馏，把被裁剪的模型训练回来。

他们从 Nemotron-15B 裁剪出了 8B 和 4B 的模型。与从零开始训练相比，每个模型**所需的训练 token 最多减少到约 1/40**。他们还发现，在同样的目标大小下，**减少宽度通常比减少深度效果更好**。

<figure id="fig-ch29-prune" data-svg="ch29_prune.svg">
<figcaption>剪枝 + 蒸馏的流程</figcaption>
</figure>

**Llama 3.2 的 1B 和 3B** 也是这样做的：从 Llama 3.1 8B 做结构化剪枝，再用 8B 和 70B 的 logits 做蒸馏。

### 29.6 训练小模型的要点

- **大量过度训练**（第 10 章）：Llama 3.2 的 1B 和 3B 最多训练了约 9T token；Qwen3 的 0.6B 到 4B 同样用了约 36T token；SmolLM2 的 1.7B 训练了 11T token。
- **共享输入嵌入和输出层**（第 5、7 章）。对小模型来说，嵌入层占的比例很大。比如 Gemma 2 2B 的词表约有 25.6 万个 token，仅嵌入层就有约 5.9 亿参数，而模型总共只有约 26 亿参数。
- **数据质量更重要**：小模型的容量有限，更要把它用在高质量的数据上（第 16 章）。
- **使用大模型的 logits 作为学习目标**（29.1 节）。
- **面向终端部署时，做量化感知训练**：在训练中就模拟低精度带来的误差，让模型适应 4 位等低精度格式，比如 Gemma 3 就提供了这种版本（第 34 章）。

#### 容量的上限：知识存储有极限

Allen-Zhu 与 Li 在"语言模型物理学"系列研究中发现，**每个参数大约能存储 2 比特的知识**，前提是这些知识在训练中出现过足够多次。照这个估算，一个 1B 的模型大约能存 20 亿比特，也就是约 250 MB 的事实性知识。**所以小模型在事实性问答上天然吃亏**，更适合配合检索和工具来使用（第 28 章）。

### 29.7 蒸馏能做到什么，做不到什么

**能做到的**：把推理方式、风格和各种任务技能高效地迁移到小模型上；软标签让学生学得更快；把能力压缩进更便宜的模型里。

**做不到的**：

- **一般不能超过教师。** 少数情况下，如果在蒸馏时用验证器筛掉错误的答案，学生可能在特定任务上超过教师；
- **突破不了容量的上限**：小模型装不下大模型的全部知识；
- **教师和学生的差距不宜太大**：有研究发现，教师过于强大时，蒸馏的效果反而会变差，这时可以引入一个中等大小的"助教"模型作为过渡（Mirzadeh 等，2019）。

**蒸馏的 scaling 规律**：Apple 的研究（Busbridge 等，2025）发现，如果已经有一个现成的教师，或者要用同一个教师训练很多个学生，蒸馏就很划算；但如果教师需要专门为此去训练，而且算力和数据都很充足，那么直接训练小模型最终也能追上。

**其他问题**：**服务条款**，很多商业模型禁止用它们的输出去训练有竞争关系的模型（第 17 章）；**安全行为不一定能迁移**，蒸馏出来的小模型，不一定可靠地继承了教师在安全方面的行为，需要单独评估和训练（第 31 章）。

::: keypoints
1. 基于 logits 的蒸馏，用 KL 散度让学生逼近教师的完整分布。软标签携带"暗知识"，实验中样本效率约为硬标签的 3 倍。实际中会保存概率最高的部分 logits，或者即时运行教师。Gemma 2/3 和 Llama 3.2 都在预训练中使用了蒸馏。
2. 前向 KL 会让学生覆盖教师的所有模式（实验中，学生的标准差变成了 2.06，横跨两个峰），反向 KL 会让学生只抓住一个模式。生成任务中常用反向 KL。
3. 基于数据的蒸馏只需要用教师生成的文本做 SFT，比如 R1-Distill；但教师的错误会一起传下去，而且学生没见过自己犯错之后的情形。在线蒸馏让学生在自己生成的回答上接受教师逐 token 的指导，结合了强化学习和蒸馏两者的优点（Qwen3 的做法）。
4. "剪枝 + 蒸馏"从大模型裁剪出小模型，再用蒸馏把能力恢复回来（Minitron 最多节省约 40 倍的训练 token）。减少宽度通常比减少深度效果更好。
5. 训练小模型要大量过度训练、共享嵌入、使用高质量数据。每个参数大约只能存 2 比特的知识，所以小模型适合搭配检索和工具使用。蒸馏一般不能超过教师，也突破不了容量的上限。
:::

::: exercises
1. **推导**：用温度 $\tau$ 做蒸馏时，为什么 loss 要乘以 $\tau^2$？（提示：看梯度的大小怎样随 $\tau$ 变化。）
2. **计算**：词表有 128,256 个 token，用 BF16 存储，为 1T 个 token 保存完整的教师分布需要多少存储空间？如果每个位置只保存概率最高的 64 个 token（每个记录 4 字节的编号和 2 字节的概率），又需要多少？
3. **思考**：在 29.1 节的实验中，为什么随着 $M$ 增大，软标签和硬标签之间的差距会越来越小？
4. **思考**：用前向 KL 蒸馏出来的小模型，在生成长文本时可能会出现什么问题？用反向 KL 蒸馏出来的又可能有什么问题？
5. **比较**：在线蒸馏和 GRPO 都是让学生自己生成回答，它们的学习信号有什么本质区别？各自适合什么场景？
6. **估算**：按"每个参数约 2 比特"来估算，一个 3B 的模型最多能存多少 MB 的事实性知识？如果要做一个离线运行的手机助手，你会怎样设计，才能让它在事实性问答上表现可靠？
:::
