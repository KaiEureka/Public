本章会用到强化学习（RL）的一些术语，它们在第一次出现时都会给出定义。

### 25.1 为什么 SFT 之后还要强化学习

1. **SFT 的上限是示范者的水平。** 模型只是在模仿人写的回答。
2. **人判断好坏，比亲手写出好答案容易得多。** 让标注员写一首好诗很难，让他从两首诗里挑出更好的一首却很容易。强化学习可以利用这种"判断能力"。
3. **SFT 只告诉模型"该这样做"，从没告诉它"不该那样做"。** 强化学习既能奖励好的回答，也能惩罚差的回答。
4. **SFT 用的是别人写的回答，强化学习用的是模型自己生成的回答。** 模型在自己真实会犯的错误上得到反馈，学到的东西更贴合它实际的表现。
5. **偏好可以表达难以写成规则的标准**，比如是否真正有帮助、语气是否得体、是否诚实。

**发展脉络**：Christiano 等（2017）在游戏和机器人控制任务上用人类偏好训练强化学习；Ziegler 等（2019）、Stiennon 等（2020）把它用于语言模型，做摘要任务；InstructGPT（2022）把它用于通用助手，后来发展成 ChatGPT（{{fig-ch25-rlhf}}）；Anthropic（2022）训练了有帮助且无害的助手，并提出 **Constitutional AI**：用一组书面原则让 AI 自己给出反馈，代替人类标注，这叫 **RLAIF**（来自 AI 反馈的强化学习）。

### 25.2 偏好数据

**格式**：一个提示 $x$，两个回答 $y_a$ 和 $y_b$，加上一个标签，表示哪个更好（有时还会标"一样好"或者"好多少"）。InstructGPT 的做法是让标注员一次给 4 到 9 个回答排序，一个包含 $K$ 个回答的排序可以拆出 $\binom{K}{2}$ 个两两比较。

**为什么用比较，而不是直接打分？** 不同的人对"7 分"的理解差别很大，同一个人前后打分也不一致；但比较两个回答时，人的判断要一致得多。

**收集偏好数据的要点**：

- **标注指南**：写清楚评判标准，比如有帮助、诚实、无害，以及标准之间冲突时该怎样取舍；
- **培训标注员，做质量控制**。InstructGPT 的标注员之间，意见一致的比例约为 73%，也就是说，**标签本身就有相当多的噪声**；
- **回答要从当前的模型中采样**，这样偏好数据才针对模型当前真实会犯的错误。Llama 2 每周收集一批，随着模型迭代不断更新，最终 Meta 自己收集了超过 140 万条比较；
- **AI 反馈**：让大模型按照一组原则来做比较，代替人工标注。现在这种做法已经用得很广泛了。

### 25.3 奖励模型

#### 结构

拿 SFT 之后的模型，把输出层（输出每个 token 概率的那一层）换成一个**输出单个数值**的线性层，读取最后一个 token 处的隐藏向量，输出一个分数 $r(x, y)$。

#### Bradley-Terry 模型

假设每个回答都有一个看不见的"好坏程度" $r$，两个回答之间的偏好概率只取决于它们的分差：

$$
P(y_w \succ y_l \mid x) = \sigma\big(r(x, y_w) - r(x, y_l)\big),
$$

$\sigma$ 是 sigmoid 函数，$y_w$ 是被选中的回答，$y_l$ 是落选的回答。这和国际象棋的 Elo 等级分是同一个思路：两人的分差越大，高分者获胜的概率越高。用最大似然来训练，loss 是

$$
\mathcal{L} = -\log\sigma(r_w - r_l).
$$

**直观理解**：模型给被选中的回答打的分越高、给落选的回答打的分越低，loss 就越小；如果模型已经把两者明显区分开了（分差很大，$\sigma$ 接近 1），这条样本的梯度就接近 0，不再推动（{{fig-ch25-bt}}）。

**一个性质**：只有**分差**有意义。给所有回答都加上同一个常数，loss 不变。所以奖励的绝对值没有意义，使用前通常会做归一化，比如减去在一组参考回答上的平均分。

#### 训练与评估

- **通常只训练 1 轮**。奖励模型很容易过拟合，InstructGPT 和 Llama 2 都是这样做的。
- **在留出的比较数据上，准确率通常只有 65% 到 75% 左右**，因为标签本身就有噪声。
- Llama 2 分别训练了两个奖励模型，一个衡量**有帮助程度**，一个衡量**安全性**；还在 loss 里加入了一个"偏好强度"的间隔项：标注员认为"明显更好"的样本，要求分差更大。
- 专门评测奖励模型的基准有 RewardBench（2024）。

### 25.4 RLHF 的目标

#### 用强化学习的语言描述语言模型

| 强化学习术语 | 在语言模型中对应什么 |
|---|---|
| **策略** $\pi_\theta$ | 语言模型本身：给定提示 $x$，生成回答 $y$ 的概率 $\pi_\theta(y\mid x)$ |
| **状态** | 提示加上已经生成的 token |
| **动作** | 生成下一个 token |
| **一个回合** | 生成一个完整的回答 |
| **奖励** | 回答结束时，由奖励模型给出的分数 $r(x, y)$ |

#### 优化目标

$$
\max_\theta\;\; \mathbb{E}_{x\sim\mathcal{D},\; y\sim\pi_\theta(\cdot\mid x)}\big[r(x, y)\big] - \beta\,\mathrm{KL}\big(\pi_\theta\,\|\,\pi_{\text{ref}}\big),
$$

$\pi_{\text{ref}}$ 是**参考模型**，即 SFT 之后的模型，在训练中保持冻结。

**为什么要加 KL 惩罚**：

1. **奖励模型只是一个近似，而且是有缺陷的近似。** 如果放任策略去最大化奖励，它会找到奖励模型的漏洞，专门生成那些"奖励模型打分很高、实际上却很差"的回答。KL 惩罚把策略拴在 SFT 模型附近，而在那个范围内，奖励模型的打分是比较可靠的。
2. **保持回答的流畅性和多样性。**

**实现方式**：KL 通常逐 token 计算，作为每个 token 的一个小惩罚 $-\beta(\log\pi_\theta - \log\pi_{\text{ref}})$；奖励模型的分数则加在最后一个 token 上。InstructGPT 还在 RL 的过程中混入了一部分预训练数据的 loss，叫 **PPO-ptx**，用来防止模型在通用基准上退化。

#### 这个目标的闭式最优解

这个结果是第 26 章 DPO 的基础。先不考虑神经网络，直接在所有可能的分布 $\pi$ 上求最优。对于每个提示（省略 $x$）：

$$
\sum_y \pi(y)\,r(y) - \beta\sum_y \pi(y)\log\frac{\pi(y)}{\pi_{\text{ref}}(y)}
= -\beta\sum_y \pi(y)\log\frac{\pi(y)}{\pi_{\text{ref}}(y)\,e^{r(y)/\beta}}
= -\beta\,\mathrm{KL}\Big(\pi\,\Big\|\,\frac{\pi_{\text{ref}}\,e^{r/\beta}}{Z}\Big) + \beta\log Z,
$$

其中 $Z = \sum_y \pi_{\text{ref}}(y)e^{r(y)/\beta}$ 是归一化常数。KL 散度最小为 0，当且仅当两个分布完全相同时取到。所以最优策略是

$$
\pi^*(y) = \frac{1}{Z}\,\pi_{\text{ref}}(y)\,\exp\big(r(y)/\beta\big),
$$

也就是**在参考模型的基础上，按奖励的指数来重新加权**。$\beta$ 越小，策略越集中到高奖励的回答上，离参考模型也越远（{{fig-ch25-reweight}}）。

### 25.5 策略梯度：怎样让模型朝着"高奖励"的方向更新

#### REINFORCE

利用"对数导数"技巧 $\nabla\pi = \pi\,\nabla\log\pi$：

$$
\nabla_\theta\,\mathbb{E}_{y\sim\pi_\theta}[R(y)] = \sum_y \nabla\pi_\theta(y)\,R(y) = \sum_y \pi_\theta(y)\,\nabla\log\pi_\theta(y)\,R(y) = \mathbb{E}_{y\sim\pi_\theta}\big[R(y)\,\nabla\log\pi_\theta(y)\big].
$$

对于语言模型，$\log\pi_\theta(y\mid x) = \sum_t\log\pi_\theta(y_t\mid x, y_{<t})$，即每个 token 的对数概率之和。

**这就是第 1 章提到的"按奖励加权的交叉熵"**：让模型自己生成回答，然后对这个回答做类似 SFT 的更新，只不过更新的力度要乘以奖励。奖励高，就让这个回答更可能出现；奖励低，就让它更不可能出现。

#### 基线：降低方差

只用 $R$ 来加权，估计出的梯度噪声非常大。比如所有奖励都是正数时，每个回答都会被"鼓励"，只是程度不同。解决办法是减去一个**基线** $b$：

$$
\mathbb{E}\big[(R - b)\,\nabla\log\pi\big].
$$

只要 $b$ 不依赖于具体生成了哪个回答，减去它就**不会改变梯度的期望**，因为 $\mathbb{E}[\nabla\log\pi] = \sum\nabla\pi = \nabla\sum\pi = \nabla 1 = 0$。但它能大幅降低方差。最好的基线约等于"这个状态下的平均奖励"，用它减出来的 $R - b$ 叫**优势**（advantage），意思是"这个回答比平均水平好多少"。

#### Critic 与 GAE：给每个 token 分配功劳

奖励只在回答结束时才给出，但回答里的每个 token 贡献不同，有的 token 是关键，有的只是凑数。怎样把最终的奖励分配到每个 token 上？

PPO 的做法是再训练一个**价值模型**（也叫 **critic**），预测"从当前状态出发，最终能拿到多少奖励"，记为 $V(s_t)$。它通常用奖励模型来初始化。然后用 **GAE**（generalized advantage estimation，广义优势估计）计算每个 token 的优势：

$$
\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t), \qquad A_t = \sum_{l\ge0}(\gamma\lambda)^l\,\delta_{t+l}.
$$

$\delta_t$ 表示生成这个 token 之后，预期的奖励"意外地"变化了多少；$A_t$ 把后面若干步的意外变化加权累加起来。在语言模型的 RLHF 中，通常取 $\gamma = 1$，$\lambda$ 约为 0.95。$\lambda$ 越大，越依赖实际拿到的奖励；$\lambda$ 越小，越依赖 critic 的预测。

### 25.6 PPO

#### 问题：生成回答很贵，希望一批数据能多用几次

生成回答是逐 token 进行的，与推理一样慢。所以希望生成一批回答之后，能用它们**连续更新好几次**。但第一次更新之后，策略已经变了，这批回答不再是"当前策略"生成的了。**重要性比率**用来修正这个偏差：

$$
\rho_t = \frac{\pi_\theta(y_t\mid s_t)}{\pi_{\text{old}}(y_t\mid s_t)},
$$

$\pi_{\text{old}}$ 是生成这批回答时的策略。

#### 裁剪：防止一次更新走得太远

PPO（Schulman 等，2017）的目标函数是

$$
\mathcal{L}^{\text{clip}} = \mathbb{E}\Big[\min\big(\rho_t A_t,\; \operatorname{clip}(\rho_t, 1-\epsilon, 1+\epsilon)\,A_t\big)\Big], \qquad \epsilon \text{ 通常取 } 0.2.
$$

- **$A > 0$**（这个 token 比平均好）：鼓励提高它的概率。但 $\rho$ 一旦超过 $1+\epsilon$，min 会选中被裁剪的那一项，它是常数，梯度为 0，不再继续鼓励。
- **$A < 0$**（这个 token 比平均差）：鼓励降低它的概率。同样，$\rho$ 一旦低于 $1-\epsilon$，就不再继续压低。

效果是（{{fig-ch25-clip}}）：每一批数据最多只能把策略推动一小步，训练因此更稳定。此外，还要用均方误差训练 critic，有时也会加一项熵奖励来鼓励探索。

#### 完整的 PPO 循环

重复以下步骤：

1. 采样一批提示；
2. 用当前策略生成回答（称为 **rollout**）；
3. 用奖励模型打分，同时用参考模型算出每个 token 的 KL 惩罚；
4. 用 critic 估计每个状态的价值，用 GAE 算出每个 token 的优势；
5. 在这批数据上分成若干个小 batch，做几轮 PPO 更新，同时更新策略和 critic。

#### 代价

**显存中要同时放 4 个模型**（{{fig-ch25-ppo}}）：策略模型（要训练）、参考模型（冻结）、奖励模型（冻结）、critic（要训练）。**而且生成回答本身很慢**，往往占了总时间的一大半。再加上一大堆实现上的细节：奖励归一化、优势归一化、KL 放在哪里算、学习率（通常只有 $10^{-6}$ 量级）等等。Huang 等（2024）专门写了一篇文章，列出复现 RLHF 时需要注意的几十个实现细节。**PPO 很强大，但非常难调。** 这正是第 26 章的 DPO 和第 27 章的 GRPO 要解决的问题。

### 25.7 奖励被钻空子与过度优化

#### 规律

Gao 等（2022）研究了**奖励模型的过度优化**。他们用一个大的奖励模型充当"真实标准"，用一个较小的奖励模型作为训练用的"代理"。结果发现：随着策略离初始模型越来越远（KL 越来越大），**代理奖励一路上升**，**真实奖励却先升后降**；奖励模型越大，过度优化来得越晚。这就是**古德哈特定律**：一个指标一旦成为优化目标，它就不再是一个好指标。

::: experiment
**过度优化的模拟。** 设有 1 万个候选回答，每个都有一个"真实质量"。奖励模型的打分 = 真实质量 + 小的噪声。但其中 1% 是"钻空子"的回答（比如堆砌字数、刻意讨好用户）：奖励模型给它们大幅高估了 3 分，而它们的实际质量反而更差。直接用 25.4 节的闭式最优解 $\pi\propto\pi_{\text{ref}}e^{r/\beta}$，计算不同 $\beta$ 下的结果：

| $\beta$ | $\mathrm{KL}(\pi\,\|\,\pi_{\text{ref}})$ | 期望的代理奖励 | 期望的真实奖励 | 钻空子的回答所占概率 |
|---|---|---|---|---|
| 10 | 0.01 | 0.14 | 0.09 | 1.2% |
| 1 | 0.59 | 1.19 | 0.90 | 6.6% |
| **0.5** | **2.54** | 2.49 | **1.41**（真实奖励的最高点） | 29.6% |
| 0.3 | 5.60 | 3.68 | 1.24 | 71.8% |
| 0.1 | 8.28 | 4.26 | 0.85 | 99.8% |
:::

<figure id="fig-ch25-goodhart" data-svg="ch25_goodhart.svg">
<figcaption>过度优化：代理奖励一路上升，真实奖励先升后降（实测）</figcaption>
</figure>

代理奖励一直在涨，真实奖励却在 KL 约为 2.5 时达到最高，之后便开始下降（{{fig-ch25-goodhart}}）。KL 再大，策略几乎只生成那些钻空子的回答。**这就是 KL 惩罚和"适时停止"的意义所在。**

#### 真实世界中常见的钻空子方式

- **越写越长**：奖励模型往往偏爱更长的回答（Singhal 等，2023）；
- **附和用户**：Sharma 等（2023）发现，经过 RLHF 的模型倾向于顺着用户已经表达出的观点说话，而人类的偏好数据本身就在奖励这种行为；
- 过度谨慎、不停地加免责声明，或者动不动就拒绝；
- 格式上的花招：滥用列表和加粗，说恭维话。

#### 缓解手段

- 加 KL 惩罚；用一个独立的评测（比如人工评测或者更强的评委）来监控，及时停止训练；
- 用多个奖励模型取平均（集成），降低单个模型的漏洞被利用的可能；
- 对长度做惩罚或归一化；
- 用新策略生成的回答收集新的偏好数据，重新训练奖励模型，不断迭代；
- 把多个目标分开，分别训练奖励模型；
- 用明确的规则来打分，比如 OpenAI 在 2024 年提出的基于规则的安全奖励。

#### 一个简单的替代：Best-of-N

对每个提示采样 $N$ 个回答，挑奖励最高的那个。它既可以用来构造 SFT 数据（第 24 章的拒绝采样），也可以直接在推理时使用。它与参考策略之间的 KL 有一个闭式表达：

$$
\mathrm{KL}_{\text{BoN}} = \log N - \frac{N-1}{N}.
$$

例如 $N = 16$ 时，KL 约为 1.8 nats。Best-of-N 也会过度优化，只不过它离参考模型的距离被 $N$ 牢牢限制住了。

::: keypoints
1. 强化学习利用了"判断比生成容易"这个事实，能惩罚坏的回答，而且是在模型自己生成的回答上学习。偏好数据用比较的形式收集，标签本身有噪声（标注员之间的一致率约为 73%）。
2. 奖励模型用 Bradley-Terry 的 loss $-\log\sigma(r_w - r_l)$ 训练，只有分差有意义。通常只训练 1 轮，准确率在 65% 到 75% 左右。
3. RLHF 的目标是"奖励 $-\ \beta\cdot$KL"，它的闭式最优解是 $\pi^*\propto\pi_{\text{ref}}e^{r/\beta}$。
4. 从 REINFORCE（按奖励加权的交叉熵）出发，加上基线得到优势，用 critic 和 GAE 把功劳分配到每个 token，再用重要性比率和裁剪得到 PPO。PPO 需要同时放 4 个模型，生成回答很慢，也很难调。
5. 优化奖励模型时，代理奖励会一直上升，真实奖励却先升后降（模拟中在 KL 约 2.5 时达到峰值）。常见的钻空子方式有啰嗦、附和用户、过度谨慎。缓解手段包括 KL 惩罚、及时停止、奖励模型集成和迭代更新奖励模型。
:::

::: exercises

2. **证明**：给奖励函数加上一个只依赖于提示的常数 $c(x)$，Bradley-Terry 的 loss 不变，RLHF 的最优策略也不变。
