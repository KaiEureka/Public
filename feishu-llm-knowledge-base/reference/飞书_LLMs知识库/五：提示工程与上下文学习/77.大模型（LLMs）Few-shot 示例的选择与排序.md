# 77.大模型（LLMs）Few-shot 示例的选择与排序

#### 为什么 few-shot 示例的选择对模型输出有巨大影响？其影响机制是什么？

示例的选择直接决定了模型在上下文学习中“看到”的任务模式，因而对输出有决定性影响。其影响机制可从以下几点理解：

- 任务规范的隐式定义：在上下文学习中，模型没有参数更新，示例是它理解任务的唯一依据。选择的示例定义了输入-输出映射的格式、风格、标签空间乃至推理路径。若示例误导或偏斜，模型会学习到错误的任务分布。

- 注意力分布锚定：Transformer 的注意力机制使模型能够从示例中提取相关信息。与测试输入相似的示例会在注意力矩阵中获得更高权重，直接“复制”其模式。若示例与测试样本不相关，模型难以建立有效映射。

- 标签与格式的偏置引入：示例的标签分布、文本长度、用词风格都会被模型捕捉为“任务先验”。不平衡的示例会导致预测倾向多数类；示例的输出格式会严格约束模型生成格式。

- 隐藏的推理链激活：对于推理任务，示例中的推理步骤会激活模型内部相应的计算路径。选择展现正确推理链的示例有助于模型模仿正确思维过程；错误的推理链则会误导模型。

- 表面模式匹配与虚假相关性：模型可能捕捉示例中的表面特征（如标点、关键词）而非深层语义。如果示例包含与任务无关的统计规律，模型会利用这些捷径，导致泛化失败。

因此，示例选择实质上是在对模型进行“即时微调”。优质示例能清晰、平衡、多样化地展示任务，使模型的上下文学习发挥最佳效果；低质示例则直接污染学习信号。

---

#### 示例选择的主要方法有哪些？列举至少三种（随机、相似度、多样性等）。

主要方法包括：

1. 随机选择：从示例池中随机采样 k 个示例。简单快速，但方差大，可能选中不相关或偏斜的示例，性能不稳定。

2. 基于相似度的选择：对于每个测试样本，从示例池中检索与其语义最相似的示例（使用句子嵌入的余弦相似度）。优点是示例高度相关，能最大化局部泛化；缺点是可能过分强调表面相似，缺少多样性，易导致标签偏置。

3. 基于多样性的选择：通过聚类或最大化子模函数，选择能够覆盖示例池中不同子群的代表性示例。常与相似度结合，在相关性和多样性间取得平衡，避免示例冗余。

4. 基于难度或信息量的选择：选取那些被当前模型认为困难或不确定的示例，或能提供最大信息增益的示例。例如，选择模型在零样本下预测错误的样本作为示例，以纠正其认知。

5. 基于强化学习或反馈的迭代选择：使用强化学习或策略梯度，根据模型在验证集上的表现迭代优化示例选择策略，自动化寻找最优示例组合。

6. 任务特定的启发式选择：如分类任务选择各类别均衡的示例；翻译任务选择高频词汇覆盖广的示例；推理任务选择步骤清晰、逻辑无误的示例。

实际应用中常组合多种方法，例如先用相似度检索候选集，再通过多样性进行二次筛选。

#### 基于语义相似度选择示例：如何使用嵌入模型检索与测试样本最相似的示例？

流程如下：

1. 构建示例嵌入库：将示例池中所有输入文本（仅 input 或 input+output 拼接）通过句子嵌入模型（如 `all-MiniLM-L6-v2`、`text-embedding-3` 等）编码为向量，存入向量数据库（如 FAISS、Chroma）。

2. 编码测试输入：对当前的测试样本，使用相同的嵌入模型生成查询向量。

3. 相似度检索：在向量数据库中执行近似最近邻（ANN）搜索，按余弦相似度或内积返回 top-N 个最相似的示例。通常取 N = 需要的示例数 k，或取稍多候选供后续筛选。

4. 后处理（可选）：
  - 多样性过滤：对检索到的 k 个示例，使用最大边际相关性（MMR）去除彼此过于相似的项，保证覆盖不同模式。
  - 标签平衡：检查所选示例的标签分布，若不均衡则从各类别中强制选取相似度最高的代表。
  - 格式清洗：确保示例与 prompt 模板的格式要求一致。

5. 构造 prompt：将选定的示例按照指定顺序插入 prompt，并在末尾附上测试输入。

关键实现细节：

- 嵌入模型的选择应匹配任务领域。通用领域用轻量通用模型；专业领域可用领域微调模型。

- 向量索引需支持实时查询，延迟应控制在毫秒级。

- 缓存常用查询的结果以降低开销。

这种方法实现简单，在分布偏移较小时效果极佳，但需警惕它可能放大标签偏置或忽略罕见类别。

#### 示例的排序重要吗？为什么把最相关的示例放在后面或前面会影响结果？

排序极其重要，直接影响模型对任务的归纳偏好。研究一致表明，示例的位置会系统性改变预测结果。

为什么靠后（靠近测试输入）的示例影响更大？

- 近因偏差（Recency Bias）：LLM 的注意力机制和自回归生成特性使得模型更倾向于关注最近的上下文。最后几个示例在注意力中被赋予更高权重，对输出的格式、标签选择产生主导影响。

- 信息新鲜度：模型在逐 token 生成时，最近的信息在隐藏状态中衰减最少，因此“印象最深”。

为什么靠前的示例也重要？

- 首个示例建立第一印象，定义了任务的整体框架和风格。如果开头示例错误或格式混乱，模型可能从一开始就误解任务，后续示例难以完全纠正。

- 在少数情况下（如模型有强烈的早期锚定效应），前几个示例可能设定任务的“基调”。

利用排序的策略：

- 将最相关或质量最高的示例放在最后：可增强对测试样本的针对性，提升准确率。

- 将标签均衡的示例放在最后：可缓解标签偏置，防止模型被末尾的多数类示例带偏。

- 随机打乱示例顺序：多次推理取平均（或投票），可降低位置偏差，提高稳定性。

- 对称排序：将高相似度示例分散放置，既保证首因建立框架，又利用近因强化匹配。

因此，排序不仅是示例选择的一部分，更是 prompt 工程设计的关键调优维度。

#### 什么是“recency bias”（近因偏差）？在 few-shot 排序中如何利用或缓解它？

近因偏差指模型在上下文学习中，过分依赖 prompt 末尾的示例，给予它们过高的注意力权重，从而使最终预测更倾向于这些末尾示例的模式、标签和风格。

利用近因偏差：

- 将最相关、质量最高、标签最平衡的示例放在 prompt 的最后位置，引导模型产出更正确的输出。

- 对于需要强调特定格式或特殊规则的场景，可将示范该规则的示例置于末尾。

- 在动态少样本学习中，针对每个测试输入，将其最相似的示例放在最后，以最大化适应性。

缓解近因偏差：

- 示例顺序随机化：多次推理时打乱示例顺序，对结果进行投票或平均，减少单次固定顺序导致的偏差。

- 校准技术：使用上下文校准（Contextual Calibration）方法，先估算出由示例顺序和标签分布带来的先验偏置，再从最终预测中减去该偏置。

- 增加元指令：在 prompt 开头明确告知模型“所有示例同等重要”或“不要因示例位置产生偏见”。尽管无法完全消除，但有一定校正作用。

- 采用对称或平衡的排列：例如，将不同类别的示例交替排列，或使每个类别在末尾出现的频率均等。

- 限制示例总数：示例过多会加剧近因偏差，因为模型容量有限，容易遗忘早期信息。控制示例数量可缓解此问题。

小结：近因偏差是 LLM 注意力机制的固有属性。理解并巧妙管理它（而非试图根除）是提升少样本性能的必修课。

#### 不同任务对示例的多样性要求是否不同？举例分类、翻译、推理任务的区别。

是的，不同任务对示例多样性的敏感度和需求差异显著。

- 分类任务：对标签平衡和类别覆盖的多样性要求极高。若示例中某类样本缺失或过少，模型会严重偏向多数类。同时，示例的文本风格、长度、领域等表面多样性也有助于模型学到更鲁棒的分类边界。但过分追求表面多样性而忽略标签平衡，可能引入噪声。

- 翻译任务：对词汇和句法结构多样性的要求中等。高质量的翻译示例应覆盖不同的句子类型（陈述句、疑问句、长句、短句），以避免模型过度拟合某一句式。然而，翻译更依赖模型内在的语言能力，示例更多是用于指示语言方向和风格（正式/非正式），极端的表面多样性不如在分类中关键。

- 推理任务（如数学、逻辑）：对推理步骤的多样性和正确性要求最高。示例应展示不同的解题策略、步骤数量和表现形式，否则模型会死板地模仿特定解题模板，遇到变体就失败。同时，错误或不完整的推理链具有毁灭性。因此，示例需要精心手工设计或校验，确保逻辑严谨且覆盖不同推理路径。

- 生成任务（如摘要）：多样性要求介于分类和推理之间。需要覆盖不同的输入长度、内容类型，以及输出风格（如抽象性、精炼度）。示例的多样性直接影响生成质量，但相比推理，容错率稍高。

总结：分类重标签覆盖，翻译重句式覆盖，推理重路径覆盖。了解任务特性才能针对性设计示例选择策略。

#### 基于聚类的示例选择：如何确保选出的示例覆盖不同的类别或模式？

聚类选择的目标是从示例池中选出一个子集，使得该子集中的示例彼此不相似，从而最大化信息覆盖。步骤如下：

1. 嵌入并聚类：将所有示例的输入（或输入+输出）编码为向量，使用 K-Means、层次聚类或社区检测算法将示例划分为若干簇。簇数可设为需要的示例数 k，或更多再进行筛选。

2. 从每个簇中选取代表：
  - 质心法：在每个簇中，选取最靠近簇中心的示例，作为该簇的典型代表。
  - 边界法：选取最远离其他簇中心的示例，以获得更多样化的边界样本。
  - 随机法：从每簇随机选一个，减少偏差。

3. 确保标签平衡：如果聚类结果显示某些簇内标签纯度高，可能导致选出的示例标签不均衡。可在每个簇内强制选取特定标签的示例，或先按标签分层，再在每层内聚类选择。

4. 结合相似度目标：可以先使用相似度检索得到一组与测试输入相关的候选集，再对该候选集聚类，选出既相关又多样的示例，从而实现相关性与多样性的平衡（MMR 算法也是如此）。

5. 算法示例：K-Means++ 初始化后从每簇选点；最大边际相关性 (MMR) 迭代选择与已选集合相似度低、与测试输入相似度高的示例。

聚类选择能够有效避免信息冗余，让有限的上下文窗口容纳更丰富的任务模式，对长尾任务和多样化测试场景尤其有益。

#### 当示例集很大时，如何快速检索最适合当前输入的 few-shot 示例？有什么高效索引方法？

大规模示例集需要高效的索引和检索机制，确保推理延迟可控。主要方法：

- 向量索引（ANN 索引）：使用 FAISS、ScaNN、Annoy 等库构建近似最近邻索引。将示例编码后建立索引，查询时返回 top-k 相似向量。索引类型可选 IVF_FLAT、IVF_PQ（内存压缩）或 HNSW（高速图索引），根据内存和延迟需求调优。

- 倒排索引 + 语义哈希：对于极端规模（亿级），可使用基于哈希的语义检索（如随机投影、SimHash）先粗筛，再在候选集内精确计算相似度。

- 分层检索：第一层用轻量级模型（如 TF-IDF、BM25）快速召回候选集，第二层用嵌入模型精细排序。兼顾速度与精度。

- 离线预计算与缓存：对常见查询模式或热门测试类型，预计算并缓存其最佳示例组合。线上仅做缓存查找，延迟极低。

- 动态索引更新：示例库可能持续增长。使用支持在线插入的索引（如 HNSW 的动态添加），并定期重建索引以维持查询效率。

- 分布式检索：当单机无法容纳索引时，将索引分片到多节点，并行查询并合并结果。

关键考量：

- 延迟预算：向量检索通常可在 1~10ms 内完成，适合大多数实时应用。

- 召回率 vs. 速度：IVF 的 nprobe 参数可动态调整；HNSW 提供高速高召回。

- 内存占用：原始向量与量化后的索引需平衡内存。

这一架构已成为动态少样本示例选择的标准方案，广泛应用于如 LangChain、LlamaIndex 等 LLM 应用框架中。

#### 在 few-shot 示例中，是否应该包含困难样本或边界样本？其利弊如何？

可以且常常应该包含，但需谨慎设计。

利处：

- 强化任务边界：边界样本（处于决策边界附近的样本）能清晰地向模型展示任务的区别性特征，有助于模型习得更精确的分类面或生成准则。

- 提升鲁棒性：困难样本暴露了任务的易错点，模型学习后可减少类似错误，提高整体鲁棒性。

- 信息量大：从主动学习的角度看，不确定性高的样本（困难样本）对模型信息增益最大，用它们作为示例更“教学”效果。

弊端：

- 混淆风险：如果示例本身标签有歧义或存在错误，或者模型能力不足以理解其细微差别，困难样本可能导致模型困惑，产生相反效果。

- 放大噪声：困难样本可能包含异常模式，模型可能学到非普遍性的虚假关联，损害泛化能力。

- 增加推理难度：在上下文有限时，过于复杂的示例耗费模型“理解带宽”，可能不如简单清晰的示例有效。

最佳实践：

- 混合使用：将少量典型困难样本与干净、简单的样本搭配。简单样本稳固基础，困难样本提升上限。

- 提供解释：对于困难示例，可在输出中附带简短的推理或标注理由（类似于 CoT 中的解释），帮助模型理解为什么这样标注。

- 根据模型能力适配：对于强模型，边界样本利大于弊；对于弱模型，简单样本更友好。

- 验证筛选：在开发集上测试包含/不包含困难样本的效果，以数据驱动决策。

因此，不是非黑即白，而是要根据任务和模型现状调配示例的难度组合。

#### 自动选择示例的动态方法有哪些？例如基于模型对示例的反馈进行迭代。

动态示例选择旨在根据模型实时或历史表现，自适应地为每个测试输入或任务选择最佳示例。主要方法有：

1. 基于模型置信度的迭代选择：
  - 先用随机或相似度选出的示例生成答案，评估模型对该答案的置信度（如 logprob 均值）。
  - 若置信度低，则替换示例（如增加多样性、更换更权威示例）重新生成，直到置信度超过阈值或达到最大迭代次数。

2. 强化学习选择器：
  - 训练一个轻量级的示例选择策略网络（如 MLP），其输入为测试样本的表示和示例池特征，输出为示例子集的选择概率。
  - 奖励信号为模型在该示例组合下的任务准确率。通过策略梯度更新选择器。
  - 这是较复杂的离线训练方案，但能学到针对特定模型和任务的最优选择策略。

3. Bootstrap / 主动学习式选择：
  - 维护一个“困难示例池”。对于每次查询，先用当前示例池中的示例组成 prompt，若模型回答错误（由人工或自动评判检测），则将该测试样本及其正确答案加入示例池（或替换掉最无效的示例）。
  - 此方法模拟在线学习，示例池随使用不断优化。

4. 贝叶斯优化或 Bandit 方法：
  - 将每一条候选示例视为一个 arm，利用多臂老虎机算法（如 UCB、Thompson Sampling）在线探索不同示例组合的效果，逐步收敛到高奖励组合。

5. 交叉验证自动搜参：
  - 在开发集上，对示例的选择超参数（如相似度阈值、多样性权重）使用 AutoML 或网格搜索调优，找到固定但较优的选择策略，部署后不再变化（属于离线动态）。

动态方法能显著提升上下文学习的稳定性和性能上限，但增加了系统复杂度和推理延迟。实际应用中常采用离线训练选择器+在线快速推理的模式，将额外延迟控制在可接受范围。

#### 如果标注数据有限，只能选少量示例，应该如何取舍？

标注数据有限时，示例的选择必须极度审慎，力求最大化每个示例的信息密度和代表性。取舍原则如下：

1. 优先选择标签平衡且覆盖核心类别\
   确保每个类别至少有一个示例，避免模型因未见过某类而完全无法预测。如果类别过多无法全部覆盖，则优先选择频率高、重要性强的类别，并对缺失类别在指令中额外说明。

2. 选择“原型”示例，而非边界或异常样本\
   在数据匮乏时，应选择最能代表该类典型特征的示例（如靠近类中心的样本），它们能稳固地建立任务的基本模式，避免边界样本带来的混淆风险。

3. 优先选择模型容易出错的模式\
   利用零样本或少量试错，识别模型在哪些类型输入上频繁失败（可通过小规模开发集检测），然后针对性地加入一个覆盖该模式的示例，达到“一个示例解决一类错误”的效果。

4. 构建高信息密度的示例\
   如果任务允许，可以在单个示例中展示多种情况（例如在一个翻译示例中涵盖特殊句式、数字翻译、敬语等），让一个示例承载多方面的规范信息。

5. 确保格式和风格的一致性\
   少量示例时，任何格式或风格的不一致都会被放大，导致模型不知所措。必须严格统一分隔符、标点、输出结构。

6. 动态复用示例\
   如果测试样本多样，可不为所有测试样本固定同一组示例，而是为每个测试样本动态从极小池中挑选最相关的一个示例（1-shot），这样每个样本都获得了最具针对性的指导。

核心思想：少而精。每个示例必须是“最小完备集”中的一员，具备代表性、正确性、信息量和格式规范性，将有限资源的效用发挥到极致。

#### 为什么有时随机选择示例也能工作得很好？这种情况反映了什么？

当随机选择示例也能达到与精心选择相近的性能时，通常反映了以下几种情况：

- 任务极其简单且模型已有强先验：模型在预训练中已经大量见过此类任务，对其格式和输出分布了然于胸。此时示例的作用仅仅是“激活”已有能力，因此任何合理示例都足够。例如，对基础情感分析、简单翻译等任务，随机示例也可触发模型的表现。

- 示例池高度同质：如果示例池中的样本彼此非常相似（例如，都是短文本、单一风格、标签分布均匀），随机抽样产生的集合自然也具有代表性和均衡性，精心挑选的增益微乎其微。

- 模型具备很强的鲁棒性和泛化能力：经过大规模指令微调的模型，对示例的微小变动不敏感。它们能从较杂乱的示例中提取不变的映射规则，表现出强大的上下文学习鲁棒性。

- 任务性能接近上限或已达平台期：当模型在该任务上的表现已接近人类或受限于其他因素（如输入本身的歧义性），示例选择带来的边际提升很小，随机选择便显得“足够好”。

- 评估指标的局限性：某些评估指标（如粗略的准确率）可能无法体现示例选择带来的细微质量差异，实际生成质量可能仍有差别。

这反映了什么？

它揭示了 LLM 上下文学习的一个本质：示例是信号，但模型内已存在强大的先验。当先验足够强，信号的具体形式就变得不那么关键。此外，这也提醒我们：在报告少样本性能时，必须进行多样本、多随机种子的评估，以判断性能是源于真正的泛化能力还是对特定示例的幸运依赖。

#### 如何处理少样本示例中的标签错误或噪声？对模型输出的影响有多大？

影响程度：标签错误或噪声对少样本学习的破坏性极大。在仅有的几个示例中，哪怕一个错误标签都可能显著扭曲模型对任务映射的认知，导致性能大幅下降。因为模型没有参数更新，它完全信任示例，错误标签会直接成为“正确答案”的模板，尤其是在将错误示例放在近因位置时，错误率可能飙升。

处理与缓解措施：

1. 严格的人工或自动化清洗\
   在构造示例时，必须进行多轮质检。可使用强模型（如 GPT-4）对示例进行一致性校验，自动标记可能错误的标签。

2. 使用多个示例进行标签交叉验证\
   如果怀疑示例中存在噪声，可以针对同一个输入提供多个来源的标签，或提供附带推理过程的示例，让模型学到“质疑”能力。不过这更适合 CoT 场景。

3. 增加示例数量以稀释噪声\
   当示例数量稍多时（如 8-shot），一个错误标签的影响会被其他正确示例部分抵消（但不完全消失）。这是最简单但成本较高的方法。

4. 在指令中提示潜在的噪声\
   在 prompt 中明确告知模型：“示例可能存在少量错误，请依据任务本质而非完全照搬示例。” 指令微调后的模型能在一定程度上理解这种元指令。

5. 将不确定的示例排除或标记为“仅供参考”\
   对无法确认真伪的示例，宁可不放，或用特殊标记（如“可能正确”）弱化其权威性。

6. 校准与后处理\
   使用上下文校准等技术，减少标签偏差带来的系统性错误。对输出结果进行规则或模型二次校验。

结论：在少样本场景下，示例的正确性是红线。如果示例质量不可控，零样本往往比有噪声的少样本更可靠。务必优先保证示例集的纯净度。

#### 多模态任务中，few-shot 示例的选择与纯文本有什么不同？

多模态任务（如图文问答、图像描述、视频理解）中，示例包含图像/视频和文本两部分，示例选择的维度从单一文本扩展到了跨模态对齐与双重多样性，具有以下显著不同：

1. 跨模态相关性成为核心指标\
   不仅需要考虑测试样本与示例的文本相似度，还必须考虑视觉内容的相似度。例如，对于图像分类，示例图片应与测试图片在视觉语义上相关。这需要多模态嵌入模型（如 CLIP）将图文映射到同一空间进行检索。

2. 双重多样性的要求
  - 视觉多样性：示例图片的构图、光照、背景、角度应多样化，防止模型学习到虚假视觉关联（如所有狗图片都在草地上）。
  - 文本多样性：示例的问题或描述文本也应多变，覆盖不同的提问方式和词汇。

3. 模态间的对齐一致性\
   示例中图像和文本的对应关系必须准确且清晰。错误的图文对齐（如图片是猫却标注为狗）比纯文本标签错误更具破坏性，因为它污染了多模态表示的核心。

4. 模态负载平衡\
   纯文本少样本中，所有示例都是同质的文本。多模态中，不同示例可能包含不同模态的侧重。需要确保选出的示例能均衡展示视觉和语言的信息交互，避免模型偏废其一。

5. 检索索引的构建\
   需使用多模态向量数据库，同时存储图像和文本的嵌入，并支持跨模态相似度查询（用文本搜图、用图搜图、用图+文联合检索）。

6. 示例大小的物理限制\
   图像 token 数远超文本（一幅图可占数百 token），上下文窗口压力大。因此多模态 few-shot 可用的示例数量通常更少，对每个示例的“信息密度”要求更高。

总结：多模态 few-shot 选择是多维优化问题，需同时满足跨模态相关性、视觉多样性、文本多样性和对齐一致性，技术挑战和计算成本均高于纯文本。

#### 在对话系统中，如何从历史对话中自动挑选相关的 few-shot 范例？

对话系统可利用历史对话库作为示例池，动态检索与当前对话语境最相关的范例，以提升回复质量或实现个性化和知识增强。

自动挑选流程：

1. 构建对话示例库\
   将历史成功或高质量的对话片段（如用户满意、任务完成）整理为示例。每个示例包含对话上下文（用户消息序列）和理想的助手回复。

2. 对话状态与意图编码\
   使用对话嵌入模型（或直接使用 LLM 的编码能力）对当前对话的最近几轮历史进行编码。编码应捕捉对话的语义焦点、未完成意图和情感状态。也可以提取显式的意图标签和关键实体作为辅助特征。

3. 多维度相似度检索\
   在向量数据库中检索与当前编码最相似的候选示例。可综合多种相似度：
  - 语义相似度：整体对话上下文嵌入的余弦相似度。
  - 实体重叠度：关键实体（如产品名、地名）的重合程度。
  - 意图相似度：若维护了意图分类器，可要求意图标签完全一致或属于同一类。

4. 动态过滤与排序
  - 过滤掉过长或过短的示例，使其适合当前上下文窗口。
  - 优先选择结局良好（用户满意）且最近发生的对话，保证范例的时效性和有效性。
  - 使用 MMR 等方法保证范例的多样性，避免重复推荐类似场景。

5. 注入 prompt 的策略\
   将选中的示例与当前对话历史按特定模板融合，例如：

```plain text
[历史对话范例]
用户：...
助手：...
[当前对话]
用户：... （待生成）
```

注意保护用户隐私，示例中不应包含可识别个人身份的信息。

6. 在线学习与反馈\
   根据当前对话的结果（用户是否采纳、评分）更新示例库中范例的权重，实现持续优化。

价值：这种方法让对话系统能够“回忆”类似情境下的成功经验，实现基于案例的推理，极大提升应对复杂、长尾需求的能力。

#### 使用对比学习或影响力函数选择对模型最有利的示例，是否可行？

可行，且是前沿研究方向，但存在较大的计算和技术挑战。

对比学习选择示例：

- 原理：训练一个示例选择器，使其最大化示例与测试样本的互信息，或最小化模型在验证集上的损失。可以将示例选择和任务性能作为端到端优化目标，使用对比损失学习一个嵌入空间，在该空间中，好的示例与测试样本距离近。

- 实现：将示例编码器和测试编码器映射到同一空间，通过对比损失（如 InfoNCE）拉近有帮助的示例与测试样本，推远无帮助的。推理时直接检索最近邻。

- 优点：一旦训练好选择器，推理时仅需向量检索，延迟低。

- 挑战：需要大量带标注的“示例-测试样本-模型表现”三元组来训练，初期成本高。

影响力函数选择示例：

- 原理：影响力函数用于量化每个训练样本对模型参数或特定预测的影响程度。在上下文学习中，虽然没有参数更新，但有工作将 ICL 类比为隐式梯度下降，并定义示例对测试预测的“上下文影响力”。

- 方法：通过计算在给定示例的条件下，模型对测试样本输出的概率变化，来估计该示例的贡献。选择那些能使正确输出概率最大化的示例。

- 优点：理论上严谨，直接优化对模型输出的影响。

- 挑战：计算影响力需要求梯度，在大型 LLM 上极其昂贵。通常需借助高效的近似算法（如基于注意力权重的近似、代理模型等）。

可行性总结：

- 离线可行：在大规模服务中，可投入资源离线训练选择器或预计算影响力，在线仅执行轻量检索。

- 在线挑战大：若需实时计算，开销过大，不适用于低延迟服务。

- 替代方案：实际中更多采用基于相似度和多样性的启发式方法，因为性价比高且效果已相当接近理论最优。

因此，这类方法在特定高价值场景（如模型调优、数据分析）中很有前景，但尚不是通用默认方案。

#### 示例的排序如何与注意力机制交互？早期 token 与后期 token 的影响力差异？

示例排序之所以关键，根本原因在于 Transformer 的因果注意力机制（causal attention）和位置编码的交互。

交互机制：

- 在自回归解码中，每个 token 只能看到它之前的 token。对于 prompt 中的最后一个 token（即目标输入结束后的生成起点），它可以注意到所有示例。然而，注意力权重并非均匀分布。

- 位置编码的衰减效应：尽管 RoPE 等现代位置编码能较好处理长距离依赖，但在极长上下文（如几千 token）中，序列开头的 token 对末尾 token 的注意力仍可能因距离过远而减弱。这导致早期示例的直接影响力可能弱于后期示例。

- 近因偏差的体现：生成第一个输出 token 时，其注意力分布往往高度集中于最近的几个示例及其输出。这是因为这些示例的键（Key）与当前查询（Query）的位置最接近，且其输出格式和标签直接成为“接下来应该生成什么”的模板。

- 早期示例的角色：早期示例更多通过建立全句的“语境”和“任务框架”来间接影响。它们被较浅层网络处理，可能帮助设定整个 prompt 的全局主题，但具体到下一个 token 的预测，其投票权重不如近邻。

影响力差异总结：

- 后期示例（靠近测试输入）：对输出格式、标签直接选择、局部风格具有强主导力。这是近因偏差的根源。

- 早期示例：对任务总体理解、术语定义、全局风格基调具有设定作用。它们是背景，后期示例是行动指令。

- 中层示例：通常处于相对较弱的影响力地带。

工程应用：将格式性、定义性的示例放在前面，将最相关、最希望模型直接模仿的示例放在最后，可以最大化利用这种注意力分布特性，达到任务框架与局部精准的双赢。

#### 在思维链提示中，示例的顺序是否影响推理路径的正确性？

影响极其显著，且其作用机制比标准少样本更复杂，因为推理链之间会相互干扰或增强。

影响方式：

- 推理模式的首因与近因：第一个示例的推理结构（如“先计算A，再计算B，最后求C”）往往会成为模型构建自己推理链的默认模板。如果首个示例使用了非最优或错误的推理路径，模型极可能沿袭错误模式。最后一个示例的推理链则会在细节上被最直接地模仿。

- 推理步骤的语义连贯性干扰：不同示例若采用不同推理风格（一个极度简略，一个非常详尽；一个用方程，一个用文字），模型可能混合这些风格，导致逻辑断裂或混乱。顺序决定了哪种风格在生成时占优。

- 中间结论的污染：由于注意力可能跨示例串联，模型可能错误地将示例 A 的中间结论应用到示例 B 的上下文中，尤其在多个示例放在一起时。错误的排序会加剧这种污染。

- 正确性传播：将正确且推理路径清晰的示例放在最后，可大幅提高最终答案正确率；反之，若最后示例推理有瑕疵，模型很可能“重蹈覆辙”。

优化策略：

- 一致性优先：确保所有示例使用统一且正确的推理范式。

- 最简单示例放首位：建立清晰的推理框架。

- 最完整、最正确的示例放末位：作为模型直接参照的范本。

- 避免相互矛盾的推理链：如果必须展示多种解法，应在 prompt 中明确说明，并谨慎排序。

实验表明，仅调整思维链示例的顺序，在数学推理任务上可产生 10% 以上的准确率差异。因此，思维链示例的排序是 prompt 工程中极其敏感且关键的调优项。

#### 如何设计一个自动化流程：给定验证集，自动搜索最优示例组合和排序？

可以设计一个基于搜索优化的自动化流程，在验证集上找到使任务指标最大化的示例集及排序。

流程框架：

1. 初始化
  - 示例池：包含大量候选示例。
  - 目标模型：需要优化的 LLM。
  - 验证集：用于评估示例组合好坏的带标注数据集。
  - 评估指标：如准确率、F1、BLEU 等，同时可加入延迟约束。

2. 候选集生成（粗搜）
  - 使用基于相似度、多样性的启发式方法生成一个初始的示例组合，或者随机生成 N 个候选组合。
  - 可采用遗传算法、粒子群优化等随机搜索策略，将每个示例的索引作为基因，组合的排序作为染色体。

3. 迭代评估与排序优化
  - 对每个候选组合，按当前顺序构成 prompt，在验证集上运行推理，记录平均指标得分。
  - 同时可在验证集上交叉验证示例顺序：对于固定的示例集合，通过 beam search 或局部调换（如交换最后两个示例）优化顺序，因为顺序对结果影响大且搜索空间相对小。

4. 搜索算法选择
  - 贝叶斯优化：适用于示例组合数较少（如 <20 维）且推理代价高昂的场景。
  - 遗传算法 / 进化策略：适合组合和顺序的联合搜索，能有效跳出局部最优。
  - 贪心前向/后向选择：从空集开始，每次加入能带来最大提升的示例，直到达到数量上限。计算效率较高。
  - 基于代理模型的优化：使用轻量级代理模型预测示例组合的效果，指导搜索方向，减少对昂贵验证集评估的次数。

5. 约束处理
  - 强制标签平衡约束：确保组合中各类别示例数量符合预期。
  - 长度约束：组合后 prompt 总长度不超过模型上下文窗口。
  - 多样性约束：通过惩罚项避免所选示例高度雷同。

6. 最终验证与输出
  - 在验证集上选出得分最高的示例组合及顺序。
  - 在一个完全独立的测试集上最终评估，确保没有因搜索过程而过度拟合验证集。

7. 部署与持续优化
  - 将搜索到的最优组合部署到线上。
  - 定期利用新收集的数据更新验证集，重新执行搜索以适应数据分布变化。

工具链：可利用 Optuna、Hyperopt 等超参数优化框架，或结合 LangChain、LlamaIndex 的示例选择器接口，自定义目标函数进行搜索。整个流程高度自动化，能极大提升少样本学习性能的上限。

#### 如果测试样本具有长尾特征，如何确保 few-shot 示例不会导致模型偏向头部？

长尾分布下，常规随机或相似度选择极易使示例偏向头部类别或常见模式，导致尾部样本被模型完全忽视或错误分类。解决方法：

1. 分层抽样确保尾部覆盖\
   在构建示例集时，强制按类别或模式分层抽样，保证每个长尾类别至少有 1 个示例。如果示例数有限，可只覆盖至一定频率的类别，对更稀有的类别在指令中声明其可能存在。

2. 反偏向加权检索\
   在基于相似度的动态选择中，对头部类别的相似度分数施加惩罚项，提升尾部示例被选中的概率。例如，使用加权采样或修改检索得分，使得与测试样本同属长尾类的示例获得加分。

3. 元指令注入\
   在 prompt 中添加明确指令：“请注意，输入可能属于罕见类别，不要仅根据示例中的频率来推测答案。” 这虽不能完全消除偏置，但能提醒模型。

4. 校准技术\
   使用上下文校准估算示例带来的先验类别分布，并从最终预测 logits 中减去该偏置，使预测更公平。

5. 合成或增强尾部示例\
   若真实标注的尾部示例不足，可借助数据增强（如回译、同义词替换）或利用生成模型合成高质量的尾部示例，确保其自然度和正确性。

6. 多示例集集成\
   使用多组侧重不同的示例集分别推理，一组偏向平衡，一组偏向尾部，最后综合结果，确保尾部不被淹没。

7. 后处理规则修正\
   对于已知的尾部模式，可设置规则：若模型输出头部类别但置信度低于阈值，则自动替换为相应尾部候选（需有知识库支撑）。

核心原则：不能依赖示例的天然分布。必须通过人工介入设计，打破头部主导，为尾部创建足够的“代表权”，让模型明白它们也是合法、应被识别的任务目标。
