# 76.大模型（LLMs）零样本/少样本学习（Zero-shot / Few-shot）

#### 什么是零样本学习？在 LLM 中，零样本如何不依靠示例完成任务？

零样本学习（Zero-Shot Learning）指模型在没有见过任何任务示例的情况下，仅凭任务描述或指令（instruction）来完成特定任务的能力。在 LLM 中，这意味着不提供输入-输出示例对，而是直接向模型描述任务要求，模型必须依靠其预训练期间积累的知识和语言理解能力来生成正确输出。

LLM 实现零样本的方式：

- 用户构建一个 prompt，其中包含任务指令（如“将下列英文翻译成中文：”）和目标输入（如“Hello, world!”）。

- 模型收到该 prompt 后，利用其强大的语言建模能力，基于指令理解和上下文推断出用户意图，并生成相应的输出。

- 整个过程没有提供任何输入-输出示例，模型完全依赖在预训练语料中学到的语言模式、任务形式知识和指令跟随能力。例如，在大量网页、书籍、论坛中，模型接触过类似的指令-回答结构，因此能够泛化到未见过的任务。

为什么有效：

大规模预训练语言模型在海量文本上训练，其中天然包含各种任务描述、问答、翻译等自然语言任务。通过指令微调（instruction tuning）后，模型进一步学会了根据指令执行任务，从而在零样本条件下表现良好。本质上，零样本是将任务要求以自然语言的形式编码进上下文，激活模型在预训练中习得的相关知识和技能。

#### 什么是少样本学习？它的典型范式是怎样的？与零样本学习的核心区别在哪？

少样本学习（Few-Shot Learning）是指提供给模型少量（通常为 1~10 个）任务示例，让模型通过这些示例理解任务模式，然后对新的输入进行推理。在 LLM 中，这通常通过在 prompt 中直接包含这些示例来实现，也称为上下文学习（In-Context Learning）。

典型范式：

- 构造 prompt，格式通常为：

```plain text
[示例输入1] -> [示例输出1]
[示例输入2] -> [示例输出2]
...
[目标输入] ->
```

- 模型阅读示例对后，自动抽取输入-输出映射关系，并应用到目标输入上，生成输出。

- 无需额外训练或梯度更新，完全依赖前向传播。

与零样本的核心区别：

| 维度 | 零样本 | 少样本 |
| --- | --- | --- |
| 示例提供 | 无示例，仅任务描述 | 提供少量示例对 |
| 任务理解方式 | 依赖指令表述和模型先验知识 | 借助示例中的模式隐式学习任务 |
| 适用场景 | 任务定义清晰、模型已有较强先验 | 任务边界模糊、或需要特定格式输出 |
| 性能 | 在复杂任务上可能较弱 | 通常显著优于零样本，尤其格式和推理任务 |
| Prompt 长度 | 较短 | 较长，随示例数线性增长 |

核心区别在于是否提供示例。少样本通过示例将任务实例化，减少了指令歧义，降低了模型推断任务意图的难度，往往能大幅提升性能。

#### 为什么 LLM 能够展示零样本和少样本能力？这与大规模预训练有什么内在联系？

LLM 的零样本和少样本能力根源于大规模预训练的两个关键属性：海量数据的多任务性和上下文学习能力的涌现。

内在联系：

1. 预训练语料天然包含多任务信号\
   互联网文本中充斥着各种结构化信息：问答（Q&A、论坛）、翻译（双语对齐文本）、摘要（标题与正文）、分类（标签与内容）等。LLM 在预训练时，虽然只做语言建模（预测下一个 token），但为了最小化损失，它必须隐式地学习这些模式。例如，看到“Question: ... Answer: ...”的片段，模型学会了问答模式。因此，当推理时遇到类似结构，模型能将其泛化为任务执行。

2. 上下文学习是涌现能力\
   研究发现，小模型（<1B）几乎没有上下文学习能力，只有在参数量超过一定阈值（如 10B+）后，模型才突然具备从几个示例中快速推断任务的能力。这种涌现是模型容量和预训练数据量共同作用的结果。大模型能够在其巨大的参数空间内，根据 prompt 中极少的模式，临时“模拟”出一个任务求解器，而不需要真正的参数更新。这类似于模型在预训练中学会了“学习如何学习”的元能力。

3. 指令跟随的泛化\
   许多现代 LLM 经过指令微调，被显式训练在零样本和少样本条件下遵循指令。这使得它们更加鲁棒。但即使没有指令微调，基座模型本身也具备一定的零/少样本能力，只是需要通过精心设计的 prompt 来激发。

因此，零样本和少样本能力本质上是 LLM 大容量、多任务预训练的副产品，是模型将海量文本中的统计规律和任务原型成功泛化到新上下文的结果。

#### 在少样本学习中，“上下文学习”（In-Context Learning）的运作机制是什么？它是否修改模型参数？

上下文学习（ICL）是 LLM 实现少样本学习的核心机制。它指模型通过前向传播处理包含示例的 prompt，并根据这些示例即时调整其行为，而不更新任何模型参数。

运作机制：\
从形式上看，ICL 将示例对 `(x_i, y_i)` 和目标输入 `x_test` 拼接为一个序列输入模型，模型自回归生成 `y_test`。在这个过程中，模型内部发生了复杂的计算，可以理解为：

- 激活任务模式：Transformer 的注意力机制在示例对之间建立连接，允许模型“注意到”输入与输出的映射关系。一些研究（如“In-context learning as implicit Bayesian inference”）表明，模型前向传播等价于在隐式地进行贝叶斯推理，根据示例推断任务分布，然后应用于新输入。

- 功能向量与任务表示：有工作发现，ICL 会在模型的隐藏状态中形成所谓的“功能向量”（function vector）或“任务向量”。这些向量编码了任务的核心操作，并通过注意力模块影响后续 token 的生成。

- 梯度下降的类比：一些理论分析指出，Transformer 的前向传播可以模拟梯度下降的某些步骤，ICL 相当于在激活空间中执行了快速的“元优化”，使得输出更符合示例中展示的模式。

参数是否修改：

完全不修改参数。 ICL 仅发生在单次前向推理中，模型权重不变。这意味着：

- 每次推理都是独立的，示例仅影响当次输出。

- 不存在灾难性遗忘，因为模型无状态更新。

- 但代价是，所有示例必须塞进上下文窗口，占用宝贵的注意力预算。

上下文学习的这种“即时推理即学习”特性，使得 LLM 具有非凡的灵活性和适应性，无需任何微调即可泛化到新任务。

#### 零样本学习能力严重依赖什么？如果指令描述不清晰会发生什么？

零样本学习严重依赖指令的质量和模型对任务的先验知识。

关键依赖因素：

- 指令清晰度与完整性：指令必须明确指定任务目标、输出格式、约束条件。模糊的描述会让模型困惑，无法准确对齐意图。

- 任务在预训练中的覆盖率：如果模型在预训练时很少见过类似任务（如极为特殊的编程语言规则），零样本性能将很差。模型依赖其内部知识库。

- 提示工程（Prompt Engineering）：指令的措辞、分隔符、甚至大小写都可能显著影响零样本结果。例如，“总结”和“用一句话概括”可能导致不同长度的输出。

- 模型的对齐和微调：经过指令微调的模型零样本能力更强，因为它们被训练来更好地遵循指令。

指令不清晰的后果：

- 任务误解：模型可能执行错误的任务。例如，模糊地说“处理这段文字”，模型可能任意选择翻译、摘要或纠错。

- 格式混乱：输出可能不符合用户期望的结构，如缺少必要的标签、返回过长或过短的文本。

- 幻觉或无关内容：模型可能生成看似合理但与任务无关的内容，因为它试图根据有歧义的指令“猜测”意图。

- 性能大幅下降：在分类任务中可能输出无意义的类别；在推理任务中可能跳过逻辑步骤。

因此，零样本性能很大程度上是人机协作的结果——需要人类通过精确的语言为模型搭建清晰的“任务脚手架”。如果脚手架不稳，模型的表现就会崩塌。

#### 少样本示例的数量如何影响性能？边际收益递减的点通常在哪里？

示例数量对少样本性能的影响呈对数增长或先快后慢的趋势，存在明显的边际收益递减。

影响规律：

- 0-shot → 1-shot：通常提升最显著。单个示例为模型提供了任务的具体格式和输入-输出映射的直观示范，大幅减少任务歧义。

- 1-shot → 4/8-shot：性能继续提升，模型逐渐从更多示例中学习到任务的边界、标签的多样性、以及格式的细微规范，鲁棒性增强。

- 8-shot → 16/32-shot：提升逐渐变小，尤其对于简单任务，模型已经基本理解任务，更多示例带来的额外信息递减。对于极复杂或需要大量背景知识的任务，增加示例可能仍有帮助，但受限于上下文窗口大小。

- 超过一定数量：可能因上下文过长导致注意力分散、计算成本剧增，甚至出现性能下降（因为模型难以聚焦于最近的相关示例）。此外，如果过多示例引入了标签噪声或与目标输入无关的样例，也可能产生负面影响。

边际收益递减点：

根据大量实验（如 GPT-3 论文），对于典型 NLP 任务（翻译、问答、分类），4~8 个示例往往已经接近饱和点，再增加到 16 或 32 个示例的收益很小（额外提升 < 1-2%）。对于需要复杂推理的任务（如数学应用题），可能需要更多示例来展示解题步骤，但同样会在 8~16 个示例左右达到瓶颈。

实践指南：通常从 2~4 个示例开始，根据验证集效果逐步增加，并监测性能与延迟/成本之间的权衡。如果示例数量已经使性能停滞，应考虑优化示例的质量、多样性和代表性，而非单纯增加数量。

#### 少样本学习中的标签平衡重要吗？为什么示例中的标签分布会影响模型预测？

标签平衡非常重要，尤其是对于分类任务。少样本示例中各类别出现频率的不均衡会显著导致模型预测偏向高频类别，这被称为示例偏差（Demonstration Bias）。

影响机制：

- 模型在上下文学习中会隐式地估计一个类别先验分布。如果示例中 80% 是正面情感，20% 是负面，模型会学习到“这个任务中正面更常见”，因此在预测时倾向于输出正面标签。

- 这种偏差在模型不确定时尤其明显，它会“随大流”选择示例中的多数类。

- 对于生成任务，标签分布不直接影响类别输出，但可能影响生成风格或内容倾向。

应对策略：

- 平衡示例：尽量让各类别（或各类输出）的示例数量相等。若类别过多，每个类别至少选取一个代表性示例。

- 随机排列示例顺序：避免同一类别的示例连续出现，以减少模型产生“局部统计偏见”。研究表明，示例顺序也会影响预测结果（最近示例影响更大）。

- 校准（Calibration）：可以在 prompt 中显式说明“各类别等可能”，或使用一个额外的前置指令校准模型的先验。一些技术（如上下文校准）通过将目标输入替换为一个无意义的输入来估计偏差，并在最终输出中修正。

因此，在构造少样本 prompt 时，必须注意标签平衡和示例顺序，它们是影响性能的关键细节，不应忽视。

#### 为什么有些任务零样本效果很差，但少样本效果很好？从模型内部表示角度分析。

零样本与少样本的巨大性能鸿沟，反映了模型将抽象指令转化为具体任务模式的能力差异。从内部表示看，原因有：

1. 任务模式激活不足（零样本）

在零样本中，模型仅接收到一段语言描述。尽管指令可能很清晰，但模型需要将这段描述映射到具体的计算步骤。对于预训练中不常见或过于新颖的任务，模型内部缺乏现成的“功能向量”。其表示可能停留在泛泛的语义理解，无法精确激活所需的注意力模式和前馈网络路径。

2. 示例提供表示锚定（少样本）\
   当给出示例后，每个示例 `(x_i, y_i)` 对在 Transformer 的隐藏状态中形成了具体的输入-输出关联。注意力机制使得目标输入的表示能够直接检索到示例输入，并复制其变换模式。这实质上是利用已形成的表示空间中的局部线性映射，将任务从抽象指令“实例化”。有理论将 ICL 解释为隐式构建一个线性分类器，该分类器的权重由示例在隐藏状态中的差异决定。

3. 格式与分布的校准

零样本可能生成语法正确但不合格式的输出（例如需要 JSON 却生成纯文本）。少样本示例直接展示了输出分布的形状，模型会将其生成分布向示例分布靠拢，从而严格遵循格式。从概率视角看，示例相当于提供了先验分布，约束了生成。

4. 未知任务的推理链缺失

对于需要多步推理的任务，零样本指令可能不足以让模型自发形成正确的推理链（Chain-of-Thought）。少样本示例通过展示完整的思考步骤，教给模型一种模板化的推理路径，模型内部会模拟这些步骤，极大提升推理成功概率。

因此，少样本本质上是在模型巨大的表示空间中，通过具体实例激活并锚定了一条从输入到输出的精确通路，而零样本只能依赖粗糙的语义引导，时常迷路。

#### 在少样本学习中，示例格式该如何设计？输入与输出的分隔符、换行等有哪些讲究？

示例格式的设计直接影响模型对任务的理解，不合理的格式会混淆模型，严重降低性能。关键要点：

1. 清晰一致的输入-输出分隔

- 使用明显且统一的分隔符将输入和输出分开，例如 `Input:` / `Output:`、`Q:` / `A:`、`→` 或特定的特殊 token（如 `###`）。

- 避免歧义：分隔符不应出现在输入或输出文本中，否则会引起边界错误。

2. 示例间的分隔

- 换行是最常用的示例分隔方式；有时使用空行或 `---` 增强可读性。

- 保持示例间分隔符一致，让模型明确感知示例边界。

3. 对称性与排版

- 示例的格式应完全一致：大小写、标点、空格数量最好统一。

- 输出结尾通常需要换行，以便目标输入后的生成自然开始。

- 使用 Markdown 或自然语言风格取决于任务。对于聊天模型，可采用类似 ChatML 的标记。

4. 标签与输出的表示

- 分类任务的标签应使用自然语言（如“正面”）而非仅有数字 ID，除非模型预期如此。

- 如果输出需要特定格式（JSON、XML），示例务必严格遵循该格式，因为它会成为模板。

5. 利用特殊标记增强注意力

- 有些研究发现，在示例和输入前加入如 `Example:`、`Text:` 等标记，能帮助模型区分示例和指令。

- 对于需要推理的任务，示例中包含推理步骤，并使用如 `Reasoning: ... Answer: ...` 明确阶段。

6. 避免过长的示例

- 太长的示例会占用过多上下文，减少可用示例数，也可能使注意力分散。尽量选择短小精悍的示例。

实践建议：设计好格式后，应在小规模实验上 A/B 测试不同格式（分隔符、排版、是否包含指令头），选择性能最好的模板。有时候，仅仅改变分隔符就能带来几个百分点的准确率变化。

#### 如何评估一个 LLM 的少样本学习能力？常用的评测基准有哪些？

评估 LLM 的少样本学习能力，需要系统地在多个任务、不同示例数量（0-shot, 1-shot, ..., k-shot）下测量性能，并与标准基线对比。

评估方法：

- 多任务多配置测试：选择涵盖不同类型（分类、生成、推理、抽取）的任务集。对每个任务，分别在 0-shot 到 10-shot 设置下，使用精心设计的 prompt 进行评估。

- 准确率与稳定性：除了平均准确率，还要评估结果对示例选择、示例顺序的敏感性（方差）。一个真正的强少样本学习者应在不同示例集上表现稳健。

- 上下文利用率：观察随着示例数增加，性能是否合理提升，是否存在过长的上下文导致性能下降。

常用评测基准：

- SuperGLUE / GLUE：经典 NLU 基准，现常用于评估少样本性能，包含问答、蕴含、情感分析等任务。通常报告 0-shot 和 few-shot 分数。

- HellaSwag：常识推理，测试模型完成场景描述的能力，对少样本非常敏感。

- MMLU (Massive Multitask Language Understanding)：涵盖 57 个学科领域的零/少样本问答，是衡量 LLM 知识和推理能力的标准基准。

- BBH (Big-Bench Hard)：从 Big-Bench 中选取的难度较高的任务集，专门评估少样本推理。

- GSM8K：小学数学应用题，需要多步推理，评估模型在少样本下利用 Chain-of-Thought 解题的能力。

- HumanEval / MBPP：代码生成任务，通过少样本示例提供函数签名和 docstring，评估代码生成能力。

- Flores：机器翻译任务的零/少样本评估。

- OpenBookQA / ARC：科学问答，需要外部知识和推理。

此外，自定义评估集也很重要：针对特定业务场景，构建专有任务，严格评估模型在该场景的少样本能力。综合这些基准和自定义任务，能够全面衡量 LLM 的少样本学习鲁棒性和泛化性。

#### 什么是“instruction tuning”与零/少样本学习的关系？指令微调如何提升零样本能力？

指令微调（Instruction Tuning）是一种在多样化的任务指令数据集上对预训练语言模型进行有监督微调的方法。每一条训练数据包含任务描述（指令）、可选示例和期望输出。模型被训练为根据指令生成正确输出。

与零/少样本学习的关系：

- 零/少样本学习是评估 LLM 泛化能力的任务范式，而指令微调是提升该泛化能力的训练方法。

- 经过指令微调的模型能更好地理解用自然语言描述的任务要求，并将这种理解泛化到全新的、未见过的任务上，从而显著增强零样本性能。

提升零样本能力的机制：

1. 任务格式泛化：指令微调让模型见过大量不同类型的任务表述（问答、摘要、分类、翻译等），学会了如何遵循自然语言指令。遇到新任务时，只要指令格式相似，模型就能快速适配，而不是仅依赖预训练中偶然习得的模式。

2. 减少歧义，对齐意图：微调过程教会模型从模糊指令中准确捕捉用户意图，并按期望的格式输出。这使得零样本下即使指令稍有不清晰，模型也更倾向于生成合理回答。

3. 激发推理能力：一些指令微调数据集（如 FLAN、T0）包含需要推理的任务，模型在微调中学会链式思考，这些推理模式可在零样本时被激活。

4. 格式标准化：指令微调通常使用统一的模板（如 “Instruction: ... Input: ... Output: ...”），使模型在推理时对这种结构非常敏感，易于提取任务要求。

结论：指令微调是连接大规模预训练和灵活零/少样本应用的桥梁，它将预训练模型中隐式的任务知识显式化，并规范化为通用的“指令遵循”能力，是现代 LLM 展现强大零样本性能的关键驱动。

---

#### 零样本能力是否意味着模型具有真正的“理解”能力？讨论其局限性和“表面模式匹配”的可能性。

目前主流的学术观点认为，LLM 的零样本能力不能简单等同于人类式的真正理解，而更接近一种高度复杂的统计模式匹配与表层泛化，尽管这种能力在很多场景下非常有效。

局限性及表面模式匹配的证据：

- 对表层提示词敏感：同一个任务，仅改变提示词措辞，模型性能可能剧烈波动。若模型真正“理解”，应对语义等价的指令保持稳定。

- 缺乏因果与反事实推理：零样本模型常无法稳定地进行因果推理或反事实思考。它们可能根据文本中的表面关联给出答案，而非基于深层逻辑。

- 记忆与模仿：许多零样本成功案例来自模型在预训练语料中见过高度相似的内容，模型更多是检索+拼接，而非当场推理。对于预训练中完全不存在的全新任务范式，零样本通常失效。

- 对虚假相关性的依赖：模型可能利用数据集中的虚假统计线索（如某些词和标签同时出现）做出判断，改变这些线索会导致预测错误，表明其缺乏真正的概念理解。

- 组合泛化困难：当任务需要组合多个已学概念解决新问题时，零样本性能急剧下降，说明模型没有形成系统性的组合推理能力。

但也不完全是否定：

一些研究认为，大模型在参数中编码了某种结构化的世界模型和推理程序，能够在上下文中模拟推理步骤。零样本的成功已经超越了简单的 n-gram 匹配。因此，这是一个尚未有定论的哲学和科学问题。

实践建议：信任但需验证。零样本适用于定义清晰、与预训练分布相近的任务；对于高风险、需严格逻辑或全新概念的任务，应引入少样本示例或人工验证，不可仅凭零样本结果轻信模型“理解了”。

---

#### 在分类任务中，少样本学习能否通过调整标签词映射（verbalizer）来提高效果？

可以，而且效果显著。 标签词映射（Verbalizer）是将任务类别映射为具体自然语言词汇的方法。在少样本分类中，合理设计 verbalizer 对性能至关重要，尤其是当模型使用生成式方式输出时（如 LLM 直接生成类别词）。

调整方法：

- 选择有意义的标签词：例如，情感分析任务将 `pos` 映射为“正面”，`neg` 映射为“负面”，而非随机 ID。

- 利用上下文词优化：为每个类别挑选在语义空间中靠近类别中心且符合任务语境的词。例如，主题分类中 `sports` 可用“体育”或“运动”。

- 多 token 聚合：允许一个类别对应多个同义词（如“积极”、“正向”、“好”），提高模型命中率。

- 动态 verbalizer：根据 prompt 或示例自动搜索最佳标签词。可使用模型本身对候选词打分（如计算“该文本的情感是___”填空的 logprob），选择概率最高的词。

为什么有效：

LLM 的输出是词汇的概率分布。如果 verbalizer 不恰当（如用冷僻词或歧义词），模型可能即便正确理解了任务，也因不擅长生成该特定词而输出错误。好的 verbalizer 将任务锚定在模型熟悉的语言表达上，降低了从内部表示到正确输出的映射难度。

在少样本中特别关键：

少样本示例为模型展示了输入和输出词汇的配对关系。如果示例中使用的 verbalizer 不一致或与预训练分布不符，模型会困惑。调整 verbalizer 使其与示例一致，并贴合模型的先验知识，可极大提升少样本分类性能。

#### 为什么有时少样本学习反而比零样本差？这种现象的可能原因是什么？

这种现象虽然反直觉，但确实存在，通常由以下原因导致：

1. 示例质量差或具有误导性

如果少样本示例包含错误标签、格式错误、或与测试样本的分布严重不符，它们会误导模型的任务认知，导致模型学到一个错误的任务映射，表现还不如没有示例的零样本（模型至少依赖自己相对鲁棒的先验）。

2. 示例导致标签偏置

如果少样本示例的标签分布极不均衡，模型会严重偏向多数类。在测试集均衡的情况下，整体准确率反而可能低于零样本（零样本可能依靠自身先验给出更平衡的预测）。

3. 示例格式与预训练不匹配

少样本示例引入了额外的结构（分隔符、特殊标记），如果这些结构与模型预训练时见过的模式差异过大，模型可能难以解析，产生干扰。零样本因没有这些额外结构，指令更纯粹，反而更好。

4. 上下文窗口过长导致注意力分散

过多的示例使得 prompt 极长，模型注意力被稀释，无法有效聚焦到目标输入上。尤其当示例中包含大量无关信息时，少样本可能表现更差。

5. 任务的“纯净”指令形式已足够

对于某些非常简单的任务，模型在预训练中已经将指令和执行形成了牢固的映射。加入示例反而可能打破这种直接映射，引入不必要的复杂性。

6. 示例限制了模型的创造性或合理推断

在某些生成任务中，示例可能限制了模型的输出范围。零样本下模型可能生成更具创造性和贴切的答案，而少样本示例导致它机械模仿示例格式，丢失了灵活性。

缓解措施：选择高质量、多样化、均衡的示例；调整 prompt 格式使其接近预训练分布；通过少量验证集筛选最优示例集合；必要时可混合零样本和少样本策略。

#### 少样本学习中的“样例偏置”问题：当示例与测试样本差异较大时如何缓解？

少样本示例与测试样本分布差异大（例如示例全是短文本，测试是长文本；示例主题单一）会导致模型学到的任务模式无法泛化，性能骤降。这种偏置是少样本学习的主要挑战之一。

缓解策略：

1. 示例选择多样化与代表性
  - 从训练池中通过聚类或基于嵌入的检索，选择覆盖不同子群（主题、长度、风格）的示例。
  - 使用主动示例选择：为每个测试样本动态检索最相似的训练样本作为示例（基于句子嵌入的相似度）。这样即使全局分布有偏，局部示例也贴近测试样本。

2. 示例重排序与权重
  - 将更具代表性的示例放在离测试输入更近的位置（prompt 末尾），因为研究表明模型受邻近示例的影响更大。
  - 在 prompt 中通过指令弱化示例的影响，如“以下示例仅展示格式，不要模仿其内容”。

3. 校准技术（Calibration）
  - 使用上下文校准：将测试输入替换为一个无意义或空输入，计算模型在此 prompt 下的输出分布（作为偏置），然后从真实测试输入的输出中减去该偏置。这可以有效抵消示例带来的标签分布偏置。
  - 还可以用额外的指令明确声明“类别与示例分布无关，请只根据输入判断”。

4. 增加元指令\
   在 prompt 开头加入“请忽略示例中的内容倾向，仅根据任务要求进行推理”等元指令。指令微调后的模型通常能遵循这类高层次指令。

5. 组合零样本信号\
   在少样本 prompt 中同时保留任务指令，并强调示例仅供参考，让模型综合两种信号。

6. 多示例集集成\
   使用多组不同的示例分别推理，然后投票或平均其输出分布，减少单组示例偏置的影响。

这些方法不能完全消除偏置，但能显著提升少样本在分布偏移时的鲁棒性。

#### 多语言零样本学习：跨语言迁移的关键是什么？

多语言零样本学习是指用一种语言（通常是英语）的指令或示例，让模型执行另一种语言（目标语言）的任务，而无需目标语言的训练数据。其跨语言迁移的关键在于：

1. 多语言预训练对齐

模型在预训练阶段学习了多种语言的共现和跨语言对齐。通过多语言语料（如 CommonCrawl 的多语言部分）、平行语料或翻译任务，不同语言的相似语义被映射到共享的表示空间中。这使得英语指令能够激活目标语言的相应知识。

2. 统一的词表和分词器

使用大规模多语言词表（如 XLM-R 的 SentencePiece），确保各语言的 token 都得到良好表示。分词器对语言的覆盖度直接影响零样本迁移能力。

3. 跨语言指令微调

在指令微调阶段，混合使用多种语言的任务数据（即使某任务只有英语数据，但在微调中模型接触了其他语言的指令格式），可以极大增强跨语言泛化。模型学会了“任务是语言无关的”——无论接收到哪种语言的输入，都要按同样逻辑执行任务。

4. 语言中性任务表示

成功的跨语言迁移意味着模型内部形成了语言中性的任务表示。即，任务操作（如情感分类、摘要）的计算独立于输入语言的表层形式。Transformer 的深层注意力可能自动学习将不同语言的同义输入映射到相近的隐藏状态。

5. 跨语言示例（如果可提供）

即使零样本，也可以通过提供极少的目标语言示例（跨语言少样本）或翻译后的示例来显著提升性能。示例的语言可以不同于测试语言，但最好与测试语言相同。

挑战：对于资源极低或与英语差异巨大的语言，跨语言迁移仍困难重重，主要受限于预训练数据稀缺和词表覆盖不足。

因此，跨语言零样本迁移的核心是多语言对齐的表示空间和语言无关的任务执行能力，这依赖于大规模多语言预训练和精心的指令微调。

---

#### 如果模型完全没见过某种任务格式，零样本学习还能工作吗？什么时候会完全失效？

如果任务格式在模型的预训练和指令微调中完全未见且无法从已知格式组合推断，零样本学习通常会失败。

能够部分工作的情况：

- 格式可分解：即使整体格式新颖，但构成元素（如输入、输出、分隔符）是模型熟悉的。例如，从未见过“输入 A，输入 B，输出 A+B 的摘要”这种确切格式，但模型理解“摘要”和多个输入，通过指令可将它们组合执行。

- 与已知任务同构：形式上不同但本质相同的任务（如将数学题从纵向改为横向排版），模型凭借深层语义理解仍有可能成功。

- 指令提供足够线索：通过详细、结构化的指令，模型可以“现场学习”新格式，尤其在指令微调后具备一定的格式组合泛化能力。

完全失效的情况：

- 任务完全不同于任何预训练信号：例如，要求模型输出图像像素值，或者用完全不自然的符号系统进行推理，而预训练语料中无此类模式。

- 格式要求极端严格且无示例：如需要生成特定 JSON schema，且字段名和结构完全未在训练中出现，模型几乎不可能凭空猜出。

- 需要领域特定知识且该知识在预训练中缺失：例如，要求用某种小众编程语言编写代码，该语言语法从未出现在训练数据中。

- 逻辑悖论或自指涉任务：这些对任何仅靠模式匹配的系统都是挑战。

总结：零样本能力的边界是预训练数据的覆盖范围和模型组合泛化能力的极限。如果新任务无法通过组合已知概念来构成，且无法从指令中明确推导出操作步骤，零样本便会失效。这正是少样本存在的价值——通过示例为新任务构建一座桥梁。

---

#### 少样本学习是否可以通过验证集动态选择示例？这种做法有什么风险？

可以，且这是提高少样本性能的常见做法，称为动态示例选择或示例检索。 方法为：针对每个测试样本，从一个较大的示例池中，检索出与测试样本最相似的几个示例（基于嵌入向量、tf-idf 等相似度），构成该样本专属的少样本 prompt。

优势：使示例高度相关于当前测试输入，模型能更好地泛化，尤其当测试样本分布多样化时，动态选择显著优于静态固定示例。

风险与挑战：

1. 过度拟合验证集的选择策略\
   如果使用同一个验证集来优化检索模型和选择策略，可能会过度拟合该验证集的特性，导致在真正的测试分布上性能不佳。

2. 检索偏见\
   基于表面形式相似度（如词重叠）检索示例，可能会忽略语义任务相关性。例如，可能检索到字面相似但任务标签完全相反的示例，造成严重误导。

3. 成本与延迟\
   每次请求都需要对测试样本进行编码和相似度检索，增加了推理延迟和计算成本，对在线服务可能形成瓶颈。

4. 示例泄露与评估失准\
   如果示例池中包含与测试样本语义极度相似甚至近重复的样本，模型可能会直接复制答案，导致评估结果虚高，无法反映真实泛化能力。这在公开基准上尤为需注意。

5. 标签分布不均衡加剧\
   检索可能导致某些类别的示例被频繁选中，放大标签偏置。

缓解措施：

- 使用独立的数据集来训练检索器，严格隔离测试集。

- 检索时加入多样性约束，强制覆盖不同标签或不同子主题。

- 评估动态示例时，同时报告静态示例基准，分析增量来源。

- 对检索到的示例进行后过滤，确保标签均衡。

合理利用动态示例选择可以大幅提升少样本表现，但必须警惕上述陷阱，确保评估的科学性和部署的可靠性。

#### 在对抗性输入下，少样本学习是否更加鲁棒？还是更脆弱？

对抗性输入是指经过精心设计、旨在使模型出错的输入（如加入误导性文本、字符级扰动）。少样本学习在对抗条件下的鲁棒性表现复杂，并非绝对的更鲁棒或更脆弱，而是取决于对抗方式和示例的质量。

可能更鲁棒的情况：

- 示例作为锚定：如果少样本示例是干净的、正确的，并且涵盖了对抗输入可能破坏的模式，它们可以起到“校准”作用。模型看到正确的示例映射后，可能会忽略输入中的部分噪声，坚持任务本质。

- 格式约束强化：少样本示例明确了输出格式。当对抗输入试图诱导模型输出错误格式时，模型可能因示例中的强格式先验而保持正确格式。

- 分布偏移的桥接：对抗输入本质上是一种分布偏移。相关性强、多样化的少样本示例可缩小训练-测试分布差距，使模型表现得更加稳健。

可能更脆弱的情况：

- 示例被污染：如果对抗性攻击能够影响少样本示例的选择（例如，通过污染示例池），则模型会被直接毒害，输出攻击者想要的错误结果。这是少样本特有的攻击面。

- 上下文窗口内的对抗注入：攻击者可能将对抗性文本注入到 prompt 中（如通过多轮对话的历史），这些恶意文本可能覆盖或干扰示例的作用，使模型混淆。

- 示例放大表面偏置：如果对抗输入利用了模型依赖的表面统计线索，而示例中恰好存在类似脆弱线索，模型可能被误导得更深。

- 更多的可利用结构：少样本 prompt 结构更复杂（有指令、示例、分隔符），攻击者可能有更多注入点来操纵模型行为。

研究显示：少样本学习在对抗鲁棒性上没有银弹。优质示例能增强鲁棒性，但对抗攻击者若可触及示例或 prompt 构造过程，风险也随之增加。防御措施包括：示例数据清洗、prompt 注入检测、输入净化，以及使用集成和一致性校验。

---

#### 如何利用思维链提示将少样本学习扩展到复杂推理任务？

思维链提示（Chain-of-Thought，CoT）是一种专为复杂推理设计的少样本学习技术，通过在示例中显式展示一步步的推理过程，诱导模型在回答最终问题前先生成中间推理步骤。

CoT 将少样本扩展到复杂推理的方式：

1. 示例构造\
   在少样本 prompt 中，每个示例不仅包含 `(输入，输出)`，还包含了 `(输入，推理链，输出)`。推理链使用自然语言详细描述从输入到答案的逻辑推导过程。例如，对于数学应用题，推理链会写出算式和每一步的计算逻辑。

2. 提示模型生成推理链\
   由于示例中包含了推理链，模型在生成时会模仿这种行为。当遇到目标问题时，它会先输出一段推理（通常以“让我们一步步思考”开始），再给出最终答案。这迫使模型将计算过程外化到生成的 token 序列中，每一个中间步骤都经过注意力机制和前馈网络的处理，大大增强了多步逻辑推理的准确性。

3. 为什么有效
  - 分解复杂度：将难题分解为一系列简单步骤，每个步骤对模型来说更容易。
  - 增加计算深度：自回归生成推理链相当于为最终答案分配了更多的计算和注意力时间（“思考时间”）。
  - 误差纠正：在推理过程中，模型可以自我修正或排除干扰，因为后续步骤以之前的推理为条件。
  - 可解释性：推理链让模型的决策过程透明，便于调试。

4. 应用范围\
   CoT 已被成功应用于数学推理（GSM8K）、常识推理（StrategyQA）、符号推理、多跳问答等各类需要多步逻辑的任务。后来的变体如自洽性（Self-Consistency） 进一步通过生成多条推理链并投票，提高了可靠性。

局限与注意事项：

- CoT 需要示例具有高质量的推理链，人工编写成本高。可使用模型自身生成推理链再筛选（Auto-CoT）。

- 对于不需要多步推理的简单任务，使用 CoT 可能画蛇添足，浪费 token 并引入不必要的复杂度。

- 推理链可能包含事实错误或逻辑漏洞，导致最终答案错误。

通过 CoT，少样本学习突破了简单模式匹配的限制，使 LLM 展现出类人的逐步推理能力，成为现代 LLM 解决复杂认知任务的标配技术。
