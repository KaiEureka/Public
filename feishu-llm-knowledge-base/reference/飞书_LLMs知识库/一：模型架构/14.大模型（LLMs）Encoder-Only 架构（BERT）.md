# 14.大模型（LLMs）Encoder-Only 架构（BERT）

#### 画出 BERT 的 Encoder-Only 架构，说明与 GPT 的主要区别。

BERT 架构（Encoder-Only）：

```plain text
输入文本 → Token Embedding + Segment Embedding + Position Embedding
       ↓
   [Transformer Encoder Block] × N 层
       ↓
   每个位置的隐藏状态（可用于分类/序列标注）
```

核心组件与 GPT 相同（自注意力、FFN、残差连接、层归一化），但有以下关键区别：

与 GPT（Decoder-Only）的主要区别：

| 特性 | BERT | GPT |
| --- | --- | --- |
| 注意力掩码 | 双向全可见（无因果掩码） | 因果掩码（只看左侧历史） |
| 预训练任务 | 掩码语言模型（MLM）+ 下一句预测（NSP） | 自回归语言模型（下一个词预测） |
| 生成能力 | 无自回归生成能力，仅用于理解 | 强大的自回归文本生成能力 |
| 位置编码 | 可学习绝对位置嵌入 | GPT-1/2 可学习，GPT-3+ 后趋向 RoPE |
| 段嵌入 | 有（区分句子对） | 无（统一序列） |
| 输出形式 | 每个 token 的上下文表示（用于下游任务） | 词表上的概率分布（用于生成下一个词） |
| 典型应用 | 文本分类、实体识别、问答（理解任务） | 对话、续写、翻译、代码生成（生成任务） |

本质区别：BERT 是双向的“读者”，能够深入理解文本；GPT 是单向的“作者”，能够流畅生成文本。

---

#### BERT 使用什么注意力掩码？是因果掩码吗？

不是因果掩码。BERT 使用的是双向全可见注意力掩码，即序列中每个 token 都能看到所有其他 token（包括其右侧的未来 token）。唯一屏蔽的是填充 token（`<PAD>`），通过填充掩码将其排除。

这种掩码方式使得每个词的表示能够融合左右两侧的上下文，是 BERT 强大理解能力的源泉。因果掩码（下三角掩码）仅在自回归生成任务中使用，BERT 不需要生成，因此完全舍弃了因果约束。

---

#### BERT 的预训练任务有哪些？如何设计的？

BERT 包含两个预训练任务，旨在学习深层的双向语言表示。

（1）掩码语言模型（Masked Language Model, MLM）

- 设计：随机选择输入序列中 15% 的 token。对选中的 token，80% 的概率替换为 `[MASK]` 特殊标记，10% 替换为随机词，10% 保持不变。模型需要根据上下文预测这些被操作的 token 的原始词汇。

- 目的：迫使模型利用双向上下文来理解语言，而不是死记硬背。随机替换和保持不变引入一定噪声，增强鲁棒性。这是 BERT 最核心的预训练任务。

（2）下一句预测（Next Sentence Prediction, NSP）

- 设计：输入两个句子 A 和 B。50% 的概率 B 是 A 的真实后续句，50% 是随机抽取的无关句。模型使用 `[CLS]` token 的最终隐藏状态进行二分类，判断 B 是否为 A 的下一句。

- 目的：训练模型理解句子间的关系，这对问答、自然语言推理等任务有益。但后续 RoBERTa 等研究证明 NSP 并非必需，移除后性能反而提升，因此后来许多 BERT 变体只保留 MLM。

---

#### 为什么 BERT 不能直接用于生成任务？

BERT 是 Encoder-Only 架构，设计上不具备自回归生成能力：

- 没有解码器：BERT 只有双向编码器，输出的是每个 token 的上下文表示，而非下一个 token 的概率分布。它没有像 GPT 那样的语言模型头（LM Head）和自回归循环生成机制。

- 双向注意力的不可行性：在生成任务中，文本是逐 token 生成的，每个时刻只能看到已生成的部分。BERT 的双向注意力假设可以看到整个序列，这与生成过程矛盾。如果强行用 BERT 生成，需要在每一步重新输入整个序列，计算量庞大且会破坏双向的优势。

- 训练目标的差异：MLM 任务是“完形填空”，它根据完整上下文（左右文）预测被遮住的词。生成任务需要根据左文预测下一个词，MLM 学到的表示并不直接适用于这种单向预测。

不过，BERT 可以作为生成模型的编码器部分，为解码器提供深度双向的源文本表示，例如在 Encoder-Decoder 架构中使用 BERT 初始化编码器。

#### 如果将 BERT 的词嵌入层换成 GPT 的，会有什么问题？

直接替换会产生严重的维度不匹配和语义空间不兼容问题：

- 维度可能不同：BERT 的嵌入维度通常为 768（base）或 1024（large），而 GPT 系列各不相同（GPT-2 有 768 至 1600 等）。如果维度不一致，后续层权重将无法匹配，模型完全不能工作。

- 嵌入空间的语义冲突：BERT 和 GPT 的词嵌入是分别在各自语料和任务上学习出来的，即使维度相同，它们在向量空间中表示词汇的方式也截然不同（BERT 偏向上下文理解，GPT 偏向语言模型特征）。直接替换会导致预训练学到的语言知识全部丢失，模型退化为随机初始化。

- 缺乏段嵌入：BERT 的输入是词嵌入、位置嵌入和段嵌入三者的和。GPT 没有段嵌入，替换后如何处理句子对任务将变得混乱。

- 位置编码不兼容：BERT 使用可学习的绝对位置嵌入（最大长度 512），GPT 后期用 RoPE 等。直接替换会破坏位置感知能力。

简而言之，BERT 和 GPT 的嵌入层是其完整架构的有机部分，任何简单替换都将破坏整个模型。

---

#### BERT 的双向注意力在捕捉上下文方面有什么优势？

双向注意力使 BERT 在理解文本时拥有“上帝视角”：

- 同时融入左右文信息：每个词的表示由整句所有词共同决定，能够充分利用来自两侧的语义、语法和指代线索。例如，代词“它”可以同时关注到左侧的名词和右侧的修饰语，从而更准确地消解指代。

- 更好的歧义消解：一词多义可以通过双向上下文区分。例如，“bank”在“河岸”和“银行”中的含义可由其左右词准确确定。

- 更强的全局理解：对于需要整体把握的任务（如情感分析、文本蕴含），双向编码能捕捉到长距离的语义依赖，提高准确率。

- 对完形填空式任务天然高效：MLM 训练使得 BERT 极其擅长根据周围语境推断缺失信息。

这些优势让 BERT 在文本分类、序列标注、句子对匹配等理解型任务上长期占据统治地位。

#### 在 BERT 中，位置嵌入、段嵌入和词嵌入是如何相加的？

三者是逐元素求和，形成一个统一的输入表示。

设词嵌入为 `E_token`（维度 d_model），位置嵌入为 `E_pos`（维度 d_model），段嵌入为 `E_seg`（维度 d_model，通常 A 句为 0，B 句为 1）。则最终的输入为：

Input=Etoken+Epos+EsegInput=$E_{token}$+$E_{pos}$+$E_{seg}$

所有这三种嵌入都是可学习的参数（位置嵌入和段嵌入也通过 Embedding 层查表获得）。求和后不进行任何额外变换，直接送入第一层 Transformer 编码器。这种简单加法使得模型能够同时感知词的语义、它在序列中的位置以及它所属的句子（A 或 B）。

---

#### 为什么后来的 LLM 大多放弃 Encoder-Only 架构？

随着 LLM 的发展，Encoder-Only 架构因其内在局限逐渐被 Decoder-Only 取代，主要原因：

- 缺乏生成能力：最核心的短板。现代 LLM 的核心价值在于与用户对话、生成代码、创作文本等，这些都需要自回归生成。BERT 完全不具备这一能力。

- 任务局限性：BERT 仅擅长“理解”，但大量现实应用需要“生成”。为了适应各种任务，往往需要为每个任务添加特定的分类头或解码器，无法像 GPT 那样统一处理。

- 规模扩展的收益不同：缩放定律在 Decoder-Only 上表现出色，涌现出上下文学习、复杂推理等高级能力。而 Encoder-Only 模型即使扩大规模，也难以展现出类似的突现能力，因为双向理解任务所需的“智能”密度可能不如生成任务。

- 训练数据利用效率：Decoder-Only 可以无监督地从海量文本中学习，仅需“下一个词预测”目标。而 Encoder-Only 的 MLM 仅对 15% 的 token 进行训练，数据利用效率相对较低（虽然后来有 Whole Word Masking 等改进）。

- 工程与生态的趋同：行业集中投入 Decoder-Only，形成了强大的工程优化和工具生态。Encoder-Only 模型逐渐被边缘化，只在特定理解任务中继续使用。

因此，Decoder-Only 以其统一的生成能力、优异的扩展性和涌现能力，成为 LLM 的主流选择。

---

#### 有没有介于 Encoder-Only 和 Decoder-Only 之间的预训练方式？举例。

有，即 Prefix Language Model (Prefix LM) 和使用混合掩码的模型。

- Prefix LM：将输入序列分为前缀（可见双向）和生成部分（单向因果）。典型代表是 T5 的预训练目标之一，以及 GLM (General Language Model)。T5 统一使用“text-to-text”格式，根据任务不同使用不同的注意力掩码。GLM 在一个模型中同时进行双向编码和自回归生成。

- UniLM：通过在同一个 Transformer 堆栈中使用三种不同的自注意力掩码（双向、单向、seq2seq），联合预训练，同时具备理解和生成能力。

- Encoder-Decoder 架构：如 BART、T5，它们有独立的编码器和解码器，编码器双向理解输入，解码器自回归生成输出。这算是两个独立模块的组合，而非“介于”单一架构之间，但融合了两者优势。

这些中间形式试图兼具双向理解的精准和自回归生成的灵活，但因其复杂性，在纯粹的大规模扩展中不如 Decoder-Only 简洁高效。

---

#### BERT 的编码器可以作为 Decoder-Only 模型的一部分吗？

可以，但通常不直接作为其解码器部分，而是作为特征提取的编码器组件。

- 作为独立的编码器：许多多模态或检索增强模型（如 RAG、Flamingo、BLIP-2）使用 BERT 或其变体对文本进行双向编码，得到深层表示后再输入给 Decoder-Only 的生成模块（通过交叉注意力或特征拼接）。这样既能利用 BERT 强大的理解力，又能保留 GPT 的生成力。

- 作为初始化权重：一些 Encoder-Decoder 模型（如 BART）的编码器部分直接使用 BERT 的权重进行初始化。但将 BERT 编码器权重复用到纯 Decoder-Only 的解码器中，由于注意力掩码机制不同（双向 vs 因果），直接复制权重会导致严重的性能损失，因为模型需要从双向注意力模式“学”成单向，代价极大。

- 灵活的混合架构：若要在同一个堆栈中混合，需要设计复杂的掩码策略（如 Prefix LM），让部分层或部分序列位置进行双向注意力，而生成部分保持单向。BERT 的预训练权重可以作为双向部分的良好起点。

总之，BERT 编码器在需要深度理解源文本的场景下仍然有用，但不能直接当作自回归解码器来生成文本。它更多扮演“理解者”的角色，而将“生成者”的任务交给真正的解码器。

#### 如何让 BERT 支持变长序列？

BERT 通过以下方式处理变长序列：

- 动态填充：将同一批次内的所有序列填充到该批次最长序列的长度。使用特殊的 `[PAD]` token，其对应的嵌入向量为零向量（或专门学习）。

- 注意力掩码：在自注意力计算时，为所有填充位置施加极大的负值（如 `-10000`），使其在 softmax 之后的权重为 0。这样模型就不会关注填充内容。

- 最大长度截断：BERT 的输入序列长度不能超过其预训练时的最大位置嵌入（通常为 512）。超过时，通常截断过长文本（如只保留开头和结尾），或者使用层次化方法处理长文档。

- 无需修改模型结构：由于自注意力本身不限制序列长度，只要内存允许，BERT 可处理任意长度（但位置嵌入的限制使其最多到 512，除非替换位置编码）。

这些方法使得 BERT 能高效地在一个批次中处理不同长度的句子。

---

#### BERT 的层数和隐藏维度通常有哪些配置？如 BERT-base/large。

BERT 主要有两种标准配置：

- BERT-base：
  - 编码器层数：12
  - 隐藏维度 $d_{model}$：768
  - 自注意力头数：12
  - 头维度：64
  - 总参数量：约 110M

- BERT-large：
  - 层数：24
  - 隐藏维度 $d_{model}$：1024
  - 头数：16
  - 头维度：64
  - 总参数量：约 340M

此外，还有后续变体如 RoBERTa 继承相同架构，以及轻量版 BERT-mini/tiny 等，用于资源受限场景。

#### 什么是“BERT 微调范式”？它和如今的提示微调有何不同？

BERT 微调范式（Pre-train then Fine-tune）：

- 在大量无标注文本上预训练 BERT，获得通用的语言理解能力。

- 针对每个下游任务，在 BERT 编码器之上添加一个任务特定的分类头（如单句分类加线性层、句子对分类加全连接、序列标注加 CRF 等）。

- 使用下游任务的有标注数据联合微调整个模型（编码器 + 分类头），所有参数都更新。

提示微调（Prompt Tuning）范式（以 GPT 为代表）：

- 不改变预训练模型的结构，也不添加任务特定的分类头。

- 将下游任务通过精心设计的自然语言模板（prompt）转化为续写任务。例如，情感分类变为“这部电影很棒。情感是 [MASK]”，模型直接预测 [MASK] 处的词。

- 微调时，可以让整个模型参数更新，也可以只训练极少量软提示向量（Prompt Tuning），冻结模型主体。这种范式减少了任务特定的参数，且更好地利用了预训练目标与下游任务的统一性。

本质区别：BERT 范式是“模型 + 任务头”，GPT 范式是“一切皆续写”。后者更符合现代 LLM 的统一生成框架。

#### 解释为什么 BERT 的 NSP（下一句预测）任务后来被质疑。

NSP 任务被质疑并最终被许多模型抛弃，主要原因：

- 任务过于简单：随机抽取的无关句子在主题、词汇上往往差异极大，模型仅凭浅层特征（如词重叠）就能判断，无法学到深层的句子间逻辑关系。这使得 NSP 对模型理解力的提升有限。

- 对下游任务帮助有限：RoBERTa 等研究通过消融实验发现，移除 NSP 后，模型在多数下游任务上的性能不降反升。MLM 本身足以让模型学到强大的表示，NSP 反而可能成为噪声。

- 破坏了文本的连贯性：NSP 需要构造大量“非下一句”的负样本，这意味着预训练数据必须被切割成独立的句子对，破坏了原始文档的连续性和长程依赖。相比之下，直接喂入连续长文本（如 RoBERTa 的做法）能让模型学到更丰富的上下文关系。

- 更好的替代方案：后来的模型更倾向于使用全文档级别的连续文本进行训练，或采用更复杂的句子顺序预测任务（如 ALBERT 的 SOP），但总体趋势是简化预训练任务。

因此，NSP 被视为 BERT 设计中可以被优化的部分，后续的强基线模型（如 RoBERTa、DeBERTa）普遍移除了它。

#### BERT 的 MLM 任务中，被掩码的 token 如何恢复？损失如何计算？

掩码策略：

- 随机选择输入序列中 15% 的 token。

- 对这些选中的 token：
  - 80% 替换为 `[MASK]` 特殊 token。
  - 10% 替换为随机词汇。
  - 10% 保留原词不变。

恢复过程：

- 经过多层双向 Transformer 编码后，被掩码位置（以及所有位置）的输出隐藏向量会融合整个句子的上下文信息。

- 每个被掩码位置的隐藏向量被送入一个线性分类头（通常与词嵌入矩阵共享权重），输出一个词表大小的 logits 向量。

- 取 logits 的 argmax 或 softmax 后的最高概率词作为预测。

损失计算：

- 仅在被选中的 15% 的 token 位置上计算交叉熵损失，其余 token 被忽略（loss mask 为 0）。

- 损失函数为：

$$
\mathcal{L}_{\mathrm{MLM}} = -\frac{1}{|\mathcal{M}|}\sum_{i \in \mathcal{M}}\log P_\theta(x_i \mid x_{\setminus\mathcal{M}})
$$

其中 $\mathcal{M}$ 是被掩码位置的集合，$x_{\setminus\mathcal{M}}$ 是未掩码的上下文。

这种设计使得 MLM 能够利用双向上下文准确推断被遮挡的词，是 BERT 强大理解力的核心来源。

#### 如果你现在要做一个文本分类任务，用 BERT 还是 GPT？为什么？

选择取决于具体需求和资源，但总体倾向如下：

用 BERT，如果：

- 需要高准确率的纯理解任务，且标签明确、数据量适中。

- 追求训练和推理效率：BERT 的参数量通常较小（如 110M），微调成本低，推理速度快，且不需要复杂的解码策略。

- 任务不需要生成能力，如情感分析、垃圾邮件检测、实体识别等。

- 团队对 BERT 微调范式熟悉，有成熟的微调流程。

用 GPT，如果：

- 任务需要结合上下文进行生成式分类（如根据文章内容自动生成标签解释）。

- 数据量极小（如 few-shot），希望利用 GPT 的上下文学习能力，无需微调。

- 将来可能将模型复用于生成任务，希望维护统一的 Decoder-Only 基座。

- 需要模型具备更强的知识储备和推理能力（如基于常识的分类），因为大模型 GPT 的容量和知识远超 BERT。

总结：对于传统、高效的文本分类，BERT 仍是性价比极高的选择；若追求通用性和未来扩展，或任务是极低资源，则现代 Decoder-Only 模型（如 LLaMA、GPT 系列）更合适。

#### 对比 BERT 和 RoBERTa 的改进点。

RoBERTa（Robustly optimized BERT approach）在 BERT 基础上进行了多项关键改进，大幅提升了性能：

- 移除 NSP 任务：只保留 MLM，输入变为连续的长文档片段，而非句子对。这使得模型能学到更长程的依赖。

- 动态掩码：BERT 在数据预处理时一次性生成掩码，每个 epoch 看到相同的掩码模式。RoBERTa 在每次输入序列时实时动态生成掩码，增加了数据多样性，模型更鲁棒。

- 更大规模的数据和更长的训练：使用 160GB 文本（远大于 BERT 的 16GB），训练步数增加，批次更大。

- 更大的词表：使用字节级 BPE（Byte-level BPE），词表更大，对稀有词和编码更友好。

- 调整超参数：如移除 Adam 的偏置校正项，使用更大的峰值学习率等，优化训练过程。

这些改进使 RoBERTa 在众多 NLU 基准上显著超越原始 BERT，成为 Encoder-Only 模型的新标杆。

---

#### 在 BERT 中，能否使用 RoPE 替代可学习位置嵌入？

技术上可以，但实际意义有限，且与 BERT 的双向注意力特性不冲突。

- RoPE 的工作原理：RoPE 在每一层的注意力计算时，通过对 Q 和 K 施加旋转来注入相对位置信息。它天然兼容双向注意力，因为它只依赖 token 之间的相对距离，不区分方向。

- 替换的可行性：将 BERT 的可学习位置嵌入改为 RoPE，需要修改每一层的自注意力核心，在 Q 和 K 投影之后施加旋转。这是架构层面的改动，需要从头预训练。

- 为什么实践中不这样做？ BERT 预训练的时代，RoPE 尚未被提出。如今的 LLM 焦点已转向 Decoder-Only，很少有人会重新预训练一个带 RoPE 的 Encoder-Only 模型。若仅是为了理解任务，标准可学习位置嵌入已足够；若是为了长文本，更直接的方案是使用 Longformer 等稀疏注意力模型。

- 理论兼容性：RoPE 本身对双向注意力无妨碍，因此如果从头训练一个带 RoPE 的 Encoder-Only 模型，它应能正常工作并可能获得更好的长度外推能力。但这更多是学术探索，工业应用动力不足。

#### Encoder-Only 模型在推理时，是否可以使用 KV Cache？

不能，也不需要。

- KV Cache 的适用条件：KV Cache 专为自回归生成设计。在逐 token 生成时，缓存历史 token 的 Key 和 Value 以避免重复计算。

- Encoder-Only 的推理方式：它是一次性输入整个序列，经过双向自注意力计算后得到所有位置的表示。不存在“逐步生成”的过程，因此没有历史缓存的需求。

- 如果非要缓存：在极特殊场景下，如果要对同一段前缀反复编码（如 Encoder-Decoder 架构中的编码器），可以缓存编码器输出的 K、V（用于解码器的交叉注意力）。但这是编码器-解码器架构的缓存，并非纯 Encoder-Only 模型内部的 KV Cache。

因此，Encoder-Only 模型的结构决定了它天然不涉及 KV Cache。

---

#### BERT 产生的上下文表示是否可以用于生成任务的初始化？

可以，但通常不作为直接的生成器，而是作为生成模型的强大特征初始化来源。

- 作为编码器的初始化：在 Encoder-Decoder 架构（如 BART、T5）中，BERT 的编码器权重常被用于初始化编码器部分。这样，解码器可以基于 BERT 产生的深度双向上下文表示进行生成。这种做法结合了 BERT 的理解优势和自回归解码的生成能力。

- 作为解码器的初始化：直接使用 BERT 的权重初始化一个 Decoder-Only 模型并不合适，因为 BERT 的双向注意力和 MLM 预训练目标与因果语言模型差异巨大。强行初始化后需要大量训练来“转换”行为模式，且通常不如直接使用预训练的 Decoder-Only 模型。

- 作为特征输入给生成模型：将 BERT 编码的句子/文档向量作为额外的条件信息，通过交叉注意力或拼接到输入中，供给给 GPT 等生成模型。这在一些任务（如文本风格迁移、受控生成）中有所应用，即用 BERT 提取理解特征，用 GPT 生成。

因此，BERT 的上下文表示更多是作为“理解模块”的输出，而非生成模块的直接起点。它是生成任务中的辅助编码器，而非生成器本身。

#### 为什么 BERT 在处理长文本时会遇到困难？

BERT 处理长文本的瓶颈主要来自三个方面：

- **平方级复杂度**：标准自注意力的时间复杂度为 $O(n^2 d)$，空间复杂度为 $O(n^2)$（注意力矩阵）。当序列长度 $n$ 超过 512 时，计算和显存开销急剧增长，难以训练和推理。

![原图](media/DTyFbfwcDo7R0bxyQmzcMAsFnle.png){.ocr-src}

- 最大位置嵌入限制：BERT 使用可学习的绝对位置嵌入，最大位置数在预训练时固定（通常为 512）。超出此长度的 token 没有对应的位置嵌入，模型无法区分它们的位置。这是硬性限制。

- 预训练数据分布：BERT 的预训练数据以句子对和短段落为主，缺乏对长文档的优化。因此模型即使理论上通过改大位置嵌入可处理更长序列，但实际表示能力并未针对长程依赖进行优化，容易出现“中间信息稀释”或对早期信息遗忘的问题。

针对这些困难，后续出现了 Longformer、BigBird 等使用稀疏注意力机制的 Encoder-Only 模型，它们将复杂度降低到 $O(n)$ 或 $O(n\log n)$，从而支持数千甚至上万 token 的长文本编码。

#### 如何利用 BERT 提取句子嵌入？

BERT 本身不直接输出句子级别的嵌入，但可以通过以下常用方法获得：

- [CLS] token 嵌入：BERT 在每个输入序列开头添加一个特殊的 `[CLS]` token。经过多层编码后，该位置的隐藏向量被认为聚合了整个序列的信息。取 `[CLS]` 的最后一层（或后几层平均）的向量作为整个句子的表示。这是最直接、最常用的方法，在句子分类、语义相似度等任务中表现良好。

- 所有 token 嵌入的平均池化：对输入序列中所有 token（不包括 `[PAD]` 和 `[CLS]`）的最后一层隐藏向量取平均值。这有时能比 `[CLS]` 更全面地捕捉句子语义，尤其在句子较长时。

- 最大池化：对所有 token 向量取最大值，作为句子表示。

- 后几层拼接/加权：一些研究发现，BERT 的不同层包含不同层次的信息（浅层语法、深层语义）。可将后几层的 `[CLS]` 向量拼接或加权求和，得到更丰富的句子嵌入。

- 专门微调：为了获得更好的句子嵌入，通常会在句子相似度任务（如 NLI、STS）上对 BERT 进行微调，使模型学会将语义相似的句子映射到相近的向量空间。如 Sentence-BERT（SBERT）通过孪生网络和对比损失微调，极大提升了句子嵌入的质量和检索效率。

因此，BERT 提取句子嵌入的核心是取 `[CLS]` 或平均池化，并通过微调优化嵌入空间。

#### 谈谈“BERT 是自编码模型”和“GPT 是自回归模型”的根本区别。

这一区分源于它们的预训练目标和建模方式的本质不同：

- 自回归模型（GPT）：基于概率的链式法则，将文本的联合概率分解为条件概率的乘积：

$$
P(x_1, \ldots, x_T) = \prod_{t=1}^{T} P(x_t \mid x_{<t})
$$

![原图](media/ZPVAb4GVDo0J5pxiZfWcW2nrn3d.png){.ocr-src}

- 它按照时间步单向地生成（或预测）序列中的每个 token，只能利用过去的上下文。训练目标是最大化这个单向的条件概率。这天然适合文本生成任务。

- 自编码模型（BERT）：不显式地建模联合概率，而是通过去噪自编码思想进行表示学习。具体来说，它通过 MLM 任务将输入序列中的部分 token 损坏（掩码或替换），然后训练模型从损坏的版本中重建原始 token。这可以看作是一种降噪自编码器：输入是被噪声污染的序列，目标是还原出干净的原始序列。BERT 通过双向注意力利用全局上下文来推断被掩码的词，其目标是学习强大的上下文表示，而非像自回归那样显式地建模序列的概率。

根本区别：自回归模型追求“根据过去预测未来”，具有因果方向性和生成能力；自编码模型追求“从噪声中恢复原貌”，利用双向上下文进行表示学习，理解能力强但缺乏直接的生成能力。一个形象比喻：GPT 是作家，一句句往下写；BERT 是编辑，看到全文后能补全空缺或纠正错误。

#### 有没有基于 Encoder-Only 的多语言模型？它们如何处理不同语言？

有，最著名的是 multilingual BERT (mBERT) 和 XLM-RoBERTa。

多语言处理机制：

- 共享词表和编码器：这些模型使用一个包含多种语言文字的巨大共享词表（如使用 WordPiece 或 SentencePiece 在 100+ 种语言的语料上联合训练的词表）。所有的语言通过相同的 tokenizer 映射到同一个子词空间。

- 无显式语言标识（早期 mBERT）：模型在预训练时接收混合语言的文本，没有明确的语言 ID 输入。它通过大量语料自动学习跨语言的共享表示。这种方式使模型具有一定的“多语言迁移”能力——在一种语言上微调后，有时能在其他语言上表现尚可（零样本跨语言迁移）。

- 引入语言嵌入（XLM-R）：XLM-RoBERTa 等模型在输入中可能加入语言标识嵌入（类似 BERT 的段嵌入），显式告诉模型当前 token 属于哪种语言。这有助于更好地分离和融合多语言信息。

- 大规模多语言预训练：XLM-RoBERTa 在 100 种语言的 CommonCrawl 数据上进行 MLM 预训练，数据量是 mBERT 的数百倍，极大提升了跨语言理解能力，成为多语言 Encoder 的标杆。

这些模型通过在共享表示空间中学习多语言文字，实现了跨语言的泛化，广泛应用于多语言文本分类、实体识别、跨语言问答等任务。

#### 如果在 BERT 的每层之间加入残差连接，它已经是残差网络，还需要额外改进吗？

BERT 本身已经具有残差连接，但针对极深网络或特定任务，仍有改进空间。

- BERT 已有的残差设计：BERT 的每个 Transformer 层内都有两个残差连接（自注意力子层和 FFN 子层）。这是它能够训练到 24 层（BERT-large）的基础，属于标准残差网络。

- 可能的额外改进：
  - Pre-Norm 替换 Post-Norm：BERT 使用的是 Post-Norm（残差加法后接 LayerNorm）。在更深的网络中（如 >48 层），Post-Norm 容易导致梯度消失。改为 Pre-Norm（在子层前归一化）可以提升训练稳定性。这是现代深层 Transformer 的普遍做法。
  - 残差缩放：对于极深 BERT（如果需要），可以引入 DeepNorm 的残差缩放思想（如乘以一个小子），以更好地控制方差累积。
  - 跨层残差连接：除了层内残差，一些研究探索了跨层连接（如连接浅层和深层的额外跳跃连接），可以进一步增强梯度流，但会增加复杂度和参数量。
  - 可逆残差：为降低内存，可逆残差网络允许通过输出计算输入，从而在反向传播时无需存储中间激活。这在视觉 Transformer 中有应用，但在 BERT 中较少见，因为 BERT 通常深度适中且显存需求尚可接受。

总之，BERT 的标准残差连接对于其 12/24 层的深度已经足够。如果要构建更深或更高效的 BERT 变体，上述改进是可选的优化方向。
